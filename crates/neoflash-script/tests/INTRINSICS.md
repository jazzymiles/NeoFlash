# Bounded intrinsic profiles

`intrinsic-fixtures.mjs` records catalog IDs, pinned sources and typed expected values. Every reference expectation is **documented_only**. These tests execute generated JavaScript and the original `examples/as-intrinsics.nflash` scripts; they do not measure an original Flash runtime. Browser acceptance must publish that document through the ordinary exporter.

The AS2 `parseInt` adapter follows the parser behavior of [Ruffle AVM1 at fe6cfc5](https://github.com/ruffle-rs/ruffle/blob/fe6cfc545405b888ebb478ce1c211d63147ca49b/core/src/avm1/globals.rs#L150), including complete octal digit strings, signed hexadecimal handling, explicit radix validation and conversion order. The [Adobe AS2 reference](https://open-flash.github.io/mirrors/as2-language-reference/global_functions.html#parseInt()) corroborates the `0777 → 511` example. Ruffle is a named implementation reference, not an original-player oracle. Missing input returns undefined; explicitly supplied radix zero is invalid. Objects still use the frontend's existing JavaScript-backed primitive conversion, so this is not a full SWF-version-specific AVM1 conversion model.

The AS3 adapter follows the native default/type declaration in [Adobe `actionscript.lang.as` at 858d034](https://github.com/adobe/avmplus/blob/858d034a3bd3a54d9b70909386435cf4aec81d21/core/actionscript.lang.as#L48) and null handling in [Toplevel.cpp](https://github.com/adobe/avmplus/blob/858d034a3bd3a54d9b70909386435cf4aec81d21/core/Toplevel.cpp#L918). Default parsing is decimal; radix zero enables hexadecimal detection. Explicit null/undefined input becomes the string `null` at the native boundary, observable at radix 36. The published documentation describes radix as uint, while this pinned implementation takes int; the adapter follows the implementation's 32-bit conversion. The digit scan and large-integer rounding use the browser's native parseInt. Historical Unicode whitespace and rounding across every radix/player version are not claimed conformant.

AS3 primitive Number/int/uint `.toFixed(...)` calls apply `int(precision)` and range 0–20 before formatting special values, following [Number.as](https://github.com/adobe/avmplus/blob/858d034a3bd3a54d9b70909386435cf4aec81d21/core/Number.as#L146) and [NumberClass.cpp](https://github.com/adobe/avmplus/blob/858d034a3bd3a54d9b70909386435cf4aec81d21/core/NumberClass.cpp#L33). Invalid precision throws catchable RangeError with errorID 1002. Precision truncates and wraps to signed 32 bits, so 4294967296 becomes zero and 4294967295 becomes −1. The fixed integral representation at magnitude ≥1e21 avoids JavaScript's exponential notation. Other finite formatting uses native JavaScript toFixed; the pinned VM's historical rounding compatibility switches are not reproduced or claimed verified. No global or prototype is patched.

Bare parseInt values retain their dialect when assigned to a callback. Local parameters/functions with that name remain user bindings. Direct custom `.toFixed()` methods retain their receiver and property/argument evaluation order. AS3 numeric method extraction through member/index reads or logical-assignment results binds the original numeric receiver, including Function.call/apply. The captured native identity distinguishes built-ins from authored methods. Numeric class aliases share publication identity and use existing scalar construction; int/uint limits are exposed as read-only class constants. Method identity storage is bounded to 16,384 distinct numeric receiver values. Ordinary same-named data fields and custom functions remain supported. Computed direct calls already lie outside the accepted call subset. This does not add Number prototype mutation, boxed Numbers, arbitrary Function construction, cross-handler typed slots, full argument reflection or player version selection.

AS3 parseInt accepts zero to two arguments in this profile; primitive toFixed accepts zero to one. Excess arguments are an explicit unsupported boundary, not a claimed Flash ArgumentError: bare parseInt calls receive a compiler diagnostic, indirect calls and primitive toFixed calls throw an explanatory runtime Error. Custom functions retain their existing argument rules.

`publishedIntrinsicTraces` is the browser acceptance transcript. It distinguishes strings from numbers and observes negative zero through its reciprocal. Two independent instance timelines run the AS2 and AS3 scripts once and stop themselves. NaN/range cases are caught in authored source. The document uses ordinary trace and timeline methods and requires no test-only globals.
