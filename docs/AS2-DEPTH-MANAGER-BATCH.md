# AS2 relative MovieClip DepthManager

This bounded package implements four useful `mx.managers.DepthManager` methods: `createChildAtDepth`, `setDepthAbove`, `setDepthBelow` and `setDepthTo`. They are exposed in their documented form as AS2 MovieClip methods. The DepthManager utility supplies six documented numeric constants. The catalogue proposal is **11 new partial declarations: four methods, six constants and one class entry**. No constructors, properties, events or reviewed-existing entries are added to that count.

The existing Rust display graph remains authoritative. `Player::as2_depth_manager` in `runtime_graph/as2_display.rs` chooses depth tiers, preserves sibling identity, inserts relative to an anchor and shuffles runtime siblings in steps of 20. `as2_depth_manager.rs` in the WASM crate only transports the request. `web/as2-depth-manager.js` retains stable method identities and delegates symbol creation to the existing `attachMovie` path, including its real Export identifier, initialization object and linked AS2 class constructor. No Flash UI component, library format conversion or second display model is introduced.

Normal objects occupy positive depths below 500000; topmost objects occupy depths from 500020 upward, within the existing 1048575 limit. `kTop` raises within the normal tier, `kBottom` lowers within that tier, `kTopmost` enters the upper tier, and `kNotopmost` returns to the normal tier. Above/below operations require attached runtime siblings and adopt the anchor's tier. The algorithm compacts sibling depths in stable steps of 20; it does not reproduce Adobe's exact historical absolute-depth growth. Direct `swapDepths` and AS3 index operations keep their existing behavior and can override manager order; a later DepthManager operation explicitly reapplies its own ordering.

Authored negative-depth placements remain untouched. Reordering `_root`, detached clips or an authored placement is explicitly unsupported. Runtime siblings created by existing APIs participate in the manager's ordering; their names, object references and children remain intact. The existing display allocation limits apply. Method lookups are cached per publication generation and have no side effects. Restart invalidates old method references and resets the serial used for generated child names; normal player reset clears the authoritative graph.

Creation reserves a position by normalizing siblings, then invokes existing `attachMovie`. If later linkage or initialization validation fails, relative sibling order is preserved, but numeric depths may remain normalized; no sibling is removed. This is a stated partial-profile boundary, not atomic creation parity. Successful creation initializes the linked class at its actual reserved depth.

`createClassChildAtDepth`, `createClassObjectAtDepth` and `createObjectAtDepth` remain unsupported. The first two require the historical UIObject construction model, and the latter two require a reserved system layer with cursor/tooltip ownership. Returning `kCursor=101` and `kTooltip=102` does not claim that system layer exists. Their methods diagnose the missing capability and are not promoted. The supported constants additionally retain Adobe's `kTop=201`, `kBottom=202`, `kTopmost=203`, `kNotopmost=204`. This utility is not constructible or a supported native superclass.

The contract source is Adobe's [AS2 Components Language Reference](https://web.archive.org/web/20130325184910id_/http://livedocs.adobe.com/flash/9.0/main/flash_as2_components_reference.pdf), pages 483–494. The existing ignored reference PDF SHA-256 is `95a200ff72acb178048b92ee00a3fec7aba69c3c808b63a3df42ab32d48c7b01`. Only the public contract was consulted; no Adobe implementation was copied. The reused sparse-depth and symbol-attachment implementation retains its pinned MIT Ruffle provenance in [AS2-DISPLAY-BATCH.md](AS2-DISPLAY-BATCH.md); the new relative-tier policy is project Rust code.

The existing native `as2_sparse_depths_duplicate_paths_and_as3_indices_share_one_graph` scenario was extended with normal/topmost ordering, removal from the topmost tier, relative placement, creation planning and rejected nonsibling anchors. Its focused run passed; **zero new test functions** were added. The coordinator observed AS2_DEPTH_RESULT 8/8 and the three actual linked clips in the expected order, then 8/8 again after physical Restart in the shared browser run. This is family evidence, not original Flash or per-method conformance. Exact catalogue IDs are in ignored `target/verification/as2-two-hour-2/depth-manager-inventory.json`.
