# AS2 primitive object constructors

This bounded package implements the three previously missing AS2 constructors `new Boolean`, `new Number` and `new String`. They create distinct objects, with object identity, `typeof == "object"`, primitive `valueOf`, string `toString`, and ordinary instance fields. AS3 constructor lowering retains its existing scalar behavior. No global JavaScript constructor or prototype is modified.

Rust owns the stored primitive conversion and formatting in `as2_boxing.rs`. Finite numeric/Boolean conversions reuse the existing AS2 binding kernel; UTF-16 strings, NaN, infinities and signed zero travel through explicit tagged values. The browser adapter owns only wrapper identity, immutable method descriptors, property bridging and value transport. Existing compiled operators invoke those primitive methods through the normal generated JavaScript execution model; this is not a new Rust VM or a claim of complete AVM1 coercion.

Number construction accepts primitives and NeoFlash primitive boxes; invalid numeric strings become NaN. The finite string parser shares the current decimal/hex binding profile. Boolean construction preserves object truthiness, including a Boolean box whose primitive value is false. String construction preserves UTF-16 code units, including surrogate code units. Default constructors produce false, zero and an empty string respectively. Extra constructor arguments are evaluated by the compiler and ignored after the first.

String boxes expose Rust-computed length, charAt, charCodeAt, concat, indexOf, lastIndexOf, slice, substr, substring, split, toLowerCase and toUpperCase through the existing Rust String service. They reuse its current limits and historical case tables; no duplicate string algorithm is introduced.

The boundaries are explicit: custom object-to-Number/String coercion, arbitrary prototype replacement/inheritance, primitive-box `instanceof`/class-alias construction, box enumeration/AMF serialization and exact historical Number formatting remain outside this package. Number.toString supports the decimal default or numeric radix 10; other radix values diagnose. The existing native-object guards reject unsupported enumeration/serialization. The current finite binding parser's accepted numeric range and hexadecimal bounds are inherited; complete AVM1 numeric-string edge cases are not claimed. The wrapper's stored primitive is immutable; dynamic instance fields do not change its value. Restart invalidates methods on old wrappers. Unsupported object coercion produces a host diagnostic that authored AS2 catch cannot recover in the current execution profile; this package does not add general host-error catch semantics.

The contracts were checked against Adobe's mirrored [Boolean](https://open-flash.github.io/mirrors/as2-language-reference/Boolean.html), [Number](https://open-flash.github.io/mirrors/as2-language-reference/Number.html) and [String](https://open-flash.github.io/mirrors/as2-language-reference/String.html) references. The new wrapper/state bridge is project code and reuses the project's existing binding and String kernels; their pinned Ruffle/MIT provenance remains in [the reuse record](AS2-REUSE-PROVENANCE.md). No external source implementation or new dependency is imported for this package.

Verification stays grouped. There is one native conversion family, `as2_boxing::tests::as2_boxing_family`, which passed in the coordinator's shared affected native delivery pass. The existing String adapter smoke replaces its old boxed-constructor rejection with wrapper behavior; its case count is unchanged. Four coherent boxing observations are embedded into the existing `as2-connections-batch.nflash` family: number identity/arithmetic, Boolean object truthiness, String UTF-16 methods, and defaults/conversion between primitive boxes. All four positive boxing groups passed within the ordinary connections export (initial combined result 9 passed / 0 failed). Its initial negative probe attempted out-of-profile object coercion and could not recover the host diagnostic through authored catch; that probe was removed without extending or concealing the unsupported boundary. No separate HTML5 cycle or shared 90/24 rerun was launched for these constructors.
