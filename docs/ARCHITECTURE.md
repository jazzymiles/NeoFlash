# Architecture

## Data and ownership

`neoflash-core` owns a versioned `Project`: stage settings, library symbols, layers, sparse keyframes, element definitions, script source, and symbol references. IDs persist across keyframes and serialization. Import reserves loaded IDs to prevent collisions with newly created objects. Indexes in storage are zero-based; UI and script frame numbers are one-based.

The document has no GUI objects, GPU handles or machine-specific resource paths. `.nflash` is readable JSON. Version 2 adds logical source files and class linkage; version 3 immutable portable resource bytes; version 4 layer roles and library folders; version 5 skew, color transforms, gradient paths and Flash easing; version 6 tween kinds, Motion ◆ keys, guides, scenes, sounds and ruler guides; version 7 per-property easing and richer authoring metadata; version 8 spatial Motion paths and layer behavior; version 9 painted masks, roving keys and advanced-authoring data; version 10 stable-ID object-scoped Motion keys, paths and options; version 11 layer/keyframe filter stacks and External/Progressive timeline-video deployment; version 12 timeline-video out-point trims. The version is raised only when a document starts using a newer feature, so older readers refuse only documents that use one. Older document versions remain readable. Unsupported versions and invalid geometry/references are rejected, not guessed.

Vector paths use explicit line/quadratic/cubic commands and compound contours. The core owns validation, analytic bounds, bounded flattening and hit testing. Native rendering tessellates with lyon; the Canvas host constructs Path2D. Both apply nested affine transforms to fills and strokes. See [the vector decision](decisions/0002-vector-geometry.md) for gesture, interpolation and rendering limits.

## Authoring versus execution

`evaluate(project, symbol, frame)` is pure. It samples authored transforms/easing, combines nested affine transforms and yields a leaf display list. Scrubbing and onion skin use it without running scripts. The editor currently paints this list through egui, including transformed text meshes.

## Timeline engine

A keyframe's `tween` and `tween_kind` choose how its span interpolates. Classic tweens interpolate the poses of elements with the same ID and follow a motion guide's first stroke when their layer is guided (`LayerProperties.motion_guide`). Shape tweens morph the layer's shapes (`shape_tween.rs`: pairing by ID then order, arc-length resampling of different contours, paint blending). Motion tweens resolve each stable element ID through format-10 `Keyframe.motion_keys` and sparse `motion_tracks`; `keyed_properties` and the shared span fields remain the legacy fallback. All of this lives in `evaluate.rs`, so editor playback, the runtime and HTML5 share one implementation. Range edits (`timeline_edit.rs`) keep object keys/tracks consistent; the editor's `commit_history` records changed properties per element ID and raises the format version.

Classic endpoint Snap also requires format 8 so older readers cannot silently apply the previous nearest-point behavior. Format 8 adds optional shared `Keyframe.motion_path`: an open MoveTo followed by lines/cubics in timeline coordinates, anchored to the first span element. Format 10 adds sparse `MotionTrackOverride` values for independent object easing, Orient/Snap/Sync and `MotionPathOverride`, plus authoritative per-object `MotionPropertyKey` lists and roving state. Absence of the format-10 fields preserves the exact shared-path/broadcast result. X/Y keys determine eased time along the same bounded Rust arc-length sampler in native, HTML5 and Lottie. Validation rejects wrong-key placement, missing/duplicate element IDs, malformed easing/keys, nonfinite/oversized coordinates and excessive paths. Editor handle drafts never enter the document until a gesture edits that object's path.

Scenes are separate MovieClip symbols listed in `Project.scenes`. The editor edits each one; export and the WebAssembly player concatenate them into one main timeline (`scenes.rs`), as SWF publishing does, and keep scene ranges for `currentScene`, scene-aware `goto` and `nextScene`/`prevScene`.

Frame sounds (`Keyframe.sound`) are decided in Rust: the `Player` emits sound commands (play, stop, stream start/stop, stop all) when frames are entered, never during pure evaluation. Hosts only decode and schedule them: Web Audio in `web/audio.js`, and rodio with Symphonia decoders in the native editor preview. See [timeline sound](decisions/0037-timeline-sound.md) and [NF2 wiring plan §7](NF2-WIRING-PLAN.md#7-timeline-current-state-and-remaining-work).

`Player` owns runtime state keyed by instance paths: frame, playback flag, placement lifetime and property overrides. Independent MovieClips keep advancing when their parent stops. Graphic playback follows its parent. A queue carries frame/load/enterFrame/click script dispatches; stale dispatches are discarded when scripts replace/detach instances. Self-goto queues are bounded by the host. This is a defined initial lifecycle, not a claim that all Flash Player edge cases match.

## Script compilation and execution

`neoflash-script` parses JS and transforms TS with Oxc, in a strict function-body context matching the browser host. Type checking and package/module bundling are separate future work. The AS2/AS3 frontend has a real tokenizer/parser/AST and explicit unsupported-feature diagnostics. There is no string-substitution claim of full ActionScript translation.

Structured control flow uses validated enclosing jump targets, lexical catch environments and conservative completion analysis. Supported try/finally constructs lower directly to JavaScript, preserving return/break/continue exits. Explicit AS2 throws use a shared branded envelope across handlers; catch-all AS2 clauses do not absorb arbitrary host failures. The HTML5 boundary unwraps that envelope and formats arbitrary thrown values without replacing their cause. See [structured ActionScript and exceptions](decisions/0006-actionscript-control-flow.md) and the compatibility matrix for the exact language boundary.

`neoflash-web` compiles the same Rust `Player` to WebAssembly. The browser host provides Canvas painting, pointer input, script object proxies, helper APIs and a browser error surface. Test Movie and published output execute the full supported browser profile; the editor also has bounded authored-script and imported-SWF previews that reuse Rust timeline state without claiming complete native runtime parity.

## Publishing

The Rust exporter validates all data and compiles scripts before publishing. It writes HTML, the browser host, WASM bindings and a data/script bundle. Full embeds WebAssembly in that bundle; Balanced and Compact stream a separate WASM file with a direct-file fallback; Shared can reference a separately published runtime. No Flash Player, remote CDN or runtime build service is required. It checks destination ownership before replacing a previous export.

Canvas is the first renderer. DOM-based accessible text, forms, responsive containers and semantic web documents are planned alongside Canvas, not represented as completed by the initial exporter. Full font resources can be embedded as browser-loadable faces. The Subset policy rebuilds supported TrueType SFNT tables around the required glyph closure; dynamic/input fields and font layouts that cannot be preserved safely retain the complete browser-loadable face instead of serving NeoFlash-only metrics as a font.

Optional placement accessibility metadata is evaluated by the same Rust runtime. A separate browser semantic layer represents named Button/Image targets and preserves their placement lifetimes; keyboard activation enters the existing Click event path. This is the first semantic layer, while rich DOM components remain planned. See [authored web semantics](decisions/0003-authored-web-semantics.md).

## Desktop

`eframe/egui 0.33.3` is pinned as the initial tested UI baseline with wgpu/Metal rendering. Custom panels implement a dense classic workspace on the NF2 design system (`crates/neoflash-ui`). Native dialogs use rfd; installed fonts use font-kit/CoreText. Editor playback of timeline sounds uses rodio (Core Audio output) with Symphonia MP3/WAV decoders (MPL-2.0, unmodified, editor-only; HTML5 exports do not contain them). Embedded and local External timeline video uses the shared Rust scheduler, streams ffmpeg PAM output into decoded RGBA frames and keeps GPU textures in a bounded cache. Decoded CPU frames are still retained for the stream, so long-form on-demand/ring decoding remains open. Stage rulers, ruler guides (`Timeline.guides`, document data) and the grid are editor overlays in `stage_view.rs`; snapping math is in `snapping.rs` ([details](NF2-RULERS-GUIDES-GRID.md)). A native `.app` wrapper sets macOS 15 as the deployment target. AppKit integration (menus, document lifecycle, accessibility and richer input) needs further work.

A single pinned egui-winit source patch retains the initiating key event immediately before its paste payload. The editor consumes that adjacent event as paste intent before normal shortcut/text routing, so final frame modifiers and release order cannot change Paste in Place. Upstream provenance/licenses and the removable patch are recorded in `vendor/egui-winit/NEOFLASH-PATCH.md`.

`WorkspacePrefs` stores bounded versioned JSON through eframe storage, separately from Project/history. Theme, panel visibility and docking, sizes, detached-window geometries, timeline view options (short rows, snap playhead, loop playback, preview thumbnails) and the saved stage view defaults are persisted; arbitrary egui memory and script buffers are not. Semantic palette tokens drive widgets and manual painters. Tools/Timeline/Actions render the same content functions into docked panels or immediate native viewports, with stable content/text IDs and one mutable Editor. Deferred text clipboard events retain their viewport as well as their authored target. Native screen enumeration uses safe AppKit bindings and global logical coordinates; recovery only adjusts detached panels on creation or display topology changes. Recovery fingerprints native files and XFL trees on a throttled cadence; Modified/Replaced/Deleted conflicts are retained per tab and validated before Reload or Save can replace state. See [native workspace](decisions/0007-native-workspace.md).

A second pinned eframe patch initializes AccessKit for every child wgpu window, using the existing per-window event and output routing. Rendering an icon does not by itself establish native accessibility; both its tree and activation require separate checks. Provenance and feature-on/off checks live in `vendor/eframe/NEOFLASH-PATCH.md`.

Commands group edits through `Editor::commit_history`; drag gestures become one bounded step. History captures a cached project baseline and stores structural deltas for changed symbols/layers/keyframes while reusing immutable resource buffers. Undo/Redo applies inverse deltas and keeps the configured capacity after ordinary edits and Redo. Dirty-state comparison uses a saved model snapshot without reserializing data every frame. Changed subtrees are still cloned into delta payloads, so larger scene graphs need continued memory profiling rather than an assumption of zero-copy history. Autosave/recovery and independent multi-document tabs are implemented as separate editor-session services.

Selection is editor state scoped to a symbol and stable layer/element IDs. Gestures capture the authored frame, view transform and original sampled poses, then apply changes from that snapshot. Keys and history begin only with an effective edit; cancellation and a return to the original pose leave neither behind. V selects/moves and Q exposes object transform handles. Multiple selections support rotation and uniform scaling; the TRS document model does not silently approximate skew. See [selection and gestures](decisions/0004-selection-and-gestures.md).

The core clipboard model captures ordered sampled placements and their reachable symbol definitions in bounded, versioned text. It prepares a complete validated destination before the editor commits one history transaction. A live document-session identity permits reuse of current library definitions; another document receives consistently remapped symbol/layer/placement IDs. The editor routes text and object commands separately, preserving the text recipient across menu focus changes. See [clipboard transfer](decisions/0005-clipboard-transfer.md).

## Imports and compatibility

The importer is independent of native GUI and publishing. It inspects container signatures, converts a documented XFL subset and binary FLA saved by Flash 3 through CS4, and reports every approximation with a location; unsupported XFL content blocks import rather than disappearing. Shared bounded adapters also feed the editor and CLI for PSD/PSB, numbered image sequences, supported PDF/AI vector/text operators, FXG and ACT/CLR/ASE palettes. They prepare and validate the complete result before the editor commits one Undo step. Binary FLA, SWF bytecode/runtime and restoration of an editable source project remain different compatibility tracks. See [IMPORTS.md](IMPORTS.md) and [decision 0036](decisions/0036-legacy-fla-partial-import.md).

Opt-in binary preservation reads Contents, archive object/reference tables and typed timeline fields from one immutable container snapshot. Partial ancestors, source-action presence and original byte spans remain explicit. Archive identity and byte consumption do not establish cross-frame placement identity or an editable document; conversion remains a separate validated adapter.

The pure solid-contour adapter accepts a strict Flash 3 record/context subset. It assembles exact integer endpoints before applying the shape's full affine matrix to core path coordinates, retaining edge provenance separately. Bounded intersection/nesting checks reject ambiguous topology and paint; this API does not infer layers, timeline placement identities or document-wide import eligibility.

## Verification boundaries

Tests cover core state, persistence, script compilation, import fixtures, publisher errors, and actual compiled WASM behavior in Node. Native UI and browser rendering require separate observed checks. Desktop and browser text use different shaping backends at this stage; identical transforms do not establish pixel-perfect typography.

The publication data-loading service resolves embedded resources before normal browser HTTP(S), shares the EventDispatcher/ByteArray services and cancels requests on Restart/disposal. Clipboard preserves the complete resource snapshot because URL dependencies can be computed at runtime. See [portable resources and loading](decisions/0013-portable-resources-and-loading.md).
