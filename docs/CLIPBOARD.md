# Clipboard workflows

Select objects with V or Q, Shift-click or a marquee. Copy (⌘C) captures the selected objects at the displayed frame without modifying the document. Cut (⌘X) prepares the same complete data before deleting the selection. One Undo restores a cut.

Paste (⌘V) inserts the objects into the active visible, unlocked layer, preserving their relative positions and painter order. The selection's copied bounds are centered in the visible stage area. Paste in Place (Edit menu, ⇧⌘V) retains original coordinates in the current symbol's coordinate system. A nested symbol uses its own editing origin. These operations preserve object transforms; they do not scale artwork to a differently sized stage.

When pasting into an interpolated frame, a key is materialized from the sampled layer before the new objects are added. Unrelated sampled objects remain at their current pose. The existing sampled-key convention inherits the preceding tween; curve-preserving subdivision is not promised. The complete paste, including new library definitions, is one Undo step. Failed candidate validation leaves the destination unchanged; any valid drawing gesture is finished before the paste command, as for other document commands.

Copying instances includes every reachable symbol definition, all their authored keys, playback modes, frame/object scripts, labels and accessibility metadata. Multiple instances sharing a symbol continue to share it after insertion. Within the same open document, live symbol definitions are reused, so an edit made to the library after Copy is reflected in Paste. A removed definition can be recovered from the captured data. Opening another document, even another copy of the same file, creates a separate clipboard session: imported symbols, layers and placements receive fresh, consistent IDs. Save As keeps the current live document session.

Copy also captures the project source-unit snapshot and every explicitly exported library symbol with its dependencies, including exports with no authored placement. Dynamic class construction and `attachMovie` can select these symbols through computed values, so omitting them would lose runtime timelines. The same clipboard budgets apply to this complete snapshot; an oversized closure produces a diagnostic. Cross-document paste may reuse an existing export only when its entire captured symbol closure matches after local IDs are normalized. Shared dependency identities stay shared, including separately selected instances; different content or incompatible sharing rejects the complete paste. Conflicting source paths also reject the paste. This preserves program data without executing it or inferring dependencies from script text.

All portable project resources are included too: script-selected paths cannot be inferred reliably from source text. A resource carries its logical relative path, media type and base64 bytes; no filesystem handle or external file is read by clipboard operations. An existing path is reused only when its exact spelling, media type and bytes are identical. Case-only path collisions, different bytes or type reject the entire paste, including within the same session. New resources receive fresh entity IDs, and the complete candidate remains one Undo step. Resource data is immutable shared storage in document/history clones. Projects containing resources use document version 3 so older readers reject them instead of silently discarding their bytes; resource-free version 1/2 documents remain readable.

Pasted top-level objects always receive new placement IDs. Names and script text are preserved, not rewritten to guess references. Animation retains authored frame indices and uses the destination document's frame rate. Scripts are data during copy/paste and execute only through the existing preview/publishing path.

Text fields, including Actions, use their text selection. Opening Edit temporarily removes text focus; the editor records the recipient and restores it for the chosen text command. Clipboard text operations pause authoring playback before the field is consumed, preventing a command from editing a later frame. Changing the document, symbol, frame, layer or text target cancels a queued text command.

Inline Stage text Copy/Cut retains mixed formatting for Paste, including across document tabs. On macOS Apple Silicon, that cache belongs to a specific system-clipboard write. Replacing the clipboard invalidates the old formatting even when the plain text is identical; unavailable ownership metadata also falls back to ordinary text insertion using the destination style. A native rich Copy writes its plain-text representation immediately, and Paste checks ownership metadata only when invoked. It does not poll or inspect clipboard contents in the background. Each accepted text paste remains one Undo step; arbitrary rich formats from other native applications are not promised.

Object Copy places a `NEOFLASH-CLIPBOARD` header followed by versioned JSON in the system clipboard. It is portable between NeoFlash app sessions and can include source code, authored content and embedded resources. Installed font files are not automatically added, and paths mentioned in scripts are not resolved. Ordinary text can replace a selected editable Stage text field or its active text range; unsupported content produces a diagnostic. Malformed NeoFlash payloads also produce a diagnostic. Copying an unsupported or oversized selection does not replace the existing clipboard or delete the selection.

The initial transfer limits are 8 MiB of encoded text, 1,024 reachable symbols, 10,000 aggregate placement records, 4,096 layers, 16,384 keys, 10,000 scripts and 200,000 path commands. Normal document validation still applies, including graph cycles, depth, transforms and expanded scene limits. Unknown clipboard versions or fields are rejected to avoid silently losing content.

The 8 MiB clipboard cap includes resource base64 and remains smaller than the document resource limits (1,024 resources, 16 MiB per decoded resource, 64 MiB decoded total). A project can therefore save successfully while its complete resource snapshot is too large to copy. This produces an explicit diagnostic; resources are never dropped to make the selection fit.

Selected frame ranges use their own frame clipboard (Edit ▸ Timeline and the frame menu). It works within and across open document tabs, preserves multi-layer ranges and keyframe side-tables, imports the same transitive symbol/resource/font/swatch/style closure as object paste, remaps colliding identities consistently and creates missing destination layers in the same Undo step. **Include frame scripts** transfers the selected symbol-level Actions once and rejects a destination collision before mutation; object scripts travel with their placements. Bitmap data from the native clipboard and SVG clipboard text can be pasted onto the Stage; the Clipboard preference chooses editable SVG paths or a rendered bitmap fallback. Other rich native clipboard formats are not promised.

Keyboard Paste in Place uses the modifiers captured when the native paste shortcut is pressed. A small pinned [egui-winit adapter patch](../vendor/egui-winit/NEOFLASH-PATCH.md) preserves that key event immediately before its paste payload, so releasing Shift before V or pressing Shift later in the same input batch does not change the operation. Native paste payloads are authoritative for their input batch: the editor consumes paste-key presses before ordinary shortcut routing, even when pointer input separates the key from its payload or the key arrives later. Only the immediately preceding press supplies the paste mode; standalone shortcuts without a payload still use the clipboard. Each payload is delivered once to the chosen recipient and remains one Undo step for artwork. Text fields retain ordinary text paste behavior for both shortcuts. An unpaired paste payload, including a platform/accessibility paste without shortcut metadata, means ordinary Paste; the explicit Edit → Paste in Place command retains its selected mode independently.

Automated verification covers the transfer model, actual shared runtime behavior after paste/reopen, the native adapter's event translation, and headless egui menu/text events, including reversed release order, interleaved pointer input, custom shortcuts, text ownership and multiple pastes in one input batch. Headless tests inject clipboard contents; reaching a system-clipboard read fails explicitly so unrelated clipboard data cannot hide duplicate dispatch. Live macOS checks additionally confirmed ordinary Copy/Paste, keyboard/menu Paste in Place and transfer of two instances sharing one library symbol into a new document. Saved JSON verified coordinates, remapped identities and both script languages. Specific physical modifier-release order and exhaustive platform clipboard interoperability remain unverified; see [verification](VERIFICATION.md).

Rich-cache regressions extend the existing `clipboard_tests::t326_*` family with equal-text replacements, tab switching, unavailable ownership and one-step Undo. The macOS ARM64 test `clipboard::native::tests::equal_plain_text_with_replaced_rich_flavors_changes_generation` uses a uniquely named pasteboard, never the user's general clipboard, and covers different HTML representations with identical plain text plus deferred-write ordering. Live native acceptance verifies successive red/bold and blue/italic copies, external replacement by identical plain text, Undo/Redo and the saved destination formats. This does not establish external rich-format interoperability or other-platform acceptance.
