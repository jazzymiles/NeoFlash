# AS2 SOAP services and XML connectors

This package implements a useful nonvisual profile of `mx.services.WebService`, `SOAPCall`, `PendingCall`, `Log`, `mx.data.components.XMLConnector` and `WebServiceConnector`. It adds **58 previously missing declaration entries**: 12 methods, 20 properties, 11 callbacks/events, seven constants, two constructors and six class entries. The generic `WebService.myMethodName` catalogue row represents dynamic WSDL operations; individual fixture operation names are not counted as new APIs. `SOAPCall.doLazyDecoding` remains unsupported and is not promoted.

The new protocol algorithms are Rust in `crates/neoflash-core/src/as2_services.rs`. They reuse the existing bounded XML tree and its quick-xml parser. `web/as2-services.js` holds browser object identities, connects the existing network transport, forwards callbacks and uses existing AS2 EventDispatcher and ComponentMixins. The WASM adapter only serializes command inputs/results. No foreign-language protocol implementation or complete engine is embedded. There is no editor UI, FLA conversion or added AS3 facade.

## WSDL and SOAP profile

A WebService loads an actual WSDL 1.1 document asynchronously. A successful parse creates operation descriptors and calls `onLoad` with the AS2 XML document; a load/parse failure calls `onFault`. Calls made before WSDL completion are queued, up to 128 waiting calls. `getCall(name)` returns the shared SOAPCall descriptor after WSDL has loaded. An unknown operation becomes a real client fault; it never returns a fabricated server result.

The profile supports one inline service with one SOAP 1.1 port, HTTP binding, document/literal wrapped messages and RPC/literal scalar type parts. Wrapped documents use an inline XSD complexType/sequence, scalar child elements, qualified or unqualified element names, optional fields and nillable fields. Supported scalar types are string, boolean, int/integer/long/short/byte, unsignedInt/unsignedShort/unsignedByte, float/double and decimal. Integer values must be exact JavaScript-safe integers, with the narrower integer type ranges enforced. Floating-point and decimal values use finite IEEE-754 Numbers; arbitrary decimal precision is not claimed. A message has at most 128 parameters and a WSDL at most 128 operations. ASCII operation/parameter names form the current authoring profile.

Rust resolves QName namespaces, constructs escaped SOAP XML, verifies response wrappers and converts output values against the declared schema. Output parameters preserve their AS2 XMLNode representation alongside the decoded value. A server SOAP Fault is decoded into faultcode, faultstring, detail, element and faultactor, including when delivered with HTTP 500. A non-Fault HTTP error remains a failure. An explicit host-only `loadBytes` option allows SOAP to inspect HTTP error bodies; ordinary URLLoader and AS3 error behavior are unchanged.

Unsupported external WSDL/XSD imports/includes, encoded SOAP bodies/arrays, lazy arrays, headers, attachments, nested/custom schema values, SOAP 1.2, multiple ports and one-way messages fail with actionable diagnostics. DTDs and external entities are rejected by the shared strict XML parser. XML input remains bounded to 1 MiB; command envelopes to 4 MiB. Browser same-origin/CORS, HTTP(S), credential and shared transport limits apply. The package does not emulate Flash policy files, authentication dialogs or unrestricted cross-domain requests.

`PendingCall` exposes the actual request/response XML, descriptor and all five output accessors. `onResult` receives the first decoded output value. `doDecoding=false` returns the raw response XML to the callback while output accessors remain available within this scalar profile. `MULTIPLE_CONCURRENCY` permits independent calls, `SINGLE_CONCURRENCY` faults a second active invocation, and `LAST_CONCURRENCY` cancels previous transports and suppresses their completion callbacks. Changes apply to subsequent invocations.

## Nonvisual connectors and logging

XMLConnector supports receive (GET), send (POST with no result event) and send/receive (POST followed by XML). Params must be an AS2 XML document. Results are parsed AS2 XML; `ignoreWhite` controls whitespace-only text nodes. The connector emits send before validation/transmission, result after successful receive, and status for active-call counts, concurrency rejection and faults. It has no visual component skin or design-time schema editor.

WebServiceConnector uses the same WebService implementation with an operation name and positional Array or named Object params. It emits send/result/status, retains the result and reports real WSDL, transport and SOAP errors. Both connectors support multipleSimultaneousAllowed and the existing primitive binding validation policy through suppressInvalidCalls. They refresh existing source bindings before a trigger and destination bindings after a successful result. This is the existing primitive ComponentMixins profile, not complete XML-schema validation or the Flash data-schema framework; disabling validation cannot bypass the required valid XML/SOAP shape.

Log supplies NONE/BRIEF/VERBOSE/DEBUG filtering, mutable name/level, logInfo/logDebug, onLog and a local-time date string. The browser supplies clock fields; Rust formats and filters messages. Logs go to the authored callback, not a fabricated disk log. Service/connector lifecycle messages are a bounded subset of the historical verbose diagnostics.

A publication holds at most 128 service/connector objects before Restart, with the shared transport limit of 32 in-flight requests. Reset cancels pending transports, invalidates callbacks and discards service references before dependent XML, network, binding and event services reset. A bounded lifecycle review also added generation checks after the authored WSDL onFault callback and before each queued fault delivery or queued invocation, so a callback-triggered Restart stops the old queue; these final guards were source-reviewed without another test cycle. The same review separated XML parsing failures from subsequent binding/callback errors, preserving one active-count decrement per completed request; callback failures follow the shared transport error-reporting path. Native subclassing and full historical component inheritance remain unsupported.

## Provenance and validation

Contracts were checked against Adobe's [AS2 Components Language Reference](https://web.archive.org/web/20130325184910id_/http://livedocs.adobe.com/flash/9.0/main/flash_as2_components_reference.pdf), pages 1415–1466 and 1491–1506. The already downloaded reference remains under ignored `target/actionscript-reference/components/`; its pinned PDF SHA-256 is `95a200ff72acb178048b92ee00a3fec7aba69c3c808b63a3df42ab32d48c7b01`. Protocol structure follows the dated [WSDL 1.1 note](https://www.w3.org/TR/2001/NOTE-wsdl-20010315) and [SOAP 1.1 note](https://www.w3.org/TR/2000/NOTE-SOAP-20000508/). Reference prose/source code is not copied into the implementation.

The reused parser is quick-xml 0.41.0 (MIT), already pinned in Cargo.lock with checksum `e660451e55124f798a69a5af3f49ccfbefbd41910eefd25caf2393e1f3473ec1`. Existing XML, broadcaster, binding and transport provenance remains with those modules. New SOAP/WSDL composition and service glue are project code; no additional library or engine dependency was introduced.

One grouped native scenario, `as2_services::tests::as2_services_family`, passed. It exercises typed parameters, XML escaping, multiple output values, namespace-preserving output XML, actual HTTP-error fault decoding and explicit rejection of malformed/unsupported inputs. JavaScript syntax passed. One ordinary export of `examples/as2-services-batch.nflash` succeeded. In the shared coordinator browser run, the visible Run service batch button completed **12 passed / 0 failed**. Actual same-origin SOAP POSTs, HTTP 500 Fault, SINGLE/LAST concurrency and raw-XML response mode were observed, with matching local server request logs. This is representative family evidence, not one acceptance test per declaration or full SOAP conformance. There was no separate full suite or WASM build for this package.

The ordinary example has one local Log check and eleven asynchronous HTTP groups behind a visible **Run service batch** button. It uses the authored `examples/as2-services.wsdl` and optional same-origin demo endpoints described below. Opening the file without the fixture server does not pretend those network scenarios passed. Exact declaration inventory is in ignored `target/verification/as2-two-hour-2/services-inventory.json`; the tracked catalogue review records this bounded shared acceptance.

## Optional local fixture contract

- GET `/__as2_services.wsdl`: serve `examples/as2-services.wsdl` as XML.
- POST `/__as2_soap`: accept SOAP 1.1 text/xml with SOAPAction `urn:neoflash:Echo` or `urn:neoflash:Fail`. For Echo, read qualified message and count parameters and return EchoResponse in namespace `urn:neoflash:as2-services`, with result equal to message, accepted=true and the same count. For Fail, return HTTP 500 with a SOAP Fault whose faultcode ends in Server, faultstring is `Deliberate service fault` and detail includes the supplied reason.
- GET `/__as2_connector`: return `<catalog>\n  <item>Rust &amp; XML</item>\n</catalog>`.
- POST `/__as2_connector`: validate `<request><message>connector</message></request>` and return `<receipt accepted="true">connector</receipt>`.

The fixture server is delivery tooling under ignored target, not an exported service, deployed backend or production SOAP implementation.
