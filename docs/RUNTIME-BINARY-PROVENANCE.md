# Rust AS3 ByteArray codecs

This packet adds bounded binary codecs to NeoFlash's shared Rust core. The existing ByteArray host retains its buffer ownership, positions, allocation budgets and publication lifecycle. New compression, text encoding and base64/hex algorithms execute in Rust/WASM. No complete ActionScript engine, C backend, foreign-language implementation or external IO is introduced.

Individual control flow and behavior are adapted from [Ruffle `89a7049965f3090e706265670df309a5128233ac`](https://github.com/ruffle-rs/ruffle/tree/89a7049965f3090e706265670df309a5128233ac), MIT selected from MIT OR Apache-2.0; see the retained [license notice](../THIRD_PARTY_NOTICES.txt). The downloaded source is confined to ignored `target/verification/as-runtime-hour/binary/upstream/`, with hashes in the adjacent inventory.

Legacy multibyte character sets now use the ordinary Rust [`encoding_rs` 0.8.35 library](https://github.com/hsivonen/encoding_rs/tree/2fa58aecf537cc76ff52c0eb3d5e9f8fda466844), the same codec family used by the inspected Ruffle implementation. The crate is pinned to `=0.8.35`, with default features disabled and only `alloc` enabled; its only enabled dependency is the existing `cfg-if` crate. License: `(Apache-2.0 OR MIT) AND BSD-3-Clause`; NeoFlash selects MIT plus the WHATWG data notice. The exact crate archive SHA-256 is `75030f3c4f45dafd7586dd6780965a8c7e8e285a5ecb86713e63a79c5b2766f3`. Required license texts and source hashes are retained in the ignored inventory and included through the shared distribution notices.

The earlier hand-written Windows-1252 table and multibyte decoders were removed. No large encoding tables are copied into NeoFlash source. `Encoding::for_label` supplies standard labels; existing `utf16le`, `utf16be`, `latin-1` and `cp1252` aliases are retained, with `cp1251` added. `ISO-8859-1`, `latin1` and `ASCII` map to Windows-1252, following WHATWG/Ruffle behavior. Replacement-only encodings and unknown labels explicitly reject. UTF-16 writing retains the explicit Rust implementation because `encoding_rs` deliberately does not supply UTF-16 encoders.

**38 enabled encoding profiles (39 canonical names), up from 4: 34 added profiles and zero additional API names.** ISO-8859-8 and ISO-8859-8-I share one byte mapping and count once; label aliases do not count. The profiles cover UTF-8, UTF-16LE/BE, Windows-1250 through 1258 and 874, ISO-8859-2/3/4/5/6/7/8/10/13/14/15/16, IBM866, KOI8-R/U, Macintosh, x-mac-cyrillic, Shift_JIS, EUC-JP/KR, ISO-2022-JP, GBK, GB18030, Big5 and x-user-defined. This reports enabled codec routes, not exhaustive conformance testing of their tables.

Legacy encoding uses an 8 KiB scratch buffer and refuses to exceed the configured byte budget before appending output. Unrepresentable output characters reject rather than introducing replacement bytes or numeric character references; incoming malformed byte sequences follow the codec's replacement-decoding rules. Decoded strings terminate at NUL while consuming the full requested byte range and honor Unicode BOM overrides. Decode memory is bounded by the input budget (at most three UTF-8 bytes per input byte). No platform codepage lookup or unknown-label fallback is performed. The separate existing strict UTF packet methods retain their earlier semantics.

Files: `crates/neoflash-core/src/as_binary.rs`, `crates/neoflash-web/src/as_binary.rs`, and the thin codec calls in `web/byte-array.js`. `ByteArray.create({wasm})` provides the five binding functions. Codec errors, malformed compressed/text data, unsupported algorithms and allocation failures preserve the original buffer and position. Decoded output is capped by the service's configured byte limit (16 MiB by default, at most 256 MiB); decompression writes through an 8 KiB scratch buffer and checks the cap before growing its result. Existing total publication capacity and instance budgets still apply at commit. Temporary codec copies are bounded independently and are not claimed to be charged to the persistent publication capacity budget.

**12 newly supported API names and 5 existing UTF API paths migrated to Rust.** Six legacy names are `compress`, `uncompress`, `deflate`, `inflate`, `readMultiByte`, and `writeMultiByte`. The historical catalogue contains four of these; its `deflate`/`inflate` omissions are recorded without expanding its denominator. Six AIR 51 extensions are `toBase64`, `toHexString`, `writeBase64`, `writeHexString`, `createFromBase64`, and `createFromHexString`. Factories and deflate wrappers reuse shared operations rather than adding independent algorithms. No constructor, property, constant or language syntax is added.

One grouped Rust test covers this family. `examples/runtime-binary.nflash` is one ordinary source project with 16 grouped checks, all 12 API names, compression roundtrips, multibyte text, base64/hex exchange and failed-operation preservation; its Run Again button reruns the same authored method. The coordinator owns the shared build and actual HTML5/browser evidence. Inventory and source inspection alone are not execution evidence.

Remaining boundaries: LZMA, gzip/ZIP container parsing, non-WHATWG/platform-only codepages (including UTF-7/UTF-32), full native exception classes/error IDs, arbitrary AS argument coercion, shared workers and atomic operations. Compression output is valid interoperable zlib/raw DEFLATE, not guaranteed byte-identical to a historical Adobe compressor. Base64 accepts the strict canonical padded RFC 4648 alphabet; hex rejects whitespace, prefixes and odd digit counts. Existing primitive number and AMF paths are unchanged by this packet.

The five migrated paths are `readUTF`, `readUTFBytes`, `writeUTF`, `writeUTFBytes`, and `toString`. The former browser UTF validation/encoding/BOM/NUL algorithms were removed. Thin adapters marshal raw UTF-16 units so malformed surrogate input reaches Rust unchanged; native TypeError/RangeError identities and the existing strict profile are retained. Numeric length prefixes and cursor/buffer commits remain part of the host storage adapter. These are conversions of existing supported behavior, not new compatibility entries. The existing `binary-data.mjs` scenario already exercises all five paths plus invalid UTF/surrogate and cursor preservation; no additional per-method tests were added.

The charset extension reuses the same grouped core test and replaces the ordinary export's existing UTF-8 roundtrip check with one combined seven-encoding loop. Core byte-oracle samples cover Windows-1251, Shift_JIS, GBK, Big5 and EUC-KR, plus an ISO-2022-JP stateful roundtrip. The export remains 16 grouped checks; no new test function, project or per-method browser cycle was added.
