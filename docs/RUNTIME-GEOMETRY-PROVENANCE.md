# Rust 2D geometry family

This one-hour scripting batch moves Point, Rectangle, Matrix and ColorTransform value state and calculations from the former JavaScript implementation into `neoflash-core/src/as2d_geom.rs`. The WASM `Geom2dValue` class transports bounded JSON; `web/geom.js` supplies per-publication facades, validation, identity and argument/result transfer. Display, bitmap and authored program code share the same constructor family. Explicit native initialization preserves existing project subclasses without copying closures bound to a temporary object. There is no complete foreign engine or new dependency.

Individual algorithms were adapted from [Ruffle `07d3e430631333f80f754df01a968bdcd80d98c5`](https://github.com/ruffle-rs/ruffle/tree/07d3e430631333f80f754df01a968bdcd80d98c5), selecting its MIT license. Nine AIR 33.1 output-parameter methods follow the official [Point](https://airsdk.dev/reference/actionscript/3.0/flash/geom/Point.html) , [Matrix](https://airsdk.dev/reference/actionscript/3.0/flash/geom/Matrix.html) and [Vector3D](https://airsdk.dev/reference/actionscript/3.0/flash/geom/Vector3D.html) contracts: `Point.addToOutput`, `subtractToOutput`, `interpolateToOutput`, `polarToOutput`, `Matrix.transformPointToOutput`, `deltaTransformPointToOutput`, `Vector3D.addToOutput`, `subtractToOutput`, `crossProductToOutput`. They reuse the same Rust kernels and setter path. Non-null output retains its identity; null allocates a new Point or Vector3D, and input/output aliasing computes before mutation. No documentation prose or example source was copied into the implementation.

AS2 `Color` adds `getRGB`, `setRGB`, `getTransform` and `setTransform`, adapted from Ruffle [AVM1 `color.rs`](https://github.com/ruffle-rs/ruffle/blob/07d3e430631333f80f754df01a968bdcd80d98c5/core/src/avm1/globals/color.rs). The browser facade binds a live display-object target and transfers its ColorTransform; the Rust kernel handles RGB packing, percentage conversion, signed 8.8 multipliers and 16-bit offset wrapping. Only supplied own properties are changed. Object targets are supported; string paths, missing targets and subclassing diagnose explicitly. This class does not add a second color state or rendering path.

AS3 standalone `PerspectiveProjection` adds `fieldOfView`, `focalLength`, `projectionCenter` and `toMatrix3D`, using the existing Rust 3D value bridge. Defaults, focal conversion and projection-matrix algebra are adapted from Ruffle [`PerspectiveProjection.as`](https://github.com/ruffle-rs/ruffle/blob/07d3e430631333f80f754df01a968bdcd80d98c5/core/src/avm2/globals/flash/geom/PerspectiveProjection.as), [native accessors](https://github.com/ruffle-rs/ruffle/blob/07d3e430631333f80f754df01a968bdcd80d98c5/core/src/avm2/globals/flash/geom/perspective_projection.rs) and [render projection value](https://github.com/ruffle-rs/ruffle/blob/07d3e430631333f80f754df01a968bdcd80d98c5/render/src/perspective_projection.rs), under the same pinned MIT notice. Unbound width is 500, focal length/matrix retain f32 rounding, and center getters return a Point from the same publication. The center setter copies finite coordinates. Display-object association, a 3D renderer, native subclassing and arbitrary AS coercions remain outside this profile.

`fl.motion.Color` adds three methods (`interpolateColor`, `interpolateTransform`, `setTint`), three properties (`brightness`, `tintColor`, `tintMultiplier`) and one constructor. It extends the same native ColorTransform facade and owns no second color state; inherited entries are not recounted. Its packed RGBA interpolation is individually translated from MIT-licensed HaxeFlixel [`FlxColor.interpolate`](https://github.com/HaxeFlixel/flixel/blob/c2030e3c9b6463577319f9697f7b72c1bd546566/flixel/util/FlxColor.hx). Copyright (c) 2009 Adam 'Atomic' Saltsman, (c) 2012 Matt Tuttle, (c) 2013 HaxeFlixel Team; the retained MIT notice accompanies publications. The per-channel interpolation is also applied to the eight existing transform values. Tint/brightness algebra is authored against the [documented Color contract](https://help.adobe.com/en_US/FlashPlatform/reference/actionscript/3/fl/motion/Color.html) and existing ColorTransform equation; no Adobe implementation source or documentation example was copied. Packed channels truncate toward zero, progress/tint ratios require 0–1, and brightness requires −1–1. Tint getters require equal RGB multipliers; brightness getters require uniform RGB values. XML construction, arbitrary extrapolation/coercion and native subclass initialization diagnose explicitly. The official class does not declare HSB/RGB conversion methods, so no such methods were invented. The shared example interpolates an actual marker tint on Advance.

`fl.motion.MatrixTransformer` adds all 19 static methods named in the [official reference](https://help.adobe.com/en_US/FlashPlatform/reference/actionscript/3/fl/motion/MatrixTransformer.html): eight scale/skew/rotation getters, eight corresponding setters and three pivot/alignment helpers. No properties or constructors are counted. Axis-angle decomposition and reconstruction adapt the existing pinned Ruffle [`display_object.rs`](https://github.com/ruffle-rs/ruffle/blob/07d3e430631333f80f754df01a968bdcd80d98c5/core/src/display_object.rs) algorithms under the same retained MIT notice. VM/display caching is removed; the existing Rust Matrix owns the six coefficients, and existing composition plus a shared point kernel implement pivot rotation and point alignment. Getters recompute axis magnitudes and angles; setters preserve the other axis and translation except when a pivot/alignment operation changes translation. Rotation preserves the difference between axis angles. Degree/radian aliases share calculations, with no new browser arithmetic or state. Finite input/output and atomic-overflow rules apply; zero-scale values do not retain hidden angle/sign history. The same example adds seven grouped checks for all 19 names, and Advance uses external-pivot rotation on the actual marker matrix. The existing grouped Rust test is extended, without a separate per-method test suite.

Counts: **46 new method/property entries** (40 methods and 6 properties), **45 existing methods and 29 existing properties moved to Rust**; four migrated and three new constructors counted separately. Four existing NeoFlash Rectangle bounds aliases remain available but are excluded from the standard API headline. AS2 and AS3 use the same implementations; those migrations are not doubled by dialect. The nine output names do not count as nine independent arithmetic algorithms. No new language constructs are claimed.

`examples/runtime-geometry.nflash` is one ordinary project with 54 grouped AS3 checks exercising 116 listed method/property names, plus a six-check AS2 probe using the same Rust families. Together the AS2/AS3 probes execute 120 unique method/property names. Its marker takes an actual Matrix and AS2 Color changes through the existing display transform. One grouped Rust test covers value/mutation/transfer/overflow behavior. Browser/shared-run results belong to the main hour report; this document alone is not acceptance evidence. Exact source hashes and per-member inventory are retained under ignored `target/verification/as-runtime-hour/geometry/`.

Boundaries remain finite numeric input/results, strict coordinate objects, atomic rejection of overflowing mutations, singular-inverse diagnostics, bounded transport, incomplete AVM coercion/prototypes and exact numeric-to-string formatting. ColorTransform concat order and native ColorTransform subclassing remain explicitly limited. Internal pre-existing display-list transform arithmetic is not migrated or counted by this value-family change.
