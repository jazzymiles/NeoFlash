# AS2 bitmap PrintJob in HTML5

PrintJob reuses the shared Rust BitmapData scene capture and PNG encoder, then gives actual captured pages to the browser's print preview. This is a deliberately bounded web profile: it neither reads a physical printer's capabilities nor recreates Flash's operating-system dialog sequence.

`new PrintJob()` creates a publication-owned job. An explicit click calling `start()` opens a separate preview window; popup blocking returns false. The ordinary browser print dialog appears at `send()`, after the captured PNG pages are decoded. Cancellation is controlled by the browser and does not prove that a physical page was printed. Preview windows and their Blob URLs belong to the publication and are closed/released on Restart.

The read-only paper and page properties describe the job's **virtual CSS page**: portrait, 595×842 points, 36-point margins and 523×770 printable points. The same geometry is declared in `@page`; browser print settings may override it. These values are explicit authored output geometry, not invented device-reported printer facts. They become available after a successful `start()`.

`addPage` supports a live MovieClip/current runtime frame and an explicit `{printAsBitmap:true}` option. Root level 0 and live reference resolution are supplied by the shared runtime. The `printArea` uses local xMin/yMin/xMax/yMax coordinates, rounded outward to raster pixels. Omitted bounds use the current target area. Oversized areas are clipped to the right/bottom of the printable page; one source pixel maps to one print point. The Rust policy validates coordinates and limits each job to eight pages / 32 MiB of captured PNGs. The existing Rust snapshot and shared painter retain the ordinary scene's text, vectors, bitmaps, video and filters within their existing capture boundaries; no timeline is advanced or authored script evaluated to make a print page.

Explicit vector printing and arbitrary timeline frame selection diagnose rather than silently switching behavior. Physical device dimensions, orientation selected in a printer dialog, vector PDF fidelity, printer status, exact Flash page failure timing and custom native PrintJob subclasses remain unsupported. Native authoring UI and AS3 are unchanged.

The contract reference is Adobe's mirrored [PrintJob documentation](https://open-flash.github.io/mirrors/as2-language-reference/PrintJob.html). New page policy is project Rust code; existing BitmapData capture and platform modules retain their recorded provenance. No print library, foreign-language engine or new runtime dependency is embedded.

Validation extends the existing `as2_platform_family` test and the existing `as2-capture-batch.nflash` example with a **Print scene** button, producing two raster pages from the current scene. No new test function or standalone HTML5 family is added. The coordinator clicked Print scene in the ordinary export and observed `AS2_PRINT_PAGES true true page523x770 paper595x842 portrait`: two Rust-captured PNG pages were accepted and send was invoked without an observed error. The owned popup was not exposed as a controllable in-app browser tab, and native Codex app inspection was unavailable. **Visual preview, system dialog and cancellation remain unverified.** This is limited browser acceptance of capture/page submission, not proof of printing. No physical printing is performed or claimed by the development checks.

The bounded inventory contains ten new partial declarations: the class, constructor, three methods and five properties. This does not constitute complete Flash PrintJob compatibility.
