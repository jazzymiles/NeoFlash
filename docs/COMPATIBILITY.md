# Script and runtime compatibility

Timeline frame ranges support multi-layer selection, copy/cut/paste, move, clear and time insertion/removal. Independent layer ends stop authored exposure in native and HTML5 evaluation. Frame scripts remain symbol-level: “Include frame scripts” moves them once, and a destination code collision rejects the complete operation. Object scripts travel with their placements. Trimming a layer removes later keys and is undoable. Edits intersecting tweens bake the affected segment to integer-frame poses to preserve appearance; this does not retain an editable easing curve across the cut. Clips are internal to the current editor session, and paste requires existing destination layers.

## Native timeline authoring

Layers support inline rename, compact row labels, configurable colored outlines, folders, guides and vector masks. Outline display is authoring-only. Native and HTML5 painting share authored mask geometry; guide layers are excluded from publication. Text/bitmap mask sources and nested mask roles inside mask sources diagnose. Four-sided workspace docks support resizable groups, reordered tabs and transfer between native floating windows. Floating windows support horizontal/vertical splits. Convert to Symbol provides name/type/folder, nine-point registration and existing runtime identifier/class linkage. Library adds first-frame preview, search, sorting and persistent folders. Group conversion requires contiguous artwork on one layer. 9-slice guides, arbitrary recursive main-window splits and legacy shared-library options remain unsupported.

SVG/PNG/JPEG import supports the File menu, Library controls and native file drops. Placement fits graphics within the page and creates a visible normal layer when necessary; supported resources and symbols can be dragged from the Library. Solid SVG artwork becomes editable paths; richer paint uses a rendered image and retained original source. SVG animation/scripts, embedded HTML and external file references reject. See [workspace behavior and limits](WORKSPACE.md).

The timeline distinguishes held content, blank-key intervals and unused cells after its end. An ordinary key holds its content until the next key or the end of the symbol; a blank key ends that exposure. Moving the last key does not shorten a layer. Layer lengths are not stored independently, and frame-range selection/clipboard remain unfinished.

Keyframe dragging uses the original pressed frame, keeps scrollbars outside frame rows, previews the destination and scrolls at the grid edges. Frame Actions opens from the timeline context or toolbar; selecting a frame makes F9 target that frame. The Actions header identifies the symbol and frame, and opening it pauses playback. Frame scripts belong to the symbol/frame and are shared across its layers. Onion skin has a visible stage-header indicator; its tinted neighbouring frames remain visible even when the current frame is blank. Scrubbing and onion preview do not execute authored scripts.

Button authoring uses Up/Over/Down/Hit; Hit is input-only in HTML5. AS2 object callbacks and AS3 events target the instance. Authored/export-linked buttons are recognized as `flash.display.SimpleButton`; linked AS3 classes must extend that base. Dynamic empty SimpleButton construction and arbitrary state-display-object setters remain unsupported. Graphics support Loop / Play once / Single frame with a placement-specific First frame. Align, distribution and exact spacing treat authoring groups as units. See the [bounded tool and panel behavior](WORKSPACE.md#tools-and-modify).

## Runtime scope

AS2 and AS3 support is partial. The [complete declaration audit](progress/ACTIONSCRIPT.md) separates implemented subsets, partial support, missing entries and review gaps. [Verification scope](VERIFICATION.md) distinguishes observed browser behavior from native/compiler checks; a successful example does not establish full language or API conformance.

Shared Rust services provide display, geometry, media, data, binding, strings and image behavior. Browser adapters connect viewport, capture, messaging, HTTP and printing. Hardware camera/microphone capture and system print-preview acceptance remain unverified. Raw TCP/RTMP, remote SharedObject and full historical prototype/coercion semantics remain unsupported. See the [AS2 browser-service profiles](AS2-RUNTIME-TWO-HOUR.md) and [data/display profiles](AS2-TWO-HOUR-2.md) for their limits.

The standalone handler API remains `neoflash_script::compile(&Script) -> Result<String, Vec<Diagnostic>>`. Publication first calls `compile_project(&Project)`, then `compile_with_program(&Script, &ProjectProgram)` for handlers. Diagnostics include the source language, one-based line/column and a message; project-source diagnostics also identify the logical source path. A failed script or unresolved linked class blocks publishing. A single script/source unit is limited to 1 MiB; the AS frontend also bounds token count, parsing nesting (48 levels) and expression-tree depth to avoid runaway parsing.

## Project source and class profile

Version-2 documents store source units with stable IDs, normalized project-relative paths, language and source text, plus optional document-class and symbol-class names. Existing version-1 documents remain supported; adding project source/linkage promotes the document to version 2. Source paths identify files inside the saved snapshot, not arbitrary filesystem/network dependencies. Validation rejects duplicate paths, invalid linkage names and conflicting root/document linkage. Limits are 4,096 units and 16 MiB of combined source, within the document limit.

Portable data resources require document version 3 so an older version-2 reader rejects the document instead of silently saving it without its bytes. Resource records carry stable IDs, canonical relative paths, media types and canonical base64 data inside the saved snapshot. Limits are 1,024 resources, 16 MiB decoded per resource and 64 MiB total; the enclosing JSON document is bounded at 128 MiB. Relative paths are identifiers, not permissions to read or write disk paths. Save As and HTML5 publication retain the embedded bytes; clipboard transfer preserves the resource closure and rejects conflicting paths before mutation. Binary data is shared across in-memory history snapshots. Authored PNG/JPEG placements use the bitmap profile below; portable font installation, broader media decoders and an external resource dependency/reimport graph remain separate work.

The **AS3 profile** accepts exactly one class or interface per unit. Supported syntax includes an optional package, exact/wildcard imports, same-package or qualified type resolution, access-controlled instance/static `var` and initialized `const` fields, declared methods, constructors, inheritance between project classes, project-method overrides and `super` calls. Constructors support the implemented positional-argument profile, with explicit first `super(...)` or implicit base initialization. Declared methods have stable bound identity, allowing the same method value to be registered and removed as an event listener. Project class fields use descriptors for defaults, const protection and supported type coercion, including qualified/aliased writes; this does not retroactively turn old handler `var` declarations into typed class slots.

Public instance/static `get`/`set` accessors use real property descriptors. Getters take no arguments; setters take one typed argument and return void. Paired property types must match, including inherited halves. A subclass can override one half while retaining the other, and instance `super.property` reads/writes select base accessors with the actual receiver. Missing getter/setter access throws an explicit write-only/read-only error; this bounded runtime check is not a complete static type checker. Interface units contain method/accessor signatures only, support multiple interface parents, and classes can implement several interfaces. Public inherited implementations satisfy exact parameter/return/property signatures. Interface types work in supported slots, arguments, returns and nominal casts; unrelated lookalike objects fail, and interfaces cannot construct or link as classes. AS2 uses the separate interface/accessor profile below; native-interface declarations remain unsupported. Syntax/signature rules follow the [AS3 statements reference](https://airsdk.dev/reference/actionscript/3.0/statements.html); no original-player differential conformance is claimed. The original `examples/interfaces-accessors.nflash` passes one ordinary-export/real-WASM/host scenario covering these components, input and Restart. Representative model updates, independent state and Restart also passed in the shared in-app-browser batch; exact scenario boundaries are in VERIFICATION.md.

AS3 exact imports for `flash.utils.getQualifiedClassName`, `getQualifiedSuperclassName`, `getDefinitionByName` and `describeType` provide bounded public source-class reflection. Lookup accepts dotted and `::` names from the current publication. `describeType` returns XML for ordinary project instances and class objects, including public inherited fields, methods and accessors, signatures and separate static/factory traits, without executing getters. Native-base, interface and rest-signature descriptions diagnose; full bytecode metadata and native traits are not inferred. Numeric class objects are identifiable; primitive numeric values cannot recover erased Number/int/uint identity and diagnose. Rust owns name, lookup, hierarchy and XML policy; the host supplies compiler metadata and live identities.

Ordinary AS3 source classes rooted in Object now have distinct class prototypes linked through their source-class base chain. Fresh instances inherit their own class prototype; its nonenumerable `constructor` points to that class, enabling ordinary `isPrototypeOf` checks and Class-valued construction. Explicit default `toString`/`toLocaleString` use Rust to produce short labels such as `[object Item]` and `[class Item]`. The default locale method is independent of a custom `toString`, while authored overrides remain callable. Prototype replacement, native-derived prototype chains, general prototype mutation and implicit `String(value)`/coercion parity are outside this profile.

The **AS2 profile** accepts one qualified class per matching logical source path, for example `class app.Widget` in `app/Widget.as`, exact/wildcard imports, same-package/qualified resolution, public/default/private instance/static variables and methods, and optional `dynamic`. Single inheritance stays within AS2; constructors support explicit or implicit `super()`, and methods can call `super.method(...)`. Annotations are erased, missing defaults are `undefined`, and scalar inline defaults live on the shared prototype. Instance writes shadow those defaults; create arrays, objects and computed values in the constructor. Declared methods are shared, writable and unbound: their `this` is the actual call receiver, and prototype replacement is visible to existing instances. Static state is shared until Restart. This is a distinct model from AS3 typed slots and bound methods.

AS2 concrete classes now support instance/static get/set accessors with dynamic receivers and inherited getter/setter halves; interface accessors remain unsupported. See the [AS2 class profile](AS2-LANGUAGE-BATCH.md) for details. AS2 source interfaces support method contracts, `implements` and single-parent interface inheritance; interface fields/accessors and multiple interface parents remain unsupported. See the [interface profile](AS2-INTERFACES-BATCH.md). AS2 symbol linkage attaches classes to authored instances. Using an AS2 `document_class` for the root is an explicit **NeoFlash extension**, not a historical Flash AS2 document-class claim. AS2 package blocks, `override`/`const`, protected/internal access declarations, interface accessors, default/rest parameters, non-scalar inline initializers, mixed-dialect imports/inheritance, class-as-function casts and unsupported `super` value extraction produce diagnostics. Complete prototype/reflection, type checking, construction/static initialization order and AVM1 coercion remain unfinished.

One class registry is created per publication and shared by handlers and linked instances. The host supplies an explicit built-in map; project code does not rely on replacing browser globals. Linked document/symbol classes attach once per active placement lifetime. The current host initializes linked descendants before their container so a document constructor can access initialized authored children. Static state belongs to the publication program and Restart creates a fresh program; full Flash initialization/re-entry order is not claimed. Ordinary project objects can be constructed. Native display classes initialize compatible authored objects; the bounded runtime allocation path also creates Sprite/Shape/MovieClip instances and project subclasses. Explicitly exported MovieClip symbols now supply scoped library timelines to the allocation path described below; their linked class must ultimately extend MovieClip.

Unresolved/duplicate/cyclic classes/interfaces, incompatible interface contracts and unsupported source constructs produce diagnostics. User-defined namespaces, built-in member overrides, complete lazy static dependency ordering and full VM type semantics remain pending. Native member redeclarations remain rejected rather than replacing host properties. Typed member assignment-expression results and owner-aware handling of every native member are not fully implemented. Complete AS2 prototype/reflection semantics and JS/TS project modules remain separate work. Project-aware member calls may resolve at runtime; accepting a call is not evidence that the corresponding Flash API exists.

The Actions workspace now includes a Sources mode for creating/importing/editing logical source files, selecting document/symbol linkage and checking the project. Changes participate in document history and save/open. AS2 and AS3 source units use their separate class profiles; JS/TS project-unit text is retained but produces an explicit compiler diagnostic, while its frame/object handlers continue to work. Check feedback is attached to the current source/handler and invalidated by relevant edits. **Native acceptance of this Sources UI is pending.**

AS3 `is`/`as` resolve Number, String, Boolean, int, uint, Function, Class, Object, Array, the selected Error family, project and native types, including parameterized Vector types. Core predicates do not coerce the operand; `as` preserves a matching value and otherwise returns null. `in` and member/index `delete` use the container reference bridge below. Rejected constructs include `instanceof` and class access-control namespace qualifiers. AS3 XML attribute/descendant/qualified selectors have the bounded E4X profile below. `new` accepts Array, Object, AS3 scalar Number/Boolean/int/uint/String, the selected Error family and, in a resolved project program, same-dialect project classes and supported native facades. Object calls/construction preserve existing objects; AS3 also preserves non-null primitives. AS2 primitive boxing remains diagnosed. `const` is accepted for AS3 class fields, not AS2 fields or general handler declarations. Calls accept the APIs below plus declared user values and explicitly defined function members. AS2 additionally resolves unqualified dynamic timeline calls at execution time. Missing/non-callable dynamic values fail explicitly; project-aware member calls have a wider runtime-resolution boundary than standalone handlers.

Selected AS3 defaults: `Number` starts as `NaN`, `int`/`uint` as `0`, `Boolean` as `false`, `String`/`Function` as `null`, and `*`/untyped as `undefined`. Bare-name primitive assignments use the annotation of the nearest lexical binding; integer casts wrap to 32 bits. Function-typed values accept functions or null/undefined (converted to null), otherwise they throw TypeError. New numeric Class values use Class bindings; existing callable Object/String facade compatibility is retained. This is a useful subset, **not** a complete AS3 type system. For example, writing `this.count` from another handler does not enforce a `count:int` declaration in the first handler.

At handler level, declarations without an initializer preserve an already defined instance field on subsequent invocations; an explicit initializer runs each time. Those instance defaults are established when the declaration executes, not by a complete Flash class/slot initialization pass. Function-local defaults are established at function entry; their initializers run at their source position, and a later uninitialized `var` does not reset an earlier assignment. JavaScript/TypeScript `var`/`let`/`const` retain ordinary JavaScript scope; use `this.counter` for shared handler state.

## Function and closure semantics

Scope analysis collects declarations before checking calls. Direct function declarations are available before their source position, enabling recursion and mutual recursion. Handler-level declarations are installed as fields on the owning timeline/object before the handler statements execute; nested declarations remain local. Their definitions are recreated when that handler executes again. Local parameters and `var` bindings shadow enclosing locals and instance fields, and closures retain their lexical bindings after the outer function returns. Unqualified instance names and timeline calls inside a function resolve against the owner captured when the handler ran, even if the closure is later invoked by another object.

Local bindings may shadow built-ins such as `trace`, `Number`, `play` or `Math`; compiler coercions use separately captured intrinsics. A shadowed `trace()` invokes the user's binding. Unknown methods on a shadowed Math value still require an explicit user function definition. At handler level, built-in names remain reserved. All declaration/parameter names beginning with `__nf` are reserved for compiler-generated bindings and produce a diagnostic. Named function-expression self bindings support recursion but cannot be reassigned.

AS3 handler-level declared functions and AS3 project methods retain their owning receiver when detached. AS2 project methods instead establish the owner from their actual call receiver, including inherited methods used as listener callbacks. Ordinary AS2/AS3 function expressions can use explicit dynamic `this`, but bare owner fields inside older handler closures still resolve through their captured timeline owner. These are separate supported boundaries, not a complete AVM1 scope-chain/global-receiver model.

AS3 function entry enforces the supported required/optional/rest signature and coerces annotated normal arguments. Optional defaults apply only to omitted positions; explicit undefined goes through the normal typed conversion. Rest collects extra supplied values into a fresh Array. Optional parameters must follow required parameters; rest must be last. This profile accepts literal scalar constants as defaults, with computed/default class-constant expressions left for a later frontend increment. Annotated returns are coerced once. A void/Void function cannot return a value. An explicitly typed AS3 non-void/non-`*` function must return a value or throw on every path the frontend can prove. A conservative completion analysis handles branches, switch fallthrough, loops, labels, catches and finally overrides; unproven normal fallthrough is a compilation diagnostic. It does not prove arbitrary infinite loops. Untyped/`*` functions may return undefined. AS2 parameter/return annotations are erased and omitted normal arguments remain undefined; extra arguments are available through its arguments array. AS2 default/rest syntax remains unsupported. Arguments use the supplied count: AS3 exposes converted supplied normal parameters plus raw extras, without appending omitted defaults; AS2 preserves supplied values. The implementation reference and exact accepted boundaries are recorded in ADR 0028.

`call` and `apply` route explicit receivers and argument lists through the same function body. AS3 bound methods retain their original owner; AS2 ordinary functions and methods can use the supplied receiver. Null/undefined receivers of unbound functions use the captured source frame when available, as an explicit NeoFlash convention. Without a captured frame, an explicit object receiver is required. This is not a complete AVM global-scope model. Native JavaScript globalThis is not substituted.

Reading arguments is semantically significant in this bounded profile: it allows extra supplied values. Adding an arguments-based trace can therefore change an excess-arity probe's contract; independent verification preserves the altered probe and corrected publication separately. Function.length counts normal declared parameters, including optional parameters and excluding rest. Calls accept at most 16,384 values. Arguments are a fresh Array with a nonenumerable callee; AS3 rest suppresses the arguments binding. Caller inspection, primitive receiver boxing, arbitrary array-like apply inputs, extracted native call/apply aliases and dynamic Function construction remain outside this profile. See [the function decision](decisions/0028-source-function-arguments.md).

Declared variables/parameters can be called as dynamic user values (known AS3 primitive bindings cannot); non-callable dynamic values fail at runtime. Standalone handler member calls outside the built-in API list require an explicit function declaration/assignment or a function-valued object-literal property at the same resolved receiver path. Project-aware AS2/AS3 compilation also permits member dispatch through the linked program and native facades. Literal-string computed calls use the same family routing as direct members; general dynamic computed calls and alias/type inference remain unsupported.

AS2 permits an unqualified call such as `run()` to find a function installed on its owning timeline by an earlier frame or parent script. It resolves against the captured timeline owner, checks that the value is callable, and preserves that owner for calls inside retained closures. A missing value reports the function name and originating script location. This does not add AVM1 prototype/scope-chain lookup or implement an otherwise absent Flash API. Method lookup precedes argument evaluation; callability checks follow argument evaluation. JavaScript call/receiver semantics remain the underlying subset, not a full AVM1 call implementation.

## Control flow and exceptions

`switch` evaluates its subject once and tests cases in source order until a match; case bodies can fall through without re-evaluating later tests. `do/while` runs its body before testing. Break and continue targets are validated separately, including switch inside loops. AS3 permits labels on statements and labelled continue to enclosing iteration statements; targets do not cross function boundaries. AS2 labels remain diagnosed pending source-compiler compatibility evidence.

`throw` requires a same-line expression. `try` accepts catch clauses, finally, or both. Finally runs for normal completion, returns, exceptions and loop/label jumps, and its own abrupt completion replaces the previous one. Return coercion occurs at the return site before finally. Lowering uses native structured statements, preserving control flow rather than placing user blocks in helper functions.

AS3 catch parameters have their own lexical environment. They can shadow outer locals, owner fields and built-ins; retained closures capture the particular catch binding. Function/frame `var` declarations retain their existing declaration owner. Catch matching is ordered and does not coerce values. Supported AS3 catch types are `*`/untyped, `Object`, `Function`, `Number`, `String`, `Boolean`, `int`, `uint`, and `Error`, `TypeError`, `RangeError`, `ReferenceError`, `SyntaxError`, `EvalError`, `URIError`, `ArgumentError`. Null and undefined match only catch-all. The current primitive predicates cover JavaScript primitive representations; boxed primitive objects, custom classes/interfaces and namespaces are outside this boundary. Unsupported catch types produce diagnostics. Subsequent bare-name writes use implemented primitive/Error type coercions; Object catch writes normalize undefined to null while preserving other values.

AS2 supports untyped catches and `catch(e:Error)`. Catch parameter names must be distinct from enclosing declarations and built-ins; outside-catch references to otherwise unresolved catch names and function definitions/expressions inside catches are diagnosed. These restrictions avoid inventing AVM1 variable/register collision and capture behavior. Other AS2 typed catches, including String, are not approximated with AS3 predicates: upstream AVM1 evidence distinguishes primitive strings from boxed String values.

Explicit AS2 throws travel in `{ [Symbol.for('neoflash.as2.thrown.v1')]: true, value: originalPayload }` envelopes, recognized across separately compiled handlers. A catch sees the original payload; rethrows preserve payload identity, while an unmatched catch propagates its envelope. AS2 catches do not swallow native JavaScript/host failures; finally still executes. AS3 throws raw values. JS/TS interoperability with these envelopes is an explicit boundary, not a sandbox or a claim of complete AVM1 runtime error behavior. General mixed-language catch conversion is not implemented.

`new Error(...)` is available in both languages; AS3 also accepts the listed core Error-family constructors. AS2 accepts at most one argument, AS3 at most two. These are a closed facade, not arbitrary constructor/class support. AS3 selected Error types also work in variable, argument and return annotations: null/undefined become null, matching Error-family objects preserve identity, and incompatible bare-name writes throw TypeError. AS2 Error annotations are erased. Constructor aliases/class values, getStackTrace, platform-specific subclasses and Flash runtime error numbers remain unsupported.

AS3 Error construction preserves the message value without immediate String coercion, converts the id to int once, and exposes read-only `errorID`; string conversion happens when the error is formatted, and toString applies the implemented nullable String return coercion even if name was reassigned. This follows [Adobe avmplus Error.as at the inspected revision](https://github.com/adobe/avmplus/blob/858d034a3bd3a54d9b70909386435cf4aec81d21/core/Error.as), whose untyped constructor differs from the published String signature. AS2 missing/undefined message defaults to `"Error"`; its toString returns the message, following [the inspected AVM1 implementation](https://github.com/ruffle-rs/ruffle/blob/fe6cfc545405b888ebb478ce1c211d63147ca49b/core/src/avm1/globals/Error.as). This facade does not reproduce prototype enumeration, all error properties or Flash stack traces.

Runtime error families generated by the browser/earlier compiler subset remain browser approximations. For example, current exact-argument-count checks throw TypeError, not a fully mapped AVM2 error/errorID. Catch support does not make every underlying JavaScript operation Flash-compatible. The host reports uncaught arbitrary values with guarded formatting and preserves their original cause.

## Host API contract

Frame handlers run with `this` bound to their owning timeline instance; object handlers run with `this` bound to the object. Named children and custom fields belong to that instance. The document identifies object events separately as `load`, `click` and `enter_frame`.

| --- | --- |
| `play()`, `stop()` | Call the bound timeline object's method and return `undefined`, rather than leaking the internal control-result Boolean. |
| `gotoAndPlay(frame)`, `gotoAndStop(frame)` | Frame numbers are one-based at the author API; internal model indices are zero-based. AS2 direct calls use the explicit label/numeric boundary below. JS/AS3 retain the existing strict host behavior. |
| `nextFrame()`, `prevFrame()` | Move to the bounded adjacent frame and stop; these and successful goto calls return `undefined`. |
| `trace(...)` | Calls the host-provided trace function, updating console output and player status. Captured outside nested function scopes; a function-local user binding named trace still shadows it. |
| Named children | `child.play()` and `parent.child._x` become instance property access; each instance has its own runtime state. |
| Legacy properties | `_x`, `_y`, `_rotation`, `_alpha`, `_xscale`, `_yscale`, `_visible`, `_name`, `_width`, `_height`, `_root`, `_parent`, `_currentframe`, `_totalframes` have bounded host adapters. `_alpha` and scale aliases use percentages; modern `alpha` and `scaleX/scaleY` use unit values. Visibility and geometry are described below. |
| Primitive globals | `parseInt`, String, Object, numeric constructors/conversions, AS2 Boolean omission and AS3 URI codecs have bounded profiles below. Other `Number`/`Boolean` calls, `parseFloat`, `isNaN`, `isFinite` retain JavaScript-backed behavior unless a documented conversion applies. |
| `Math` | `abs`, `acos`, `asin`, `atan`, `atan2`, `ceil`, `cos`, `exp`, `floor`, `log`, `max`, `min`, `pow`, `random`, `round`, `sin`, `sqrt`, `tan`. |
| Array/String families | Bounded constructors, mutation, sorting, primitive text processing and AS3 callbacks described below. AS3 `toFixed`/`toExponential`/`toPrecision` retain separate bounded adapters; AS2 exponential/precision methods are diagnosed. |

### Array and primitive String families

Array construction returns ordinary indexed arrays, including a single numeric length or multiple initial values. The adapter supplies `push`, `pop`, `shift`, `unshift`, `join`, `slice`, `concat`, `reverse`, `splice`, `toString`, `sort` and `sortOn`. Sorting accepts comparators and the Flash `CASEINSENSITIVE`, `DESCENDING`, `UNIQUESORT`, `RETURNINDEXEDARRAY` and `NUMERIC` flags. Indexed sorting leaves the receiver unchanged; unique sorting returns zero on a detected duplicate. AS3 also has `insertAt` and `removeAt` for ordinary mutable dense arrays: negative indices count from the end, insertion clamps to the array bounds, and out-of-range removal returns undefined. Index and growth policy execute in Rust; sparse arrays and exotic/frozen descriptors refuse before mutation. AS3 also has `map`, `filter`, `forEach`, `every`, `some`, `indexOf` and `lastIndexOf`; callbacks use an initial length snapshot, current values and `(value, index, array)` arguments. The AS2 search extension is not claimed as a native AS2 API. References: [AS2 Array](https://open-flash.github.io/mirrors/as2-language-reference/Array.html), [AS3 Array](https://airsdk.dev/reference/actionscript/3.0/Array.html).

AS3 `Array` has a shared Class identity across project code, frame/object handlers and public class lookup within one publication. A Class alias can call or construct the existing Array profile; the Array Class facade retains its publication identity across Restart. Reading the supported mutation, search, sorting, slice/concat/join and callback methods returns stable method values bound to that array, including `sortOn`, `insertAt` and `removeAt`. Calling a captured method through `call` or `apply` retains its array receiver. Member lookup evaluates a getter once, preserves authored function overrides and retains an already captured native method after the property is replaced. These method values reuse the existing algorithms and limits.

The Array profile is limited to 1,000,000 entries and ordinary data records. AS3 numeric sorting requires numbers; AS2 uses numeric comparison only for pairs of numeric values. `sortOn` supports equal-length per-field option arrays and, in AS2, plain stored fields. Historical comparison invocation/equal-key ordering, exotic length/index coercions, prototype augmentation and complete sparse-array behavior remain outside the profile. Public prototype `toString`/`toLocaleString` functions are not converted into bound Array method values. AS2 native method extraction retains its existing diagnostic boundary. No native JavaScript prototype is modified.

Primitive String supports conversion/class values, `fromCharCode`, character/code-unit access, search, slicing, `substr`/`substring`, splitting, concatenation, casing, `toString` and `valueOf`; AS3 adds literal-pattern `replace`, including a replacement callback. Bounds are 1,000,000 UTF-16 code units/results. Dialect adapters preserve the pinned differences for omitted arguments, integer positions, null search, zero code units and literal replacement text. AS3 `new String` produces a primitive; AS2 boxed String, constructor aliases under `new`, native method extraction, AS2 RegExp, custom pattern objects and prototype augmentation are unsupported. AS3 localeCompare/toLocaleLowerCase/toLocaleUpperCase now have a bounded Rust profile without OS locale collation. AS3 constructor-based RegExp operations are described below. Historical UTF-16 casing, primitive String calculations and literal replacement now run in Rust; JavaScript retains host object conversion and the pre-existing RegExp backend. AS2 extra arguments are evaluated then ignored; unsupported AS3 excess-argument forms diagnose without asserting a Flash error code. References: [AS2 String](https://open-flash.github.io/mirrors/as2-language-reference/String.html), [AS3 String](https://airsdk.dev/reference/actionscript/3.0/String.html).

The exact selected behavior, pinned Ruffle/Adobe source links and deliberate limits are recorded in `collections-fixtures.mjs` and `strings-fixtures.mjs` under `crates/neoflash-script/tests/`. Expectations are **documented_only**, not original-player measurements. The same embedded adapters serve handlers and project methods. `examples/collections-text.nflash` connects row parsing, leaderboard processing and authored text output. Its two pipelines, colored output and Restart were observed in the in-app browser; see VERIFICATION.md for the bounded acceptance record.

### Typed Vector, Dictionary and enumeration

AS3 supports `Vector.<T>` annotations, construction and explicit conversion. Standalone handlers accept primitive/Object/Array/Function/*, Date, RegExp, supported Error and nested Vector elements; project context additionally resolves imported native types, project classes/interfaces and qualified names. Typed slots use nullable nominal casts, distinct from explicit Vector conversion; covariance, bare Vector and void elements are unsupported. Dense storage, default elements, bounds, `length`/`fixed`, invariant type checks, indexed mutation and common mutation/search/slice/sort/callback methods share one adapter across handlers and project methods. Type identity uses actual type tokens, not qualified-name strings. Numeric positions/lengths and Boolean fixed flags have explicit bounded requirements; one Vector holds at most 1,000,000 elements. Structural mutation inside callbacks, reentrant mutation during coercion/sort, RETURNINDEXEDARRAY, subclassing and prototype extension diagnose. Full historical coercion, comparison order and native error IDs are not claimed.

Exact `flash.utils.Dictionary` imports in project-aware compilation provide object/function keys by identity, including display proxies. Standalone compilation has no import resolver. Primitive keys use property-name conversion: `1`/`"1"`, `NaN`/`"NaN"`, null/`"null"` and undefined/`"undefined"` share primitive slots. Canonical unsigned property names below 2^28 enumerate as numeric keys. Weak mode uses WeakMap values and WeakRef enumeration keys, with no strong fallback; collection timing is nondeterministic. The adapter bounds live entry records to 100,000 and primitive key text to 1,000,000 UTF-16 units. Dictionary defaults to a toJSON label; authors can override it or project entries into a report. Custom property descriptors, prototype replacement and sealing the representation are unsupported.

AS3 `hasOwnProperty`, `propertyIsEnumerable` and `setPropertyIsEnumerable` share Rust descriptor policy for plain records and ordinary project objects. Fixed public instance traits remain owned but nonenumerable; class objects expose their declared public static traits. Dynamic properties can be hidden and restored without losing their values or membership. Authored method overrides remain intact. Native/display hidden storage and complete prototype/namespace reflection remain unsupported.

Both languages support `for..in` over the bounded ordinary record/Array/project-object profile; AS3 adds `for each..in` values and typed Vector/Dictionary enumeration. Keys are snapshotted, later insertions are ignored, deleted entries are skipped and values are read when visited. Fixed AS3 traits are excluded from ordinary property enumeration and cannot be deleted. Native display objects can be Dictionary keys, but hidden native/display storage cannot itself be enumerated. General AVM iteration order and full captured AVM1 scope chains remain separate work. AS2 object-target `with` is supported within the bounded [language profile](AS2-LANGUAGE-BATCH.md). XML/XMLList has its own bounded enumeration profile below; wider E4X remains pending.

Computed reads, writes, compound updates, `in` and member/index `delete` retain the original key until the adapter selects the container. Bare-identifier deletion and general dynamic computed method calls remain diagnosed. Receivers and keys are evaluated once; assignment expressions return the original RHS after slot coercion. This does not globally complete older handler-field coercion or every native property contract. Vector JSON uses the existing array traversal and registered public model fields/getters. [typed-collections.nflash](../examples/typed-collections.nflash) combines parsed records, typed models, identity-keyed linked cards, enumeration, card reuse and JSON with an independent AS2 record loop. Verification is recorded separately in [VERIFICATION.md](VERIFICATION.md); original Flash comparison and independent per-declaration audit are not implied by the source implementation. See [the decision](decisions/0019-typed-collections-and-enumeration.md) for pinned references.

### TextField, TextFormat and uniform layout

AS3 `new TextField()` and AS2 `MovieClip.createTextField(name, getNextHighestDepth(), x, y, width, height)` create dynamic plain-text display objects in the shared Rust graph. AS2 depth is append-only. Text fields have a logical width/height box, `multiline` and `wordWrap`; resizing a box reflows its text while its display transform remains independent. Existing authored Text keeps its unboxed layout unless explicitly given a box. New dynamic fields start at 100 × 100 with Times New Roman, size 12, black, left alignment and wrapping/multiline disabled. Native text subclass initialization is unsupported; use composition. The native editor creates wrapped multiline TextBox elements with the Text tool, converts legacy Text explicitly, and edits box dimensions, font/style/color, leading and alignment using the same Rust layout. Live native acceptance remains pending.

AS3 imports `flash.text.TextFormat` and `TextFormatAlign`; AS2 uses the captured global `TextFormat`. Uniform formatting supports font family, size, RGB color, bold, italic, leading and left/center/right alignment. Nullable format properties preserve the existing value. `getTextFormat` and `defaultTextFormat` return copies, and `setTextFormat` changes the current whole-field format. Insertion defaults remain separate; AS2 exposes `getNewTextFormat`/`setNewTextFormat`. Assigning `text` applies the default format. Appending or partially replacing nonempty text when the insertion default differs from the current format fails before mutation because mixed character runs are not implemented. Partial formatting ranges also fail explicitly. References: [AS3 TextField](https://airsdk.dev/reference/actionscript/3.0/flash/text/TextField.html), [AS3 TextFormat](https://airsdk.dev/reference/actionscript/3.0/flash/text/TextFormat.html), [AS2 TextField](https://open-flash.github.io/mirrors/as2-language-reference/TextField.html).

Live `text`, `textColor`, UTF-16 `length`, `appendText`, `replaceText`, `numLines`, line text/length/offset/index and `textWidth`/`textHeight` share the same runtime state. Public text uses carriage-return separators; renderer storage uses line feeds. Text must be a string of at most 1 MiB UTF-8, and replacement ranges must preserve complete Unicode characters. Rust owns wrapping, line source ranges and alignment; browser/native frontends supply measured glyph widths. Boxed text uses two-unit padding and a line advance of `1.2 × size + leading`; wrapping requires multiline mode, and single-line hard breaks render as spaces. Long tokens break at Unicode scalar boundaries, not complete grapheme clusters. Bounds are 16,384 layout segments/lines, 65,536 fallback glyphs, 1,024 UTF-8 bytes per font family, size through 10,000, leading within ±10,000 with positive line advance, and box dimensions through 1,000,000. Runtime text override storage is bounded at 16 MiB. Metrics depend on installed fonts and this bounded layout algorithm, not Flash font-engine parity. Authored content remains unchanged by runtime edits; placement retirement and Restart discard runtime overrides.

Full IME conformance, embedded fonts, rich mixed-format runs and complete Flash text metrics remain pending. AS2 has separate partial [styled HTML/CSS](AS2-TEXT-DISPLAY-TWO-HOUR.md) and [auto-sizing/paragraph layout](AS2-DISPLAY-FILTERS-BATCH.md) profiles; these do not establish general rich-text support or AS3 parity. The later text-input profile below adds scripted input and selection with its own evidence. Unsupported known members diagnose instead of storing misleading custom values. `examples/text-layout.nflash` is one combined AS3/AS2 workflow with independent text cards and a grouped button that cycles width/alignment. Its ordinary-export/real-WASM scenario passes creation, reflow, independent current/default formats, shared line queries, Canvas draw/clip consumption, atomic mixed-run refusal and Restart. Canvas observation uses deterministic injected measurements and does not establish browser rasterization parity. The in-app-browser workflow visibly passed reflow/alignment, independent fields and Restart; native interactive editing remains pending, and the earlier collection/plain-text workflow retains its separate bounded acceptance record.

### MovieClip and DisplayObject family

The host exposes lifetime-checked identity and hierarchy: `name`/`_name`, `root`, `parent`, `stage`, `numChildren`, `getChildAt`, `getChildByName`, `getChildIndex` and `contains`. Renaming updates name lookup in the shared runtime. The authored root's modern parent is the Stage singleton; legacy root `_parent` remains null. Child traversal includes the supported authored containers and runtime-created objects described below. General historical depth semantics remain incomplete; bounded linked `attachMovie` is described below, with additional AS2 depth operations in the [depth profile](AS2-DEPTH-MANAGER-BATCH.md).

AS3 MovieClip metadata reads from the shared Rust timeline for the root, authored nested clips, linked instances and empty runtime clips. `currentLabel` returns the nearest preceding label; `currentFrameLabel` returns a label only on its exact frame, otherwise null. `currentLabels` returns a fresh array of typed `FrameLabel` values with read-only `name` and one-based `frame`. `new FrameLabel(name, frame)` accepts a primitive String and signed 32-bit integer and supplies the existing EventDispatcher interface. `framesLoaded` equals the total frame count of fully local content. `isPlaying` records explicit play/gotoAndPlay versus stop/gotoAndStop state on multiframe clips; initial autoplay and one-frame clips report false. Pausing the global preview does not change that per-clip state. Retired display references reject metadata reads. The seven AS3 metadata names remain ordinary stored properties when accessed from AS2 code; AS3 reads retain their native read-only meaning on the same object.

`currentScene` and `scenes` expose one unnamed Scene snapshot for each local clip, with `name == ""`, `numFrames` equal to the clip's total and typed `labels`. Each MovieClip read returns fresh Scene values and arrays. A particular Scene retains its mutable labels array; editing it does not change later timeline reads. Scene fields are read-only and direct Scene construction is unsupported. This profile does not add authored multiple scenes, scene navigation, streaming progress, automatic `frameLabel` events, `FRAME_CONSTRUCTED`/`EXIT_FRAME` phases or full Flash construction/frame-script ordering. The existing linked MovieClip example presents these metadata values alongside its playback controls; validation boundaries are recorded separately.

With `buttonMode = true`, a local MovieClip can use `_up`, `_over` and `_down` labels for automatic pointer states. Rust selects the corresponding frame and stops the clip; missing labels leave its frame unchanged. `enabled` defaults to true. Setting it false suspends these automatic state changes while ordinary mouse/key event delivery remains active; `mouseEnabled` remains a separate input setting. Input listeners currently run before the automatic transition and its queued frame scripts; complete Flash event ordering is not established. This does not implement automatic tab ordering, keyboard button activation or `trackAsMenu`. See [MovieClip.enabled](https://help.adobe.com/en_US/FlashPlatform/reference/actionscript/3/flash/display/MovieClip.html#enabled) and [Sprite.buttonMode](https://help.adobe.com/en_US/FlashPlatform/reference/actionscript/3/flash/display/Sprite.html#buttonMode).

`getBounds`/`getRect`, `width`/`height` and legacy dimension aliases use the current nested geometry, including transforms and hidden objects; `getRect` excludes strokes. `localToGlobal` and `globalToLocal` use affine coordinates and reject noninvertible conversions. Display results use the same Point/Rectangle constructors as the imported finite geometry family below, preserving typed assignment identity. Dimension setters scale supported nonrotated geometry and can recover from a zero scale; rotated dimension writes fail explicitly instead of guessing Flash resizing. Text bounds use the existing Canvas font measurement and line layout, so platform font differences remain.

Finite rotation readback is normalized by complete turns into the signed -180 to 180 range, retaining the two endpoints. Numeric assignment/update expressions preserve their expression results rather than rereading the normalized property: assigning 450 yields expression 450 and getter 90. Authored tween angles are not globally normalized. Complete AVM1 object/nonfinite conversion and rotation/matrix conformance remain pending. The finite range and void method signatures have primary reference evidence; they are not an original-player differential result. See [AS2 MovieClip](https://open-flash.github.io/mirrors/as2-language-reference/MovieClip.html#_rotation) and [AS3 DisplayObject](https://airsdk.dev/reference/actionscript/3.0/flash/display/DisplayObject.html#rotation).

Recognized AS2 assignments to `onEnterFrame` and `onPress` register host callbacks on compatible MovieClip/Button instances; null/undefined clears them. Linked AS2 classes also expose inherited prototype callbacks; runtime lookup observes prototype replacement, and an own null value suppresses the inherited callback. The callback bridge retains receiver/lifetime identity and prunes retired placements. Supported source `on`/`onClipEvent` wrappers register the corresponding callbacks; imported `on(release)` runs its registration on placement Load. Other event names diagnose. This does not implement all historical event properties or event ordering. The current tick order runs registered callbacks and event broadcasts before advancing the shared timeline and draining the resulting authored frame scripts; this is a bounded NeoFlash schedule, not a complete Flash construction-order claim.

Authored Button symbols retain Up, Over, Down and Hit at frames 0–3. They stay in Up until pointer state changes; the Hit frame supplies separate invisible input geometry and does not advance as an independent MovieClip. Blank visible states remain interactive through Hit geometry. This bounded authored-button profile does not implement the complete AS3 `SimpleButton` API. Native button-state UI acceptance is pending.

### Runtime display objects and drawing

AS3 `new Sprite()`, `new Shape()` and `new MovieClip()` allocate stable runtime identities in the shared Rust/WASM graph. Project subclasses use the same native allocation path. Containers support addChild/addChildAt, removeChild/removeChildAt/removeChildren, setChildIndex and swaps across authored, linked and runtime children. A runtime hierarchy overlay allows these children to interleave without editing their authored source addresses. Reparenting keeps local transforms, references, fields and listeners; current ancestry drives rendering, bounds, child lookup and event routes. Detached objects retain their state and can be added again while their original source placement remains live. Source removal/replacement still retires an authored object even after it was moved; independent surviving children detach rather than transferring to the replacement. New source placements have new identities. Authored layer-mask migration remains explicitly unsupported. Root/Loader ownership, cycles, index ranges and depth/event budgets are validated before mutation.

`removeChildren(beginIndex = 0, endIndex = 0x7fffffff)` removes an inclusive mixed-child range; the default maximum means through the last child. The entire selection is preflighted, then detached atomically before removal events are delivered; native per-child reentrant callback timing is not implemented. `stopAllMovieClips()` stops the receiver and its current subtree of independent local MovieClip timelines, including linked/nested clocks and detached receiver subtrees. It does not stop media streams; explicit play/gotoAndPlay can resume clips. Unlinked runtime MovieClips are empty one-frame containers. Limits include 4,096 runtime-created objects, counting detached objects, and 64 levels of nesting. Restart invalidates the old graph.

A non-root MovieClip symbol can declare an explicit unique `linkage_id`. AS3 construction of its linked MovieClip project class allocates an independent copy of that authored timeline; AS2 `attachMovie` resolves the exact export identifier. Each copy has a separate namespace, nested clocks, state and script identities while sharing immutable authored content. Linked classes initialize once per live placement, and the host prepares linked descendants before the container constructor. The reserved linked-node budget is 100,000; class/native-base mismatches and missing/ambiguous exports diagnose. Copy/paste captures the explicit-export symbol closure because runtime references need not appear in an authored placement. The original `examples/linked-movieclips.nflash` passes the combined ordinary-export/real-WASM host scenario. Representative pointer/keyboard/semantic activation and Restart also passed in the shared in-app-browser batch. Full Flash construction order remains unverified; VERIFICATION.md records the exact acceptance.

Runtime-created Sprite/Shape/MovieClip graphics support solid and linear/radial gradient fills and strokes, move/line/quadratic/cubic paths, rectangles, ellipses/circles, rounded rectangles, drawPath and clear. Per-corner drawRoundRectComplex is a NeoFlash convenience extension, not an Adobe Flash Graphics API; its radii must be nonnegative and fit without overlap. Graphics.copyFrom makes an independent drawing-state copy. An exact AS3 Graphics import can type the owner-supplied facade; direct Graphics construction and inheritance reject. Drawing uses the shared Rust scene, bounds and hit targets. Graphics commands do not edit the authored document. Coordinates must be finite, colors are RGB integers, alpha is in `0..1`, and positive stroke thickness is bounded at 255. Hairlines, other cap/join modes, bitmap fills and drawing into authored owners are pending; vector display masks and the separate runtime display-filter profile are described below. The runtime bounds retained graphics storage to 100,000 commands/runs and a submitted operation batch to 4,096 operations.

Gradients accept one through fifteen ordered stops, finite invertible Matrix values, linear/radial type, pad spreading and RGB interpolation. Finite AS3 alpha values clamp to 0..1 and finite focal ratios clamp to -1..1. Endpoint radial focal cones leave their exterior transparent; unsupported spreading/interpolation modes diagnose. The input arrays and Matrix are copied. Parent ColorTransform values transform the stored RGBA stops when the scene is produced. Stroke gradients require an active positive-width lineStyle. GradientType, SpreadMethod, InterpolationMethod, GraphicsPathCommand and GraphicsPathWinding imports expose their documented constants; unsupported mode constants still diagnose when used. The drawPath profile accepts dense arrays or typed Vectors with move/line/quadratic/cubic/wide move/wide line commands and either winding rule; mismatched data rejects before changing geometry. Canvas gradient strokes use one reusable offscreen mask capped at 16,777,216 pixels, released on Restart/failure/page exit. Oversized masks diagnose before allocation. Pointer picking uses gradient alpha and exact Path2D geometry; semantic bounds are conservative geometric bounds clipped to nonzero paint regions. Native gradient authoring and exact historical rasterization remain unverified. See [ADR 0022](decisions/0022-runtime-gradient-graphics.md).

AS2 runtime MovieClips expose direct beginFill/endFill/beginGradientFill/lineGradientStyle/lineStyle/moveTo/lineTo/curveTo/clear with percentage alpha. Gradient matrices currently require a native flash.geom.Matrix; historical box/3×3 matrix objects diagnose. RGB/rgb spellings select the same implemented interpolation profile. createEmptyMovieClip and attachMovie accept only the append depth returned by getNextHighestDepth; removeMovieClip detaches a runtime clip. attachMovie optionally copies at most 1,024 enumerable own data properties from an initObject before linked construction; accessor properties reject. This is not full historical depth/replacement or initialization behavior. Runtime add/remove/reparent notifications retain the captured ancestor route for EventDispatcher propagation; retired receivers remain guarded. Complete Flash construction/lifecycle order remains outside the profile. The original `examples/dynamic-display.nflash` now combines gradients, copied paint and path construction with pointer/keyboard/lifecycle and Restart. Delivery evidence remains in VERIFICATION.md; the earlier independent solid-drawing audit does not automatically accept gradient declarations.

### Vector masks and scroll rectangles

AS3 DisplayObject.mask and AS2 MovieClip.setMask assign a live vector source to a target. Filled components form a union, including compound holes and zero-alpha fills; stroke, paint color and alpha do not affect this uncached mask geometry. Consumed sources are omitted from ordinary drawing and input. Single-owner reuse clears the former target. Dynamic vector sources and supported static vector subtrees are available; bitmap/text mask sources, alpha-mask/cacheAsBitmap behavior and multi-frame authored mask timelines remain pending. Cycles, mask-of-mask sources, overlapping source subtrees and scrollRect inside a source diagnose. Source/target lifetime and graph mutation validation stay in Rust. The profile caps active mask/scroll entries at 256, inherited chains at 32 and authored mask geometry at 100,000 reserved commands alongside the existing dynamic Graphics budget.

scrollRect is a copied native Rectangle or null. Its initial profile requires integral coordinates/sizes within ±1e9 and nonnegative dimensions; fractional inputs diagnose. Changes apply immediately. Content coordinates include the negative scroll origin while the base Transform.matrix stays unchanged; getBounds/width/height reflect the viewport. Ancestor viewport and mask clips intersect. AS3/JavaScript absence is null; AS2 native bare/member/computed reads produce undefined, without rewriting ordinary user fields. AS2 setMask returns true for successful object/null assignment, false for unresolved nonnative objects and undefined for no arguments; String target paths remain unsupported. These are bounded documented profiles, not full historical rounding, frame timing or AVM behavior.

Canvas clipping shares Path2D curves with pointer tests. Two reusable surfaces are each capped at 16,777,216 pixels; semantic readback is limited to 16,777,216 pixels per frame in tiles of at most 262,144 pixels. Nonsemantic clipped draws skip readback. The semantic layer consumes visible bounds of the already clipped artwork; oversized buffers/readback diagnose. Native mask/scroll authoring and original Flash raster fidelity remain unfinished. See [ADR 0023](decisions/0023-runtime-masks-and-scroll-rectangles.md) and the delivery-specific verification record.

### Stage, EventDispatcher and input family

`web/events.js` supplies Event, MouseEvent, KeyboardEvent, EventPhase and EventDispatcher facades. The same hub powers display-instance and Stage `addEventListener`, `removeEventListener`, `hasEventListener`, `willTrigger` and `dispatchEvent`. It supports capture/target/bubble phases, priority with stable equal-priority order, target/currentTarget, propagation stops, cancelable default prevention and Boolean dispatch results. Redispatch clones the event. A listener phase uses a snapshot: removals still run in that snapshot, while additions may participate in a later phase. This follows the documented [EventDispatcher mutation contract](https://airsdk.dev/reference/actionscript/3.0/flash/events/EventDispatcher.html#addEventListener()). Work/depth limits bound recursion; listener exceptions retain their original failure for host reporting.

Subscriptions belong to active object identities, not reusable path strings. Replacement placements do not inherit old listeners; Restart clears the host subscriptions. Generic `new EventDispatcher()` is supported; aggregation through its optional target argument is explicitly rejected. Weak subscriptions use browser WeakRef where available, without a claim that browser and Flash garbage collection are identical. Custom event types can be dispatched manually. Exposing event constants does not imply automatic ADDED/REMOVED, frame-construction or every other Flash lifecycle event.

`web/stage.js` provides one sealed Stage with logical `stageWidth`/`stageHeight`, transient `frameRate`, mouse coordinates and focus. Pointer input supplies mouse down/up/move/click/wheel and basic over/out events; keyboard input is delivered to the current live focus and can bubble to Stage. Event data includes the implemented coordinates, key codes and modifiers. Input can cancel browser default behavior. Editable DOM controls and IME composition are not hijacked. Authored Click handlers remain on their existing dispatch route; registering an EventDispatcher listener does not create a second authored Click execution.

The ordinary fitted export keeps fixed logical stage dimensions. The adapter can dispatch RESIZE when the host changes those dimensions, but preview zoom/window resizing does not currently establish Flash `noScale` behavior. Fullscreen, scale/alignment modes, IME composition events, touch gestures, Stage3D, exact legacy key/mouse rules and full focus behavior remain pending. Event `ENTER_FRAME` is a host broadcast, separate from the existing authored EnterFrame handlers. AS3 imports resolve these facades through the program registry; JS/TS can use `NeoFlashEvents` constructors without replacing browser-native Event globals. The separate AS2 adapter below exposes its own captured singleton bindings.

Original family examples are `examples/display-family.nflash`, `examples/events-stage.nflash` and `examples/project-program.nflash`. Current automated evidence and the bounded shared browser acceptance record are in [VERIFICATION.md](VERIFICATION.md).

### AS2 Key, Mouse and Stage

`web/legacy-input.js` exposes `Key.isDown/getCode/getAscii`, common key constants and listener registration/removal; `Mouse` listeners for down/up/move/wheel plus `hide/show`; and read-only logical `Stage.width/height` with resize listeners. The compiler captures these singletons through a hidden host binding; local names can shadow them without changing the host. Listener methods run on their listener object. Registration is idempotent, `addListener` returns undefined and `removeListener` returns a Boolean. Broadcasts snapshot the listener list; additions/removals affect later broadcasts, retired display proxies are pruned, and reset/disposal cancels the old snapshot. ### Geometry and Timer

Exact project imports expose `flash.geom.Point`, `Rectangle` and `Matrix` to both AS2 and AS3 through the shared `web/geom.js` facade. The profile includes point arithmetic, distance/interpolation, rectangle edges/containment/intersection/union, and affine matrix construction, composition, point transformation and inversion. Coordinate fields and results must be finite numbers; overflow, nonfinite values and singular inversion diagnose. Matrix angles are radians, and `concat(other)` applies the receiver followed by `other`. Point, Rectangle and Matrix in this geometry profile are detached values. Display matrix assignment and ColorTransform are supported by the separate bounded [runtime Transform profile](#runtime-transform-and-colortransform), with its own [independent acceptance and AS2 rgb limitation](VERIFICATION.md#independent-transform-verification-of-852c8b7). Vector3D/Matrix3D have the separately bounded Rust value profile from the reuse experiment. Complete historical coercion/native-slot behavior remains outside these profiles. See the wider [Point](https://airsdk.dev/reference/actionscript/3.0/flash/geom/Point.html), [Rectangle](https://airsdk.dev/reference/actionscript/3.0/flash/geom/Rectangle.html) and [Matrix](https://airsdk.dev/reference/actionscript/3.0/flash/geom/Matrix.html) contracts; implementation references are recorded in the module.

AS3 imports `flash.utils.Timer`, `flash.events.TimerEvent` and `flash.utils.getTimer`. Timer supports start/stop/reset, delay, repeatCount, currentCount/running and the shared listener methods; each tick dispatches TIMER before a finite run dispatches TIMER_COMPLETE. TimerEvent supplies clone and a host-backed updateAfterEvent render request. The AS2 bare `getTimer()` global uses the same session clock; Timer/TimerEvent are AS3-only. Publication Restart cancels scheduled work and listeners, invalidates old Timer instances and resets elapsed time. A timer's own reset stops it and clears its count. Completed finite timers require reset before another run.

Delays must be finite numbers in `0..2147483647` milliseconds, with a 1 ms scheduling floor; repeat counts are integers in that range, with zero meaning repeated ticks. At most 1,024 timers run concurrently by default. A delayed browser wake produces one tick; browser throttling applies, and no historical Flash timing/catch-up or garbage-collection equivalence is claimed. `getTimer()` returns signed 32-bit elapsed session milliseconds. AS2 global and AS3 flash.utils setInterval/setTimeout/clearInterval/clearTimeout now share the Timer scheduler and a Rust ID registry; AS2 also accepts object/method callbacks. Complete native inheritance/coercion/error-code behavior remains pending. See [Timer](https://airsdk.dev/reference/actionscript/3.0/flash/utils/Timer.html), [TimerEvent](https://airsdk.dev/reference/actionscript/3.0/flash/events/TimerEvent.html) and [getTimer](https://airsdk.dev/reference/actionscript/3.0/flash/utils/package.html#getTimer()).

The original `examples/geometry-timer.nflash` combines a typed Matrix/Point path, display bounds/local-to-global results, four Timer ticks, live text and completion. It is the shared family scenario for ordinary export and Restart. The combined ordinary-export/WASM scenario and two real-browser runs separated by Restart passed; this is bounded workflow evidence, not complete Flash conformance.

### Binary buffers

AS3 project-aware compilation accepts exact `flash.utils.ByteArray` and `flash.utils.Endian` imports. A new ByteArray has independent indexed storage, length/position/bytesAvailable, byte order, Boolean/integer/IEEE floating-point reads and writes, UTF/UTFBytes, byte copying and clear. Integer writes retain their low bits; numeric indexing does not move the cursor. Extending length or writing beyond the end fills the gap with zeros. Transfers preserve the other buffer's cursor; overlapping writeBytes uses snapshot behavior. Errors from invalid sizes, overruns, allocation limits and UTF validation preserve contents and cursors.

Each publication owns a bounded service: defaults are 16 MiB per buffer, 64 MiB combined backing capacity and 4,096 initialized arrays. Clear releases an array's backing storage; instance accounting remains until publication reset/disposal. Restart releases storage and invalidates old buffers. Size/index arguments require nonnegative integers; binary values require primitive numbers/Booleans/strings. UTF supports valid UTF-8 and rejects malformed sequences or unpaired UTF-16 inputs. UTF reads remove an initial UTF-8 BOM and stop the result at NUL while consuming the requested bytes. writeUTF has a 65,535-byte encoded payload limit. This is a documented bounded profile, not a complete AS coercion, EOFError/errorID or original-player claim.

Rust zlib/DEFLATE compression, multibyte text and Base64/hex codecs have the bounded profile in RUNTIME-BINARY-PROVENANCE.md. LZMA, shared workers and indexed enumeration explicitly reject. AMF object records and objectEncoding use the shared codec profile below. Out-of-source writeBytes ranges reject rather than silently clamp; readBytes into the same buffer is unsupported. The compiler rejects ByteArray native subclass initialization, Endian construction/inheritance and ByteArray constructor arguments. ByteArray/Endian are not added to AS2. See [ByteArray](https://airsdk.dev/reference/actionscript/3.0/flash/utils/ByteArray.html) and [Endian](https://airsdk.dev/reference/actionscript/3.0/flash/utils/Endian.html); pinned implementation references and remaining boundaries are recorded in `web/byte-array.js`.

The original `examples/binary-data.nflash` serializes a 50-byte numeric/UTF packet, copies it through independent buffers and displays the decoded result in live text. One combined scenario in the existing project executor passes ordinary export, actual WASM/host, typed buffer identity, atomic failures, live text, Restart and disposal. The ordinary browser packet/text workflow and Restart passed.

### Bitmap pixels and authored images

Version-3 authored bitmap placements reference an embedded PNG/JPEG resource ID, verified intrinsic dimensions and a smoothing preference. PNG/JPEG decoding belongs to the shared Rust model; unsupported formats and mismatched intrinsic sizes reject. Runtime pixels live in a bounded Rust arena shared by the native/WASM paths. The browser uploads revision-stamped RGBA copies for drawing and alpha hit tests; it does not maintain a second editable pixel model. Saved resource bytes remain immutable when a publication mutates BitmapData. Authored placements of the same image resource share one transparent-capable buffer per publication; clone before editing when independent runtime pixels are needed.

Image dimensions are bounded to 1–4,096 pixels per side. The publication arena holds at most 256 buffer records and 128 MiB of live pixels; disposal releases pixel storage, while its record remains until Restart. Shared image decoding uses a 64 MiB cache. Native image placement fits imported PNG/JPEG artwork to the stage and retains intrinsic size plus smoothing; native UI acceptance is pending. Other resource formats remain stored bytes without an image-placement decoder. Pixels use premultiplied RGBA8 internally and straight RGBA for upload; complete historical rounding and color-management equivalence is not claimed.

AS3 imports Bitmap, BitmapData and the nonconstructible PixelSnapping constants. Bitmap views can share or replace bitmapData, choose smoothing and use auto/always/never pixel snapping in Canvas drawing-buffer coordinates. BitmapData supports construction, width/height/transparent/rect, getPixel/getPixel32, setPixel/setPixel32, fillRect, copyPixels, clone, scroll and dispose. Pixel operations require integer coordinates and unsigned ARGB colors. setPixel preserves alpha; opaque buffers ignore input alpha. copyPixels clips and supports source-over mergeAlpha, including overlapping source/destination storage; separate alpha-mask arguments reject. scroll leaves the newly exposed edge unchanged. Clones own independent pixels; disposing a displayed buffer removes its paint, and Restart invalidates old session buffers.

AS2 imports flash.display.BitmapData, including the rectangle alias, and attaches pixels to a MovieClip through attachBitmap at the append depth returned by getNextHighestDepth. AS2 uses the shared diagnostic/error profile rather than reproducing historical invalid-object sentinel returns. Bitmap and BitmapData native subclasses are explicitly gated. BitmapData.loadBitmap linkage, drawWithQuality, shaders, bitmap fills, alpha-mask copyPixels, lock/unlock and the rest of the wider BitmapData API remain unsupported. The image pipeline below adds a bounded draw/filter/PNG profile. Neither integer-only adapters nor Canvas snapping establish complete Flash coercion, error-code or rasterization parity. The documented surfaces are [AS3 BitmapData](https://airsdk.dev/reference/actionscript/3.0/flash/display/BitmapData.html), [Bitmap](https://airsdk.dev/reference/actionscript/3.0/flash/display/Bitmap.html) and [AS2 BitmapData](https://open-flash.github.io/mirrors/as2-language-reference/flash/display/BitmapData.html).

The original `examples/bitmap-pixels.nflash` contains a programmatically authored 16×16 PNG, an editable image placement, two shared views, an independent scroll/copy clone and AS2 attachment. Its combined ordinary-export/real-WASM scenario passes shared/independent pixel state, AS2 attachment, actual RGBA transfer, Canvas upload reuse/refresh, smoothing/snapping, disposal and Restart. The Paint control groups its label and artwork in one authored Button symbol. The in-app-browser workflow visibly passed shared edits, source/clone independence, AS2 attachment and Restart. Native image-panel interaction remains pending; the exact bounded observations are in VERIFICATION.md.

The image pipeline adds colorTransform, applyFilter and generateFilterRect for the shared Blur/Glow/DropShadow/ColorMatrix specifications. Source pixels are snapshotted for overlapping filter operations; neighboring source samples outside sourceRect can contribute. AS2 applyFilter returns 0 on success, while AS3 returns void. Exact historical filter kernels, rounding and sentinel/error behavior remain outside the profile.

AS3 getPixels returns clipped row-major ARGB in a new big-endian ByteArray positioned at its end. copyPixelsToByteArray writes at the supplied position using that buffer's endian; setPixels reads complete words with the input endian. On underrun, already written pixels and their consumed cursor remain, followed by an EOFError-named Error; incomplete trailing words are not consumed. This is a partial write, not a rollback. ByteArray's existing size limits remain in force. PNGEncoderOptions selects fast/default PNG compression; encode returns a new buffer at position 0 or writes into the supplied buffer at its current position and advances it. The latter PNG cursor convention is explicit; no original-player encode differential is claimed. JPEG/JPEG-XR encoders remain unsupported.

BitmapData.draw accepts BitmapData or a live DisplayObject from the same publication, including detached objects. The same scene painter captures current committed content without advancing timelines, reparenting or dispatching scripts. The source root's matrix, color transform, alpha and visible flag are ignored; descendant transforms/color/visibility and in-subtree vector clipping remain. Root scroll clipping remains active. External mask dependencies diagnose. Display filters are bypassed throughout capture following the pinned offscreen implementation; baked applyFilter pixels remain part of bitmap sources. Active text editing contributes committed Rust text, not an empty Canvas placeholder or uncommitted DOM text.

Draw uses normal source-over blending, an explicit affine matrix/color transform, logical pixels without Stage zoom or display pixel snapping, and a destination-space integer clip rectangle. Captured RGBA commits to the original Rust destination only if its revision is still current; self-draw reads the old image before committing. Linear matrix values are bounded to ±10000, translations to ±1e12, color multipliers to ±10000 and offsets to ±255. Draw/filter staging is limited to 4 Mi pixels and PNG output to 16 MiB, in addition to existing arena/filter-work limits. Other blend modes, drawWithQuality, arbitrary native sources and exact Canvas/Flash raster equivalence remain unfinished. See [ADR 0029](decisions/0029-bitmap-image-pipeline.md) and the image-pipeline delivery record for separate arithmetic, adapter and browser evidence.

### Runtime Transform and ColorTransform

The 2D runtime family exposes `flash.geom.Transform` and `ColorTransform` to AS2/AS3. A Transform binds to a live display object. `matrix` and `colorTransform` return independent value copies; assigning them updates the shared Rust graph. Exact local matrices retain skew through parent traversal, scalar rotation/scale changes and linked reparenting. A new matrix assignment derives nonnegative column magnitudes and separate axis directions; subsequent signed/zero scales retain cached directions. This is an explicit readback profile, not historical fixed-point decomposition parity.

Color uses four multipliers/offsets composed from child to parent, then clamps/rounds each straight RGBA channel. `alpha` addresses the local alpha multiplier. Rust creates transformed vector/text paints and read-only bitmap render bytes; the source BitmapData and sibling color transforms remain independent. Dynamic Graphics distinguishes absent paint from transparent paint. Authored transparent fill is actual fill material in the existing document model. Visibility, pointer picking and semantic bounds use transformed paint alpha.

Local matrix assignments require finite linear coefficients within ±10000 and translations within ±1e12. Applied local color transforms bound multipliers to ±10000 and offsets to ±255; concatenated reads may exceed these local assignment bounds. `ColorTransform.concat` applies the current transform then its argument; `color` sets RGB offsets and clears RGB multipliers while preserving alpha. Value objects require finite numbers instead of reproducing all Flash conversions.

`concatenatedMatrix`, `getRelativeMatrix` and outward-rounded `pixelBounds` use logical stage coordinates; browser CSS zoom/window mapping and exact raster/filter bounds are outside the profile. Direct replacement of `DisplayObject.transform`, dimension writes on rotated/skewed geometry, native subclassing and 3D properties diagnose. Document version 5 preserves imported authored skew and channel transforms; native gradient preview uses bounded adaptive meshes and HTML5 uses the original gradient brushes. Native script execution, complete skew-editing UI acceptance and historical coercion/rasterization remain separate work; runtime display filters have a separate bounded record. This implementation's delivery and independent acceptance are recorded separately in VERIFICATION.md; no blanket catalogue promotion is implied. See [the decision](decisions/0018-runtime-display-transforms.md).

### Date, RegExp and JSON

Date is available in both dialects through captured native-branded values. It supports current time, millisecond/component construction, UTC and local get/set methods, static UTC/parse, timestamp/valueOf and browser string/locale formatting. AS3 adds the named Date accessor properties and toJSON returning its string form. Values remain recognizable across separately compiled handlers and project methods. Parsing accepts the browser's ISO, RFC and other supported strings, with a 65,536-unit input bound; numeric components require primitives. Native method extraction, custom numeric conversion objects and native subclasses diagnose. Historical Flash parsing, timezone databases, locale formats and exhaustive coercions are not reproduced.

AS3 RegExp supports constructor/call/clone forms, source/flag properties, lastIndex, exec/test, and String match/search/regex replace/split including captures and replacement callbacks. Flags g/i/m/s and ASCII extended x are supported. A shared facade identity allows values to cross compiled units. Patterns are limited to 65,536 UTF-16 units and subject/output strings to 1,000,000; zero-width global iteration makes progress. The engine is native JavaScript, not PCRE. Known unsupported named groups, inline flags, conditionals, possessive forms and PCRE escapes diagnose; syntax, Unicode and zero-width split semantics remain a partial backend profile. Size limits do not bound worst-case native backtracking time. Slash literals still diagnose pending context-aware lexing. AS2 has no native RegExp/JSON claim.

AS3 JSON.parse/stringify supports primitive/Array/plain-object data, reviver/replacer callbacks, property-list filtering, indentation, toJSON and readable public fields/getters from registered project classes. The metadata bridge does not make ordinary getters enumerable. Unknown native objects require an explicit supported toJSON or replacer. Parsing and serialization are bounded to 1,000,000 UTF-16 units, 128 nested containers and 100,000 traversed values; cycles and invalid callback arguments diagnose. Undefined/function root values return null, while object members omit and array slots become null. Non-String/Number/null indentation is explicitly unsupported because the published reference and inspected avmplus implementation disagree. Vector values use array encoding; Dictionary uses its default toJSON label or an author override. Transient metadata, other native object encodings, exact property order and full error/coercion fidelity remain open.

One original resource-to-report workflow in examples/data-processing.nflash combines these APIs with URLLoader, text output and an independent AS2 UTC clock. Compiler/project scenarios retain lookup-order, identity and callback evidence; the ordinary browser delivery has a separate record in VERIFICATION.md. These are documented expectations, not an original Flash differential. See [Date](https://airsdk.dev/reference/actionscript/3.0/Date.html), [RegExp](https://airsdk.dev/reference/actionscript/3.0/RegExp.html), [JSON](https://airsdk.dev/reference/actionscript/3.0/JSON.html) and [the architecture decision](decisions/0017-data-processing-builtins.md).

### XML data and language facades

AS2 XML/XMLNode and AS3 XML/XMLList use one publication-owned service with a pure Rust XML 1.0 parser. Parsing accepts UTF-8 fragments, CDATA, predefined/numeric references, comments and processing instructions, preserving namespace declarations and expanded names. Limits are 1 MiB source, 50,000 nodes/attributes/declarations, 128 nested elements, 256 attributes/declarations per element, 1,024-byte names and 4 MiB expanded transfer strings. DOCTYPE/custom entities, non-UTF-8 declarations and invalid names/characters/namespaces diagnose. This parser performs no network or external entity resolution and is separate from XFL import.

AS2 supports document construction/parseXML, ignoreWhite/status/declaration reads, createElement/createTextNode and DOM name/value/attribute/child/parent/sibling access. appendChild/insertBefore move canonical nodes; removeNode and cloneNode preserve coherent detached trees. childNodes is a snapshot array; changes to it do not edit the tree. Individual unqualified attributes can be written/deleted. XML.load uses the existing URLLoader with loaded/onData/onLoad/byte counters and callback ownership; send/sendAndLoad and header APIs remain unsupported. Strict syntax/namespace/character failures set status -6 and preserve prior content; unsupported declarations and resource bounds throw actionable diagnostics. This does not reproduce historical partial-tree recovery or every legacy status code.

AS3 supports XML/XMLList construction/conversion, nullable typed slots, is/as, list indices and for-each. Explicit child/children/elements/descendants/attribute/attributes/text queries, content/name/parent queries, copy, appendChild/prependChild/setChildren/normalize and toString/toXMLString provide the bounded tree model. Single-item lists delegate XML operations; multi-item cardinality is checked. AS3 insertion copies XML inputs; primitive insertions create text. XML static ignore/pretty settings are shared across handlers and project classes and reset with the publication. Primitive settings require Booleans and prettyIndent is 0–32. Namespace-preserving serialization does not preserve original quote style/entity spelling; unqualified string selectors match the empty namespace and `*` provides wildcard traversal.

The mutable service budgets 50,000 allocated nodes/declarations, 8 MiB owned text/name data and 1,000,000 retained list references per publication. Detached nodes remain budgeted until Restart; serialized output is limited to 4 MiB. Restart cancels old loads, invalidates old wrappers and restores settings. XML source selectors, target-list edits, Namespace/QName values and bounded literals are described below. Default XML namespace, filters, general XML equality/addition and native subclasses remain unsupported. Branded AS3 XML addition/equality and switch operands explicitly diagnose; authors can convert to String or use tree methods. AS2 node identity equality retains its ordinary behavior. Optional flash.xml legacy aliases are not included.

[xml-catalog.nflash](../examples/xml-catalog.nflash) connects both facades to the same portable resource, copied versus moved branches, namespace roundtrip and typed handler transfer. Delivery verification is separate from independent declaration audit; see [the architecture decision](decisions/0020-xml-tree-and-language-facades.md) and [VERIFICATION.md](VERIFICATION.md). No full E4X or original-player conformance is implied.

### E4X source selection, edits and literals

AS3 supports child/bracket, attribute/computed-attribute, descendant, wildcard and qualified namespace selectors. Selected lists retain target metadata so a uniquely rooted empty selection can create its child on indexed assignment. Child/attribute assignment, indexed replacement and deletion use staged tree edits; multi-parent ambiguity and wildcard target creation diagnose before mutation. Membership snapshots can retain detached node identities; insertion/assignment copies XML values. Direct descendant writes/deletes remain unsupported; indexed nodes selected from a descendant result use the normal reference path. The AS2 DOM keeps its separate move semantics.

Compiled reads and calls are distinct: `node.length` selects a child named length, while `node.length()` invokes the XML method. Namespace/QName values use URI/local names for selection, including bracket keys and explicit traversal methods. Values are immutable in this profile. Native class namespaces, namespace declarations/use namespace, scoped default XML namespace, filters and complete historical target-resolution/coercion behavior remain unfinished. Namespace/QName equality and switch operands explicitly diagnose, along with the existing XML equality/addition boundary; ordinary String conversion is available.

XML/XMLList literals accept static element/attribute names, static namespace declarations, nested markup and fragments. Child `{expression}` holes insert copied XML subtrees or escaped scalar text; whole unquoted attribute values such as `id={expression}` stay attribute data. Each hole executes and converts once before the next hole. The parser uses a buffered cursor and an isolated lexical scanner, including in project methods; XML apostrophes/content are not eagerly tokenized as ActionScript. Braces inside quoted XML attributes, comments, processing instructions and CDATA remain literal markup content. Dynamic names, namespace interpolation and partial attribute interpolation are diagnosed. The existing Rust parser validates the static skeleton; limits include 1 MiB skeleton, 1,024 holes, 2,049 parts and depth 128, plus publication tree/string budgets.

The existing XML catalog now edits stock attributes, creates an empty target, replaces/deletes selected items, inserts a literal fragment and updates qualified metadata. It distinguishes a child named length from its method, records interpolation order and preserves the tree after an ambiguous edit. The same helper/browser workflow retains the AS2 DOM pane and Restart. See [the decision](decisions/0021-e4x-references-and-literals.md) and [verification](VERIFICATION.md) for evidence; this partial layer does not claim complete ECMA-357 behavior.

### Sound playback

AS3 project imports expose `flash.media.Sound`, `SoundChannel` and `SoundTransform`. Sound loads a complete embedded resource or HTTP(S) GET through the existing resource/CORS transport, reports byte counts/duration/URL and dispatches loading events. `play(startTime, loops, transform)` returns a channel with position, stop, copied transform values and `Event.SOUND_COMPLETE`; startTime is milliseconds and loops counts additional plays. Stop suppresses natural completion. Volume is a finite number in 0–1 and pan in −1–1, implemented with browser gain/stereo-panning nodes. Native subclasses, direct SoundChannel construction, SoundLoaderContext and channel-matrix properties are unsupported. A decoded Sound retains one resource; create another Sound to load different audio. References: [Sound](https://airsdk.dev/reference/actionscript/3.0/flash/media/Sound.html), [SoundChannel](https://airsdk.dev/reference/actionscript/3.0/flash/media/SoundChannel.html), [SoundTransform](https://airsdk.dev/reference/actionscript/3.0/flash/media/SoundTransform.html).

AS2 has a captured `Sound()` global with erased annotations, `loadSound(url, false)`, start/stop, volume/pan, position/duration, byte counts and actual-receiver `onLoad`/`onSoundComplete` callbacks. Start offsets use seconds and loops is a total play count starting at one. Volume/pan use 0–100 and −100–100. Stop and transforms affect channels owned by that Sound adapter: no document-wide mixer, MovieClip target hierarchy, library attachSound or streaming behavior is implied. The wider [AS2 Sound contract](https://open-flash.github.io/mirrors/as2-language-reference/Sound.html) remains only partially implemented.

`web/audio-formats.js` validates bounded standard MPEG-1/2/2.5 Layer III MP3 frame metadata and mono/stereo PCM/float WAV before native decoding. It reserves resampled PCM memory before `decodeAudioData`; it is not a decoder and does not establish support for every browser codec. Free-format MP3, changing frame layouts and other containers reject. Default limits are 128 MiB decoded/pending PCM, 32 active or pending channels and 256 Sound objects per publication, plus the existing 16 MiB encoded-resource limit. AS3 repeat counts are 0–10,000, AS2 counts 1–10,001, and offsets are bounded. Close cancels loading; Restart invalidates channels/listeners and suppresses stale callbacks. Because native decoding cannot be aborted, outstanding reservations remain charged until those operations settle.

Playback requires browser user activation. The exported footer offers Enable audio and audio status; a suspended channel remains pending until permission succeeds. Embedded data works offline, external requests retain browser network/CORS requirements. Streaming, ID3 access, sampleData, extract, SoundMixer, microphone/capture, timeline audio authoring and complete Flash coercion/mixing/timing parity remain pending. Video uses its separate file-playback profile below.

The original `examples/sound-playback.nflash` embeds a 4,727-byte MP3 made from generated 440 Hz and 660 Hz sine pulses with silence, mono 22,050 Hz and approximately 0.7 seconds. No external recording is used. Both AS3 and AS2 set volume zero before playback, and grouped Play/Stop controls expose completion and cancellation without audible output. One ordinary-export/real-WASM scenario passes original-byte transport/preflight, typed owners, gesture gating, zero gain before source connection, channel transforms, completion/stop/close and Restart using an injected audio scheduler. It includes one bounded WAV metadata check. The separate in-app-browser delivery pass verified actual MP3 decoding, offline PCM, zero-output native lifecycle and the ordinary AS2/AS3 Play/Stop/Restart workflow. It does not establish audible quality, historical Flash mixer parity or WAV native decoding; see VERIFICATION.md.

### Portable resources and data loading

The AS3 program registry accepts exact imports for URLRequest, URLRequestHeader, URLRequestMethod, URLVariables, URLLoader and URLLoaderDataFormat, plus ProgressEvent, IOErrorEvent and HTTPStatusEvent. Requests support GET/POST, text/form/ByteArray bodies, explicit permitted headers and loader TEXT/BINARY/VARIABLES formats. A binary result is a fresh ByteArray owned by the current publication. URLVariables uses dynamic form fields, repeated keys as arrays, decode and toString; malformed UTF-8/percent escapes and unsupported object-valued serialization reject. Native subclasses of these facades are explicitly unsupported; use listener composition.

Relative URLs first resolve immutable embedded resources asynchronously. Embedded resolution uses the bundled bytes and requires no local server; direct-file browser observation is separately pending. External URLs use ordinary browser HTTP(S) fetch, CORS and same-origin credentials; they do not emulate Flash policy files, read desktop credentials or fall back to local filesystem access. Browser-controlled headers reject, while author-supplied permitted headers are preserved. Loads expose current byte counters and bounded open/progress/complete/ioError events; HTTP status events describe actual HTTP responses, not invented statuses for embedded data. close(), replacement loads, Restart and disposal suppress obsolete callbacks. The service bounds each response/body to 16 MiB, active response bytes to 64 MiB, concurrent operations to 32, form pairs to 1,024 and request headers to 64.

AS2 has its own captured LoadVars constructor with erased annotations, decode/toString, byte counters, GET load, GET/POST sendAndLoad, headers and dynamic callback receivers. The default onData route decodes then invokes onLoad; an authored onData callback receives raw text instead. HTTP status callbacks correspond to actual transport responses. Native subclassing, multipart uploads, sockets, URLStream, remote SharedObject, authentication prompts, timeouts/retry configuration, full coercion/errorID/security semantics and exact historical event ordering remain unsupported. Text/data loading does not itself decode media; images and complete-file audio use their separate bounded families above. Video uses the separate file-playback profile below.

Contracts are based on [URLLoader](https://airsdk.dev/reference/actionscript/3.0/flash/net/URLLoader.html), [URLVariables](https://airsdk.dev/reference/actionscript/3.0/flash/net/URLVariables.html) and the [AS2 LoadVars reference](https://open-flash.github.io/mirrors/as2-language-reference/LoadVars.html). The original `examples/resource-loading.nflash` combines embedded text/form/50-byte binary data, visible AS3/AS2 callbacks, missing-resource recovery and cancellation. Its combined ordinary-export/real-WASM execution scenario passed embedded loading, actual local HTTP POST from emitted AS3/AS2 code, cancellation and Restart. The embedded pipeline, successful same-origin HTTP GET and Restart also passed in the in-app browser. Native resource-panel and direct-file browser opening remain pending; Node fetch does not verify browser CORS, and cross-origin behavior was not separately exercised.

### Visibility and replacement

`visible` and `_visible` now change shared Rust display state. The getter reports local visibility; a hidden ancestor prevents descendants from drawing or receiving pointer/semantic activation. Hidden instances remain script-addressable, retain custom fields, and continue their independent clocks and Load/EnterFrame dispatch. Showing them restores rendering and semantic targets without recreating them. Root visibility is also supported by the runtime. Modern visible uses Boolean conversion. Legacy _visible follows a bounded numeric-property profile: Boolean/number and plain signed decimal strings; null/undefined/NaN and supported invalid alphabetic strings leave the value unchanged. Object/function and ambiguous numeric-text conversions give explicit diagnostics. See web/runtime.js for the supported grammar and pinned Ruffle reference; this is not every historical conversion or TextField/Button contract.

Changing the library symbol at an existing placement path creates a new subtree lifetime. Its overrides, custom fields and nested clocks reset; old proxies become stale, and sibling instances retain their own state. Blank-gap XFL re-entry receives fresh placement IDs. Broader construction/re-entry ordering still requires conformance work. TextField state and uniform layout now have the bounded owner-aware implementation above; rich text, remaining callbacks and other absent built-ins still require implementation or diagnostics. Arbitrary custom-field storage does not establish those APIs.

### Bounded numeric profiles

AS3 direct `int()` and `uint()` calls and scalar constructors accept zero or one argument and use captured numeric conversion followed by signed/unsigned 32-bit coercion. AS2 direct `int()` also uses signed 32-bit coercion. Local bindings and resolved project names retain precedence; AS3 Number/int/uint/Boolean values can be stored in `Class` bindings, called or constructed through lexical aliases, and queried with `is Class`/`as Class`. The int/uint MIN_VALUE and MAX_VALUE constants are available. Registered project classes also support Class-alias construction; arbitrary Function construction and complete prototype identity remain unsupported. Extra numeric constructor arguments still diagnose. AS2 `random(n)` supplies an integer below the nonnegative truncated bound, capped at signed-int maximum, using the host RNG; historical seed sequences are not reproduced. AS2 `Boolean()` returns undefined for omission and false for explicit undefined.

AS2 `parseInt("0777")` returns 511 using the pinned Ruffle AVM1 parser profile; AS3 returns 777 using the pinned Adobe avmplus native profile. AS2 validates explicit radix before input conversion, rejects explicit radix zero and uses automatic octal only for a complete octal digit string. AS3 uses signed 32-bit radix conversion and decimal default/hex detection. Bare function values retain their dialect; user bindings that shadow parseInt remain ordinary user functions.

AS3 Number/int/uint `.toFixed()` converts precision to int once and accepts 0–20. Invalid precision throws catchable RangeError with errorID 1002 before formatting NaN/Infinity. Large finite integral values avoid JavaScript's exponential notation. Other finite formatting uses native JavaScript; historical Flash rounding differences are not implemented. Custom user methods preserve their receiver and evaluation order. Extracted AS3 numeric `toFixed`, `toExponential`, `toPrecision`, `toString` and `valueOf` retain their receiver through direct calls and Function.call/apply. Numeric class identity is shared across publication handlers; method identity storage is bounded to 16,384 distinct numeric receiver values. Existing formatting calculations are reused. Prototype borrowing and excess precision-method arguments remain outside the profile.

AS3 `.toExponential()` accepts precision 0–20, defaulting to zero. `.toPrecision()` accepts 1–21; omission uses zero and throws RangeError, while explicit null/undefined uses ordinary string conversion. Both use the same bounded numeric formatting policy above. AS3 `encodeURI`, `encodeURIComponent`, `decodeURI` and `decodeURIComponent` use the shared Rust UTF-8 codecs after typed String conversion: omission becomes `"undefined"`, explicit null/undefined becomes `"null"`, and malformed input throws URIError. These additions have grouped execution evidence; earlier browser acceptance does not cover them.

The [intrinsic reference record](../crates/neoflash-script/tests/INTRINSICS.md) gives exact pinned sources, argument/conversion limits and typed expectations. All reference expectations are **documented_only**, not measurements of an original Flash Player. The ordinary `examples/as-intrinsics.nflash` export produced its exact twelve-line transcript twice with Restart in Chrome and the in-app browser. JS/TS globals and prototypes are unchanged. These profiles do not implement boxed primitives, all historical whitespace/rounding, project classes or typed instance slots.

### AS2 timeline navigation boundary

Direct AS2 `gotoAndPlay`/`gotoAndStop` calls compare labels with ASCII-only case folding and select the earliest matching frame across layers. `END` can match `end`; `BADÀ` does not match `BADà`. An unknown label is a no-op that preserves both the frame and its play/stop state. A successful jump changes `_currentframe` immediately while destination-frame scripts remain queued for the host's normal dispatch. The separate bridge is captured by AS2 closures, so invoking one from JS or AS3 does not change its navigation behavior.

Decimal numeric strings are parsed before label lookup: `"3"` targets author frame 3 even when a label named `3` exists elsewhere. The implemented numeric range is integer frames 1 through the timeline length. Zero/negative values, values above the last frame, fractions, non-finite numbers and wrapping/clamping cases produce explicit unsupported-behavior errors; other argument coercions are not implemented. This intentionally bounded numeric behavior is not the complete [AVM1 goto behavior in the pinned Ruffle implementation](https://github.com/ruffle-rs/ruffle/blob/fe6cfc545405b888ebb478ce1c211d63147ca49b/core/src/avm1/globals/movie_clip.rs#L1113).

Native AS2 goto function values/aliases remain unsupported because detached receiver semantics have not been established. Known direct forms such as `var jump = gotoAndStop` or `var jump = clip.gotoAndStop` produce compilation diagnostics. Calls through computed/copied aliases are also checked by native method identity and fail explicitly without changing the timeline. Ordinary user functions and local variables/parameters shadowing `gotoAndStop` retain their own behavior. Arbitrary computed member calls remain compilation errors. JS/AS3 navigation stays strict: exact label matching, the existing label-first numeric-string handling, and errors for unknown labels or invalid frame numbers. None of these rules claims complete Flash navigation compatibility.

The AS1 legacy and AS2 profiles accept top-level `on(...)` wrappers for `press`, `release`, `releaseOutside`, `rollOver`, `rollOut`, `dragOver` and `dragOut`, and `onClipEvent(...)` wrappers for `mouseDown`, `mouseMove`, `mouseUp`, `unload` and `enterFrame`. They register the corresponding `onPress`/`onRelease`/other named callbacks; imported wrappers initialize on placement Load. Other event names, wrappers inside functions/classes and AS3 wrappers produce diagnostics. NeoFlash's separate object-event UI accepts handler bodies in its supported languages; it is an authoring abstraction, not historical AS3 object-script syntax.

The browser host still needs independent conformance work for event ordering, first-frame creation, nested `goto` reentrancy, frame script ordering, buttons, loaders, destruction, sound and timeline lifetimes. Scrubbing/onion skin must evaluate authored state without executing user code. Passing a syntax test does not prove parity with Flash Player.

Checks: script-crate Rust tests verify parser/diagnostics, lowering invariants and the AS2 dynamic-call/alias boundary; four core tests cover AS2 label resolution. `node crates/neoflash-script/tests/execute.mjs` runs the executable behavior fixtures counted in VERIFICATION.md: timeline calls, repeated-handler state, integer overflow, evaluation order (including one numeric conversion per typed postfix update), short-circuit writes, named children, TypeScript output, function hoisting, local defaults, shadowing, recursion, closures, callbacks, early returns, typed arguments/returns, argument-count errors, supported receiver binding, escaped object-property names, postfix line breaks, assignment in conditional branches, switch test order/fallthrough, do/continue, labelled jumps, finally completion precedence, catch closures and shadowing, per-language throw identity, typed catch/slot checks and Error message/id evaluation order. Integration checks execute the actual `proxyFor`/`dispatchScripts` host code for lifecycle, trace/status, language isolation, numeric precedence, unknown-label no-ops, dynamic callable failures and alias rejection. The public FLA comparison below additionally runs the actual WASM timeline. These test NeoFlash's implemented subset; they are not a Flash Player conformance suite.

## Complete compatibility work remaining

1. Per-language conformance fixtures: parse, type resolution, output trace, runtime state, and expected diagnostics. Include edge cases for short-circuiting, coercions, integer overflow, string indexing and frame transitions.
2. Broader AS2 source semantics and an AVM1 compatibility strategy built on the shared Rust core.
3. Extend the bounded AS3 project/class profile with access control, deeper interface/accessor conformance, namespaces/E4X, initialization/type conformance and remaining function defaults/rest/receiver semantics; deepen the separate AS2 project class/prototype and native-input profiles.
4. Flash API mapping by package, with explicit supported/adapted/unavailable decisions. Platform APIs are distinct from operators. No claim that all of `flash.*` or AIR works in a browser.
5. Complete linked-class construction/re-entry and event ordering, broader host API ownership, debugging and source maps. Current project linkage and native family facades do not complete these contracts.
6. Broader legacy playback/import through deliberately adapted, licensed algorithms in the shared Rust core. Complete external ActionScript engines are not embedded; native HTML5 publication remains the primary architecture.

## Legacy file conversion and source fixtures

Native Rust conversion supports the bounded Flash MX/CS4 binary profiles exercised by `Clock.fla` and `300x600.fla`; the separate XFL adapter retains its own limits. Version-5 projects preserve supported nested symbols, layers/masks, text and bitmap placements, full affine transforms, gradient paths, color transforms and classic motion tweens with Flash acceleration or a single all-property Bézier curve. Original frame/object source is retained. Exact original FLA bytes and provenance are embedded for properties outside the editable model; this is not lossless FLA re-export. Unsupported semantics block conversion or produce the documented diagnostic, and a bitmap already absent from the source remains an explicit unresolved placeholder. See [the import boundary](IMPORTS.md#native-binary-conversion-boundary) and [the architecture decision](decisions/0008-real-fla-acceptance.md).

Actual imported projects passed the ordinary exporter and WASM host: Clock's original AS1 callback rotates all six hand/shadow instances despite their lowercase authored names; the banner retains two active masks and its stable button Hit geometry through its nested animation. Its original AS2 release handler navigates when the containing project supplies `link1`. Browser observation showed Clock moving and the banner progressing from the car artwork to the phone artwork, with no runtime errors. Missing installed fonts were accepted as fallback differences. Native editor checks on the 300×400 and 300×600 banners also show independent animation beneath a one-frame root, filled logo/wipe artwork and the white-to-black transitions. Pause/resume and Rewind retain/reset the displayed pose; native scrubbing and preview do not execute source scripts. These are sample-specific observations, not pixel-identical Flash conformance; Clock’s scripted behavior still uses Test Movie. Private source files and their artwork are not added to the public corpus. The checked-in [legacy runtime scenario](../crates/neoflash-script/tests/legacy-import.mjs) exercises the source/case and button callback boundaries independently.

The [FLA corpus](../examples/fla-corpus/README.md) retains 15 unchanged upstream FLA sources and three original synthetic examples. Its 21 input forms produce nine successful imports and 12 explicit refusals. Three upstream documents import: the MX button and static-text cases through the native binary profile, and Ruffle's [frame-labels FLA](../examples/fla-corpus/upstream/ruffle/avm1-frame-labels/test.fla) through the bounded convex solid/stroked XFL profile. The two MX cases contain no scripts; checked-in native projects, semantic regressions and comparison with the pinned converter establish their conversion boundary, without additional browser or script-execution claims. See [import compatibility](IMPORTS.md).

`node --test web/tests/real-fla-frame-labels.test.cjs` imports the unchanged FLA, compiles all nine original AS2 frame scripts, and executes them through the actual WASM timeline and browser-host proxy/dispatch code. It matches the upstream 17-line trace exactly, verifies the stopped root at author frame 3 while the child loops to its own stop frame, and repeats the exact trace after reset with a fresh instance lifetime. The three original examples retain their separate import/runtime checks; see [the verification record](../examples/fla-corpus/VERIFICATION.md) for browser observations. The other 12 upstream FLAs remain blocked, and their expected outputs are reference material. Import retention alone never establishes ActionScript compatibility; these case-specific corpus results do not establish general AS2/AS3 or binary FLA support.

## Runtime image loading

AS3 Loader/LoaderInfo and AS2 MovieClipLoader use the shared resource/HTTP byte transport and bounded Rust PNG/JPEG decoder. Loader.load and loadBytes create a managed Bitmap child, expose metadata and emit asynchronous loading events. Its inherited child mutation methods reject; unload/replacement detaches previous AS3 content while retained Bitmap/BitmapData references remain valid until explicit disposal or publication reset. Existing arena budgets remain enforced; full garbage collection is not implemented. Encoded images are bounded to 16 MiB, dimensions to 4096, decoded pixels to 128 MiB/256 records and tracked load targets to 256. Pending loads retain committed content until successful replacement; this timing profile is explicit rather than claimed as complete Flash load-transition parity.

AS2 loadClip replaces the original non-root MovieClip artwork/descendants, clears its Graphics, stops its timeline and suppresses original authored dispatches. Target identity and transforms remain; unloadClip leaves an empty target. Listener callbacks and getProgress share the current load operation. AS3 INIT precedes COMPLETE, while AS2 complete precedes init. New loads, close/unload and Restart invalidate obsolete callbacks. SWF/GIF decoding, application/security domains, native Loader subclasses and arbitrary legacy string/numeric target addressing remain outside this first profile. See [ADR 0024](decisions/0024-runtime-image-loading.md) and delivery evidence in VERIFICATION.md.

## Local SharedObjects and AMF object records

ByteArray readObject/writeObject and instance/default objectEncoding support AMF0/AMF3 through a bounded Rust codec. Common records/arrays, shared references/cycles, Date, ByteArray, undefined, non-finite values and negative zero use the actual wire format. Sparse holes materialize as undefined. AMF0 dates are inline values; date identity is not promised there. Anonymous source-class public fields/getters can flatten to records, but aliases/class reconstruction, externalizable objects, XML/Vector/Dictionary, empty AMF3 dynamic property names and native/display serialization remain unsupported. Decoder consumption controls the ByteArray cursor; failures preserve buffer/cursor state. Encoded data is limited to 16 MiB, graph items to 100,000 and nesting to 128.

AS3 SharedObject/SharedObjectFlushStatus/ObjectEncoding and captured AS2 SharedObject provide getLocal, data, flush, clear and size/getSize. AS3 defaults to AMF3, AS2 to AMF0. Browser storage keys include origin, publication pathname or an explicitly allowed ancestor localPath, name and secure flag. secure=true requires HTTPS; file/opaque origins refuse persistence. A versioned localStorage envelope carries AMF data, not native .sol files. Size counts AMF payload bytes, excluding envelope/filesystem overhead. Quota/access errors throw in AS3 or report failure in AS2; there is no emulated pending permission dialog.

Clear replaces AS3 data but empties AS2 data in place in this bounded dialect profile. Explicit flush persists synchronously; pagehide is best effort. Restart invalidates wrappers/discards unflushed edits and reopens successful saves. Remote synchronization, remote NetConnection transports, full historical disk/name/coercion behavior and cross-tab notifications remain pending. See [ADR 0025](decisions/0025-shared-objects-and-amf.md) and the delivery-specific evidence in VERIFICATION.md.

## Text input, focus and selection

The scripted input profile adds TextField.type/selectable/displayAsPassword/maxChars/restrict, UTF-16 selectionBeginIndex/selectionEndIndex/caretIndex, setSelection and replaceSelectedText. Rust owns committed values and revision-checked user-edit transactions. maxChars/restrict affect user insertion; programmatic assignment/replacement bypasses them. Common Unicode scalar ranges, exclusion toggles and escaped range metacharacters are bounded, without automatic legacy case substitution; complete Unicode boundaries prevent broken surrogate replacements. Password layout masks characters while the raw script-readable value is retained.

AS3 TextFieldType, TextEvent and FocusEvent connect to EventDispatcher and Stage.focus. Insertion dispatches cancellable textInput before mutation; change follows an actual user text change. Scripted edits do not synthesize user events. AS2 Selection accepts live display targets/null and exposes focus/selection queries and listener callbacks, with TextField onChanged/onSetFocus/onKillFocus. General string target resolution remains pending.

Native password editing requires a single-line field. The browser supplies a native input/textarea during editing, including transient composition and paste/selection. The overlay follows the stage affine transform and shared vector clipping; the Canvas copy is suppressed until editing ends. It sits above Canvas artwork, so foreground Canvas occlusion during editing is a known boundary. Browser native text metrics, scroll/wrap details, arbitrary IME/locale/grapheme behavior, original Flash focus navigation and full accessibility are not implied by the initial workflow. Rich/HTML text, mixed runs, embedded fonts, advanced text APIs and native input-field authoring UI remain unfinished. Restart removes editing controls and invalidates old fields. See ADR 0026 and the separate form acceptance in VERIFICATION.md.

Observed typing, paste, focus, selection, cancellation and saved-value workflows are documented in the [form verification scope](VERIFICATION.md#independent-forms-verification-of-c10e19e). Password/selectable modes, arbitrary transformed/clipped editing, full accessibility and native input authoring still require acceptance.

## Display-object filters

AS3 BitmapFilter/BlurFilter/GlowFilter/DropShadowFilter/ColorMatrixFilter and BitmapFilterQuality imports, plus the AS2 qualified filter classes, support copied display.filters arrays and cloneable values. ColorMatrix matrix reads/writes are copies. Sequential arrays apply cumulatively; nested filtered objects become parent-linked groups in the Rust snapshot. A whole object's graphics, text and bitmap descendants share its filter, with child filtering/clipping inside the parent's source and owner mask/scroll clipping on final output. Original geometry remains the hit and semantic target; shadows and glows do not add targets.

The original Rust CPU kernel uses premultiplied separable box blur, blurred-alpha glow/shadow with strength/alpha/color and inner/knockout/hideObject flags, and straight-RGBA ColorMatrix coefficients. Radius/angle/distance are logical Stage values; object rotation/skew changes the source, and Stage zoom scales the result. The browser's first raster profile is one logical pixel per Stage pixel, with bounded reusable surfaces/cache. It does not claim exact Flash Gaussian/rounding, high-density text fidelity or every AVM coercion/clamp.

Limits are eight filters per owner, 128 filtered owners, 512 specifications, 4 Mi raster pixels, 8192 pixels per side and 128 Mi channel-pass work units per kernel call. Filter JSON is limited to 64 KiB. Blur dimensions are 0..255, integral quality 0..15, alpha 0..1, strength 0..255; distance is within ±8192, angle within ±1e9 and twenty finite matrix coefficients within ±65536. Invalid value arrays/assignments are explicit failures; old object state remains intact. Native subclasses, arbitrary custom/shader filters, full cacheAsBitmap conformance and native effect authoring remain unfinished. Additional gradient/convolution effects have the [Rust filter profile](AS-RUNTIME-HOUR-2.md); displacement has the bounded [AS2 bitmap profile](AS2-BITMAP-BATCH.md). Native DOM TextField editing under filters is explicitly diagnosed rather than displayed without its parent effect. See ADR 0027 and the gallery's own verification record.

## Source class access and packages

AS3 project fields, methods and accessors carry public/private/protected/internal visibility. Omitted class/member visibility is internal; constructors and interface signatures follow their separate declaration rules. Private slots are owned by their declaring class, protected overrides retain virtual dispatch, and internal collaborators share a package namespace. Final classes/methods reject extension/overrides. Dynamic permits additional public properties only on explicitly dynamic classes; a derived class is sealed by default. Public fields and readable getters remain JSON-visible, while nonpublic state is excluded. Fixed traits do not become dynamic enumeration entries.

Property lowering carries the lexical class for dot/bare access; computed string properties use the public namespace. Sealed checks cover ordinary objects and linked display owners. This is a bounded source/runtime profile, not a complete namespace or VM implementation. Exact and wildcard imports resolve only embedded same-dialect definitions and supported built-ins; wildcard imports do not recurse into subpackages. Internal classes are package-visible.

AS2 private retains compile-time access, including subclasses, while runtime properties remain string/prototype based. The compiler diagnoses supported statically resolved invalid access; dynamic/untyped and bracket behavior are not AS3 privacy. See [ADR 0030](decisions/0030-class-packages.md) and the component workflow for the delivery-specific bounds and evidence.

## Video and local streams

AS3 Video is a display leaf with authored or runtime-created identity, dimensions and smoothing. Native File → Import → Video placeholder and Properties use the existing document/undo path; native preview renders an explicit placeholder, while HTML5 consumes decoded frames through the shared painter. AS2 has no ordinary Video constructor: a named authored placement accepts attachVideo. Parent containers own mouse input because Video is not an InteractiveObject.

Local NetConnection.connect(null) and NetStream support embedded media and browser HTTP(S)/CORS sources, metadata/status callbacks, play, pause/resume, second-based seek, close and publication cleanup. AS2 has its own onStatus/onMetaData and pause(flag?) adapter. The shared audio gesture/mute controls apply to video; SoundTransform volume is copied and unsupported pan/matrix behavior diagnoses. Browser codecs determine playback. The original example uses H.264 baseline/yuv420p and silent AAC.

Embedded media preserves the existing 16 MiB/resource and 64 MiB/document resource budgets. Native HTTP media requests do not first buffer the entire file in URLLoader; buffering and codec allocations are browser-managed. Metadata bounds do not imply a preallocation guarantee for the browser decoder. Exact supported object/surface limits and lifecycle behavior are recorded in [ADR 0031](decisions/0031-video-streams.md). Host media adapters prove command delivery and ownership only. The separate [browser record](VERIFICATION.md#file-video-and-local-stream-workflow) confirms the original MP4 decode/control/lifecycle workflow; it does not establish every native codec or progressive-before-download completion.

RTMP/RTMFP, camera capture, publishing, DRM, legacy FLV codecs, cue points, historical buffer/byte/mixing fidelity, native video decoding and timeline synchronization remain unsupported or unverified. Seek follows browser media behavior rather than a claim of exact Flash keyframe selection. Original Flash and cross-engine conformance remain separate acceptance.


## Pointer dragging and hit tests

The shared Rust display identity now carries mouseEnabled/mouseChildren, buttonMode/useHandCursor and hitArea references. Updates validate the complete copied state; stale sources, noninteractive targets and unsupported self/cyclic hit-area references reject. A hit-area donor retains its own identity and transform, can be invisible, and is not consumed as a mask. Its own mouseEnabled controls whether it intercepts input. Removing an authored lifetime clears inbound references; detached live objects retain their state until retirement or Restart.

The browser adds one active AS3 Sprite/MovieClip startDrag/stopDrag operation, copied parent-space Rectangle constraints, local mouseX/Y, hitTestObject and hitTestPoint. AS2 uses numeric startDrag limits, hitTest overloads, _xmouse/_ymouse, _droptarget and onRelease/onReleaseOutside/onRollOver/onRollOut alongside onPress. A release delivers script callbacks; drag ends through explicit stopDrag or replacement, rather than being implicitly tied to mouseup. The host clears capture/active state for cancellation, removed/detached owners, Restart and publication failure. Reparenting during a drag is a bounded cancellation policy, not a historical-Flash guarantee.

Input picking and script geometry queries remain distinct: flags change event targets without changing script collision results. The initial profile covers two-dimensional transformed geometry; filter expansion, exact glyph/antialias coverage, transparent-fill identity, all mask/scroll combinations, multi-touch, 3D and complete historical coercion/event ordering require separate evidence. Legacy MovieClip.enabled and trackAsMenu are not inferred from AS3 mouseEnabled. See [ADR 0032](decisions/0032-pointer-drag-hit-testing.md) for ownership and delivery verification.


## Web page integration

AS3 flash.external.ExternalInterface and the separate AS2 facade connect a publication to named functions in its containing page. AS3 uses addCallback(name, closure); AS2 uses addCallback(name, instance, method), preserving its explicit receiver and Boolean result. The publication canvas supplies its real DOM identity and callback methods. Calls are synchronous and copy supported values; receiver-preserving named function paths do not evaluate JavaScript expressions. Restart removes owned callbacks and invalidates saved wrappers. AS3 marshallExceptions is a bounded exception bridge; ActiveX/plugin domains and arbitrary executable/native values are outside this profile.

AS3 navigateToURL and AS2 getURL/LoadVars.send use native HTTP(S) GET or UTF-8 URL-encoded POST navigation. AS3 absent targets select _blank; AS2 getURL defaults to _self. LoadVars.send defaults to POST and an omitted target is the documented no-navigation return path. Named frames/windows and reserved contexts retain browser policy. Navigation cannot attach custom headers or binary/non-form request bodies; use the existing data transport for those.

AS3 sendToURL reuses URLRequest GET/POST/header/body validation and ignores the HTTP response, including its status. No URLLoader completion event or response data is synthesized. Pending sends share the 32-operation, 16 MiB per body and 64 MiB active-byte budgets; Restart aborts pending work without undoing a request already delivered. Browser CORS, activation, sandbox and popup policies apply; unload delivery, arbitrary network/security semantics, native host channels and original-player parity are not claimed. See [ADR 0033](decisions/0033-web-container-integration.md).
