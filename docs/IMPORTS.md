# Import compatibility

The product goal includes FLA, XFL and SWF import. They are **not interchangeable formats**, and a file extension alone cannot establish support. The importer implements a deliberately limited XFL subset, native Rust conversion of binary FLA saved by Flash 3 through CS4, native Rust SWF (`FWS`/`CWS`/`ZWS`) conversion into editable projects with static AVM1/AVM2 decompilation, and `Project → .fla` (ZIP-compressed Adobe XFL 2.2 archive) export. Recognizing a container or consuming its records does not by itself establish lossless authoring fidelity.

## Public regression corpus

The [public corpus](../examples/fla-corpus/README.md) contains 15 unchanged licensed FLA sources from Ruffle, Flump and flacomdoc, plus three original synthetic ZIP/XFL examples and their native projects. The 21-input checker records all 21 successful imports (15 external FLA sources plus the XFL/FLA versions of the three original examples), each compared with a checked-in native project and its required warnings. It verifies pinned source hashes, required diagnostic categories, no partial output on refusal, no overwrite and unchanged inputs.

The [downloaded frame-labels FLA](../examples/fla-corpus/upstream/ruffle/avm1-frame-labels/test.fla) imports directly to [an editable native project](../examples/fla-corpus/imported/ruffle-avm1-frame-labels.nflash). Its 550 × 400 stage at 24 fps, seven-frame root, two-frame child, solid stroked square and all **nine original AS2 frame scripts** are retained. The actual-WASM/browser-host regression imports the unchanged source, compiles all nine scripts, and reproduces all **17 lines** of the upstream expected trace after initialization and three ticks. Further ticks keep the root on display frame 3 without extra trace; reset creates a new instance lifetime and reproduces the same trace. See [the verification record](../examples/fla-corpus/VERIFICATION.md) for HTML5 browser observations. This is one verified XFL-based document; the other upstream traces remain reference material. Native binary import has a separate conversion and verification boundary below.

Run `python3 scripts/check-fla-corpus.py`; it builds the current importer. The same checks are included in `scripts/check.sh`. Licenses, immutable source URLs, hash manifests and browser-check limits are kept with the corpus.

## Using the importer and FLA exporter

```sh
cargo run -p neoflash-import -- inspect /path/to/project.fla
cargo run -p neoflash-import -- inspect /path/to/movie.swf
cargo run -p neoflash-import -- import /path/to/movie.swf /path/to/new.nflash
cargo run -p neoflash-import -- import /path/to/movie.swf /path/to/new.fla
cargo run -p neoflash-import -- export-fla /path/to/project.nflash /path/to/new.fla
```

`inspect` prints a JSON report with detected format/version, `can_import`, statistics and source-located diagnostics. A recognized unsupported format is a successful inspection with `can_import: false`. Read/container failures return an error. `import` requires no blocking diagnostics and creates a new `.nflash` JSON document (or a `.fla` XFL 2.2 ZIP archive when the output path ends with `.fla`); `export-fla` converts an existing `.nflash` project or any importable `.swf`/`.fla`/`.xfl` input into a new `.fla` archive. Both commands refuse to overwrite an existing file. In the desktop editor, `File ▸ Open…` opens `.swf`, `.fla` and `.xfl` directly as an editable project. `File ▸ Save as…` saves `.nflash`; choosing `.fla` produces a modern Animate compatibility copy without changing the open document path, saved snapshot, dirty/recovery state or recent-project identity. The explicit File ▸ Export profiles cover legacy FLA and uncompressed XFL targets.

Library API: `inspect(&Path) -> Result<ImportReport, ImportError>`, `import_project(&Path) -> Result<Project, ImportError>`, `export_fla(&Project, &Path) -> Result<(), ImportError>` and `export_fla_bytes(&Project) -> Result<Vec<u8>, ImportError>`. Accepted uncompressed entry points are the folder, `DOMDocument.xml`, or its `PROXY-CS5` `.xfl` stub.

## XFL conversion boundary

- XFL topmost-first layers become NeoFlash painter order. Frame duration/blank gaps, keyframe labels and nested library references are retained.
- Layer `visible` is an authoring eye-toggle, not the Flash publish decision. The current profile's `PublishFlashProperties/InvisibleLayer` (`0` or `1`) controls hidden-layer publishing, defaulting to inclusion when the field or publish file is absent. Included hidden root and nested layers become visible NeoFlash layers with a warning that their original eye-toggle state is normalized. With inclusion disabled, hidden artwork remains editable on hidden layers and is excluded from playback. Hidden-layer frame scripts or labels block in this mode because the model cannot retain their publication ownership; no source is silently executed or discarded. An excluded layer extending beyond the published layers also blocks until its published duration can be established. Unsupported artwork on excluded layers is still validated.
- A single publish profile may omit `current`; multiple profiles require exactly one explicitly current profile. Language and hidden-layer policy come from that same profile. Malformed, nested, namespaced, repeated or misplaced policy fields and ambiguous profile selection block conversion. `InvisibleLayer` is the verified CS6 XML field; a speculative `IncludeHiddenLayers` XML field is not accepted as an alias. Inactive profiles are reported and not applied.
- Non-singular 2D affine matrices — translation, rotation, scale, reflection and shear/skew (`Transform::from_matrix`, upgrading the project to format 5 when `skew != 0`) — and placement alpha are supported. Singular or zero-scale matrices block conversion with `matrix_singular`. The stored placement matrix is retained; custom authoring pivots are reported as a warning.
- Solid-fill rectangle/oval **primitive objects** are supported. `DOMShape` preserves the single-`ElementKind::Path` representation for simple single-solid-fill straight convex polygons and single-stroke open/closed paths, and converts general vector artwork into `ElementKind::PaintedPath` (`FillRule::NonZero`, format 5): concave, collinear and self-intersecting contours, holes and multiple disjoint islands, quadratic Bézier curves (`[`/`]`) on filled and stroked edges, interior seams (`fillStyle0 == fillStyle1`), multiple fill and stroke styles, partial stroke coverage, and `<LinearGradient>` / `<RadialGradient>` paints (with `focalPointRatio`, 1–15 `<GradientEntry>` stops and `<Matrix>` transforms) on fills and strokes. Edge coordinates accept signed 32-bit integer twips, decimal fractional twips and `#HHHHHH.HH` signed 24.8 fixed-point hexadecimal twips (`1 px = 20 twips`); move-selection bits (`S1`–`S7`) warn with `xfl_shape_selection`, and auxiliary `cubics` editing handles warn with `xfl_cubic_editing_metadata`. Non-pad `spreadMethod` / `linearRGB` gradients, `<BitmapFill>` (shown as neutral gray) and patterned strokes (`DashedStroke`, `DottedStroke`, `RaggedStroke`, `StippleStroke`, `HatchedStroke`) import with `xfl_shape_approximated`; hairline (`weight="0"`), non-round caps/joins, non-normal `scaleMode`, `pixelHinting` and `sharpCorners` import as round strokes with `xfl_stroke_rendering`. Limits are 16,384 segments per shape and 65,535 edge-text bytes per `<Edge>`. Unclosed fill contours, dangling style indices, `isFloating="true"`, primitive-object strokes, rounded corners and partial ovals remain blocked.
- A single-run, single-line, left-aligned static text object is supported with its font name, size and color. Text metrics/antialiasing can differ and always produce a warning. Rich/dynamic/input/TLF text and nonzero margins/tracking are blocked. All immediate text/CDATA fragments in `characters` and frame `script` nodes are concatenated in order, including fragments separated by XML comments; normal XML newline normalization still applies. Nested semantic content is not silently discarded.
- Multiple scenes (`DOMTimeline` entries in `DOMDocument.xml` mapped to `Project.scenes` with the first scene as `root`, upgrading to format 6 when more than one scene is present), library folders (`<folders>/<DOMFolderItem>` plus `DOMSymbolItem` `folder` attributes or slash-prefixed symbol names, format ≥ 4), and `layerType` `normal`, `guide`, `mask` and `folder` (with `open` mapped to `collapsed` and `parentLayerIndex` mapped to `parent`, `mask` on masked normal child layers or `motion_guide` on guided normal child layers, format 4/6) are supported. MovieClip instances, 4-frame `Button` symbols (`symbolType="button"` Up/Over/Down/Hit states and `DOMSymbolInstance` button placements with `InstancePlayback::Independent`, warning `xfl_button_track_as_menu` when `trackAsMenu="true"`), Graphic loop/play-once/single-frame modes including nonzero `firstFrame` offsets (`LoopFrom`/`PlayOnceFrom`), and `DOMSymbolInstance` `isVisible`, `cacheAsBitmap`, `blendMode`, accessibility attributes (`hasAccessibleData`, `accName`, `description`, `tabIndex`, `silent`) and `<filters>` stacks (`DropShadowFilter`, `BlurFilter`, `GlowFilter`, `BevelFilter`, `GradientGlowFilter`, `GradientBevelFilter`, `AdjustColorFilter`, format 7; warning `xfl_filters_approximated` on disabled/excess filters or non-instance/button-state child filters) are supported. `<media>` imports `DOMBitmapItem` (`LIBRARY/*.{png,jpg,jpeg}` and `bin/*.dat` binary caches decoded to PNG) with `DOMBitmapInstance` (`ElementKind::Bitmap`, preserving `allowSmoothing`, matrix transforms and classic-tween continuity; non-empty instance names warn with `xfl_bitmap_instance_name`) and `DOMSoundItem` (`LIBRARY/*.{wav,mp3}` and `bin/*.dat` PCM/ADPCM/MP3 caches, warning `xfl_sound_short_read` on truncated streams), and `DOMFrame` imports timeline frame sounds (`soundName`, `Event`/`Start`/`Stop`/`Stream` sync, `soundLoopMode`/`soundLoop`, preset `soundEffect`s, format-7 `inPoint44`/`outPoint44` sound trim bounds, and format-7 custom `<SoundEnvelope>` `<SoundEnvelopePoint>` stereo curves, warning `xfl_frame_sound` on clamped repeat counts, >32 envelope points or >100% envelope gain).
- XFL export validates every resource selected for the media library before writing output. Authored bitmap/sound use is authoritative over a misleading MIME type or filename, but the bytes must still decode as supported PNG/JPEG or PCM WAV/MP3 data. Invalid or unsupported media produces an actionable error and no partial archive; it is never silently omitted. WAV/MP3 inspection is shared by import and export and retains bounded RIFF-chunk and ID3 handling.
- Current exports identify `creatorInfo="NeoFlash"` and write standard direct filter strengths. Marked Adobe/current NeoFlash documents therefore read direct values. Unmarked archives retain the first NeoFlash exporter's historical ×100 compatibility interpretation and report `legacy_neoflash_filter_strength`, preserving their previous appearance while making the ambiguity visible.
- Instance identity is supported within held placement spans and across valid single-instance classic-tween keyframe spans (`tweenType="motion"` placing the same symbol on adjacent keyframes). Later spans after a blank gap receive fresh IDs, so a direct goto across an explicit or implicit blank gap cannot inherit earlier instance state, even when its name/referenceID repeats or XML order changes. Non-tweened adjacent keys that end and place the same library symbol still block with `ambiguous_instance_continuity`, including transitions between layers: without an explicit classic tween, XML index, instance name and `referenceID` alone do not establish continuation versus replacement in this adapter. Different-symbol replacement has fresh placement identity.
- Frame ActionScript text is retained without rewriting, using unambiguous `ActionScriptVersion` 2 or 3 from the selected current profile in `PublishSettings.xml`. Nonempty recognized AS3-only configuration fields are inactive when the document unambiguously selects AS2 and produce warnings; this includes CS6's default AS3 package path/configuration constants. Active document classes/package/library/configuration fields and language ambiguity still block import. The recognized configuration nodes must contain unnamespaced plain text, without attributes or nested elements; all text fragments are checked. Source retention does **not** certify execution compatibility; the separate compiler/exporter checks it.
- XFL classic tweens (`tweenType="motion"`, mapping `acceleration` to `Easing::Linear` when zero or `Easing::Flash { acceleration }`, a single-segment global `<tweens><CustomEase target="all">` to `Easing::CubicBezier`, and `motionTweenOrientToPath` to `Keyframe.orient_to_path`, format 6) and shape tweens (`tweenType="shape"` as `TweenKind::Shape`, format 6) are supported. Broken classic tweens (final keyframe, mismatched endpoints or non-single-element frames) degrade to held poses with `xfl_tween_dropped`; directed CW/CCW tween rotation warns with `tween_rotation` because NeoFlash interpolates shortest-angle rotation; multi-segment or per-property custom eases block with `custom_ease_not_supported`. CS4+ object tweens (`tweenType="motion object"` / `<MotionObjectXML>`) and IK/armature `animationType` layers block explicitly (`motion_object_not_supported`, `layer_animation_not_supported`). Object-attached XFL scripts are retained: NeoFlash's reversible event wrappers restore Click/Load and language exactly, while unfamiliar external handler grammar stays as raw source under the documented Load fallback instead of being discarded.
- Explicitly recognized editor metadata can be omitted with warnings: authoring platform, library Include `itemID`, an empty `PrinterSettings` marker, audited publish-history timestamps/sizes and finite `centerPoint3DX/Y` authoring pivots. The placement matrix remains authoritative; actual 3D transforms are unsupported. `<folders>` parses audited `<DOMFolderItem>` declarations (an empty `<folders/>` container retains its `editor_metadata` warning); only empty `swatchLists` and `swatches` markers are accepted, and nonempty swatch containers remain blocked rather than treating an unvalidated subtree as harmless metadata.
- Unknown semantic elements/attributes, namespaced attributes, foreign element namespaces, missing resources, invalid values and invalid resulting project graphs produce blocking diagnostics. All parsed XFL elements must use the canonical Adobe namespace or no namespace; publish settings must be unnamespaced. Other Flash publishing options beyond language/hidden-layer policy are not carried into HTML5 export and are reported. Recognition of a metadata container does not exempt its contents from validation.

XML is parsed with DTD disabled and a 100,000-node limit. Sources are bounded to 10,000 files, 8 MiB per file and 64 MiB total; directories have a depth limit of 16. ZIP paths and symlinks are rejected without filesystem extraction. Scripts are never executed by the importer.

The original [hidden-layer](../crates/neoflash-import/tests/fixtures/hidden-layers/DOMDocument.xml) and [instance-gap](../crates/neoflash-import/tests/fixtures/instance-gap/DOMDocument.xml) fixtures exercise these boundaries independently of licensed upstream examples. They are synthetic regression sources, not Flash-generated conformance oracles. The former includes hidden red root and blue nested squares; an `InvisibleLayer=0` copy excludes both while retaining the backdrops. The latter jumps directly across a blank frame after assigning distinct properties to two same-symbol instances; its expected HTML5 trace is `fresh placements undefined undefined 1 1`.

Adobe's [publish-settings documentation](https://helpx.adobe.com/animate/desktop/exporting-and-publishing/publish-settings.html) establishes the default inclusion and nested-layer scope. The unchanged CS6 Ruffle FLA supplies the `InvisibleLayer` field spelling. Ruffle's pinned [forward-goto removal handling](https://github.com/ruffle-rs/ruffle/blob/fe6cfc545405b888ebb478ce1c211d63147ca49b/core/src/display_object/movie_clip.rs#L2195-L2215) corroborates that jumping over an intervening removal is not continuous placement; it does not establish XFL `referenceID` matching semantics.

## Native binary conversion boundary

Binary FLA saved for Flash 3 (`Contents` revision `0x14`), 5 (`0x20`), MX (`0x29`), MX 2004 (`0x38`), 8 (`0x3F`), CS3 (`0x43`) and CS4 (`0x47`) imports directly through the Rust core; Java, Python, Flash and an intermediate XFL export are not required. The resulting project is validated and serialized through the normal NeoFlash document model before it is returned. See [decision 0036](decisions/0036-legacy-fla-partial-import.md) for the conversion policy.

**What blocks import** (`can_import: false`): an unreadable or unsafe container, a Contents stream that stops before its library descriptors and document settings, an empty document, or a converted project that fails validation. Everything else imports, and the report lists each approximation as a warning with a location. Repeated warnings are collapsed into one entry per code with a count.

**Converted to model equivalents:**

- Scenes in order (the first is the root timeline; more than one scene uses document format 6), library symbols with their folders, linkage and class names, and source groups as editable one-frame Graphic symbols. A library object and a display placement remain distinct identities.
- Layer order, names, lock/outline state, folders, masks and motion guides (a normal layer whose related layer is a guide gets `motion_guide`). Held/blank frames, labels and layer end markers.
- Classic motion tweens with Flash acceleration or a single global cubic custom ease; shape tweens (`key_mode` low byte 2) as `tween_kind: shape`; Graphic loop/play-once/single-frame playback including first-frame offsets (`LoopFrom`/`PlayOnceFrom`). Offsets beyond the symbol's length wrap for loops and clamp otherwise, with a warning.
- Solid, linear and radial gradient fills and strokes as compound nonzero paths preserving quadratic edges, holes and draw order; bitmaps as PNG resources; uncompressed PCM and compressed Flash ADPCM (`codec_id == 1`, 2/3/4/5-bit mono and stereo decoded to 16-bit PCM) `CMediaSound` streams wrapped as RIFF/WAVE (`audio/wav`) and embedded MP3 streams preserved as `audio/mpeg` resources; `CPicFrame` timeline frame sounds (`Event`, `Start`, `Stop` and `Stream` sync, repeat counts and `0x7FFF` loop-forever, `SoundEffect` presets `0..=6` plus legacy full-span 2-point preset envelopes as format-6 `Keyframe.sound`, and multi-point or partial-span custom stereo envelopes as format-7 `SoundEffect::Custom` with `FrameSound.envelope`); instance matrices, color effects, display filters (`DropShadow`, `Blur`, `Glow`, `Bevel`, `GradientGlow`, `GradientBevel`, and `AdjustColor` → 4×5 `ColorMatrix`) and blend modes (format 7). Color offsets of ±256 saturate exactly like ±255 and are clamped silently.
- Text as a text box with its authored family/face, size, style, alignment, layout values, active display filters, `Dynamic`/`Input` field options (variable binding, max characters, password, selectable, HTML, multiline, word wrap, border/background, auto-size) and multi-run UTF-16 `TextFormatRun`s. Missing installed fonts do not block import.
- Frame and object ActionScript source without rewriting, with the publish language (`Vector::ActionScriptVersion`; Flash 3–MX without that key are ActionScript 1).
- Historical and compiled Actions-panel commands (Flash 3–MX) are translated to ActionScript 1 source: navigation, getURL/fscommand, load/unload, set/setProperty, drag, duplicate/remove, `on(…)`/`onClipEvent` handlers, if/else, loops, with, switch, try, functions and calls. `tellTarget(t)` becomes `with (eval(t))` (assignments to variables the target lacks land on the enclosing timeline, unlike Flash) and numeric `ifFrameLoaded(n)` becomes `if (_framesloaded >= n)`. Commands that cannot be translated stay as marked `// NeoFlash: untranslated FLA action …` comments with their fields, and `fla_actions_translated` reports them; their bodies are commented out with them so they never run unconditionally.

| Missing or undecodable bitmaps, bitmaps beyond the 64 MiB resource or 128 MiB encoded JSON budget | Unresolved bitmap placeholder; no image is invented | `fla_source_bitmap_missing`, `fla_bitmap_skipped` |

**Original source.** Every imported project embeds the exact original FLA as `legacy/source.fla` (split into `legacy/source.fla.partNN` resources of at most 16 MiB when larger) plus `legacy/provenance.json` (schema 2: `source_resources` in concatenation order, `source_bytes`, an FNV-1a digest, descriptors, folders, placements and container tolerances). When the original plus converted media and timelines exceed the project's 64 MiB resource budget or 128 MiB encoded JSON limit, the original is not embedded and `fla_source_not_embedded` says to keep the file; provenance still identifies it. If converted media and vector geometry alone still exceed 128 MiB of pretty-printed JSON, the importer sheds decoded audio resources largest first (`fla_media_not_imported`, `fla_frame_sound`), then decoded bitmaps (`fla_bitmap_skipped`), compacts provenance placement offsets (`fla_provenance_compacted`), and finally replaces excess vector paths in later groups/frames with placeholders (`fla_shape_approximated`). Imported scripts never run during parsing, scrubbing or onion-skin evaluation.

The local MX and CS4 reference documents remain the detailed acceptance cases: all 20 decoded banner bitmaps match the pinned reference converter's PNG pixels exactly, and native preview checks cover the 300×400 variant's nested playback, mask/color transitions and logo/wipe artwork. This establishes those inputs, not general Flash rendering, text layout, interaction or lossless FLA re-export. Private source files and derived artwork are not added as public fixtures.

## Binary FLA reader boundary

`ImportReport.binary_fla` contains the CFB major version, Contents revision, save-target name, storage/stream counts, logical byte lengths and per-stream structural progress. The structural inventory uses numeric stream identifiers and does not emit payload bytes or scripts. Conversion diagnostics can name affected authored layers or symbols. Ordinary compound documents are not classified as FLA merely because their extension is `.fla`: a root Contents stream and a recognized scene/symbol stream are required. An eight-byte signature with no valid container now returns a container error.

The container reader (`legacy/compound.rs`) reads CFB v3/v4 regular streams and mini-streams from a bounded immutable memory snapshot; nothing is extracted, repaired or executed. Like Flash, it follows only the sector chains that live directory entries name. Flash writers left stale data in allocation metadata they never read again — DIFAT slots after the declared FAT count, MiniFAT entries of deleted streams, nonzero reserved stream timestamps ([MS-CFB requires zero](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-cfb/60fe8611-66c3-496b-b70d-a504c94c9ace)), noncanonical red/black colors and chains that continue past their stream. These are tolerated, listed in `BinaryFlaInspection::container_tolerances` and reported once as `fla_container_compatibility`. Errors remain for a bad header, sectors outside the file, cycles inside a chain that is read, chains shorter than their stream, directory loops, overlapping FAT/DIFAT/directory sectors, invalid names, duplicate paths and budget overruns.

Budgets: 512 MiB per file and in total logical streams, 64 MiB per stream, 10,000 directory entries, storage depth 16, FAT allocation 16 MiB and DIFAT 1 MiB. The directory walk reproduces the `cfb` crate's pre-order (siblings in tree order, a storage's contents right after it), so inventory indices and the imported symbol IDs derived from them stay stable. Version 3 stream sizes ignore the high 32 bits, as MS-CFB requires. The MIT-licensed `cfb` crate remains a test dependency for writing synthetic archives.

The MFC reader follows the combined class/object reference table, short/extended tags, null list terminators, schema checks and bounded CString lengths. It stops sequentially at the first unsupported or invalid record in each stream; it never searches for a later byte pattern to guess a boundary. Limits are 50,000 references/collection entries, object nesting 32 and strings 1 MiB. UTF-16 strings are validated; legacy ANSI strings are retained as bytes, and conversion decodes them with the reported Windows-1251/1252 guess. Document budgets are 4 million retained geometry items, 1 million timeline items and 64 MiB per shape.

The preservation reader decodes these bounded record families; editable conversion additionally checks the semantic profile above:

- `CPicObj` revisions 0–5, `CPicPage` 0–7 and `CPicLayer` 0–11: bounded child lists, registration words, layer metadata, guide tables and related-object references.
- `CPicShape` 0–6 with shape-data revisions 0–5: matrix words, fill/stroke tables, straight/quadratic delta edges and auxiliary curves are decoded into preservation IR. This includes inherited geometry inside `CPicFrame` records.
- `CPicFrame` 0–26 except revision 17's pose extension. Durations, optional sound metadata, labels, bounded classic/custom easing records, the shape-tween blend and an optional `CPicMorphShape` reference are retained structurally. A zero duration is a legitimate empty, zero-length key at the start of some layers: it occupies no frame (conversion skips it without moving later keys).
- Actions in every historical form: one inline historical command (frame revisions 4–9, button revision 2), counted historical lists (frames 10–18, buttons 3–4), compiled Actions-panel command lists (Flash 5/MX, in the source container's compiled mode) and source text. These are typed panel commands, not SWF bytecode; each command keeps its exact span and typed operands (`TimelineActions::decoded`). Unknown command kinds or over-maximum revisions stop explicitly.
- `CPicMorphShape` with its `MorphSegment`, `MorphCurve` and `MorphHint` records (start/end matrices, fills, strokes, segments and hints), `CPicRect`/`CPicOval` primitives, `CPicSwf` compiled clips and `CPicVideoStream` placements, and typed component parameter lists. Editable conversion maps compatible hint points into at most 26 ordered `ShapeHint`s; null, incomplete, wrong-type and excess records produce the located `fla_morph_hints_approximated` warning without displacing later valid hints.
- `CPicSymbol`, `CPicSprite` and `CPicButton` placements retain matrix, library identity, names, playback, color transforms, actions, blend mode (`TimelineBlendMode`), filter lists (drop shadow, blur, glow, bevel, gradient glow/bevel and adjust color with typed parameters; convolution and unknown types stop) and known extension fields. Classic `CPicText` retains text/style runs, filters and bounded metadata. Unsupported versions or semantic extensions stop explicitly.
- `CPicBitmap` instance revisions 1–2 without extension records; the separate media decoder converts supported referenced bitmaps.

`structure_complete: true` means the supported reader consumed that stream's entire record structure. It does **not** mean that the artwork was converted or that its semantics were validated. Completed record counts are separate from the ordinary converted-project statistics. Contents reads descriptor lists, settings and the versioned suffix through exact EOF for Flash 3 through CS4. A stream stop is reported; conversion uses only the complete records before it (see the conversion boundary). No project is returned on a blocking error.

### Contents prefix and document settings

`read_binary_contents(&Path) -> Result<BinaryContentsDocument, ImportError>` is a separate, explicit opt-in preservation API. It returns the ordinary inspection plus `BinaryContentsPrefix`: the entire exact `original_bytes` stream (including unread suffix), completed descriptor spans, encoded name spans, a combined MFC identity table, scene/library/media object-ID lists, selected-scene identity, raw counters and optional `BinaryDocumentSettings`. It contains private names, metadata and potentially embedded code/media in its raw bytes. It is not emitted by ordinary `inspect`, and scripts are never executed. Ordinary reports expose only `ContentsCounts`, byte progress and static stop diagnostics.

The prefix accepts every known save target from `0x14` (Flash 3) through `0x47` (CS4); Flash 1/2 stop as unsupported. The reader consumes the versioned header, counted null OLE pointers, reserved fields, null-terminated descriptor lists and selected-scene pointer in their actual order. Short and extended MFC tags share one class/object table throughout the Contents stream. A selected-scene pointer must identify an existing scene-list object. Descriptor targets resolve case-insensitively to the immutable root CFB inventory; missing streams, wrong scene/symbol/media roles, repeated identities and duplicate target ownership stop explicitly. No filesystem path is opened from an embedded name.

Schema-1 `CDocumentPage` revisions 0–25 are traversed except revision 9's historical action lists. Supported media descriptors are `CMediaElem`/`CMediaVideoStream` base revisions 0–7, `CMediaBits` subrevisions 0–4, `CMediaSound` 0–10 and `CSwfPage` (compiled clips, subrevision ≤5: source name, bounds, recursive dependency metadata up to depth 32, then a shared-library record or export name). Nested library metadata 0–7, linkage 0–7/auxiliary 0–3, property lists 0–2/properties 0–3/values 0–8 (including tables), smart-clip movie 0–3 and component 0–8 have bounded versioned layouts; embedded component icon bitmaps (component ≥5) are bounded by their encoded or raster framing and kept undecoded in the descriptor span. Known persistent-data scalar/array/string/blob layouts are traversed. Library parent/item identities, linkage fields, bitmap settings and sound settings (`ContentsSoundSettings`) are typed; the complete nested records also remain preserved inside descriptor byte spans. Other nested properties do not acquire inferred execution semantics. Non-null OLE objects, historical descriptor actions, unknown classes/schemas/revisions/value layouts stop at their first unproven boundary. Length-delimited smart-clip data stays opaque.

Settings are exposed only after the whole supported prefix is read. They retain the original four bounds words in `xmin,xmax,ymin,ymax` order, grid/print flags and words, printer-data spans, background/grid RGBA words and FPS fixed-point word. `size_twips()` computes positive extents with 64-bit subtraction and returns `None` for undefined (`xmin == i32::MIN`), inverted or zero-sized bounds. It never sorts or clamps the stored bounds. Pixel dimensions are twips/20; FPS is the unsigned word/65536, preserving values such as 29.5. Color packing is low-byte R, then G, B, A. Preservation does not round these values; editable conversion accepts the supported stage/color profile and rejects fractional pixel dimensions or frame rates.

After the settings one threshold-gated suffix serves every revision: publish settings (below `0x2C` a single legacy key/value list, exposed as profile 0; from `0x2C` document properties and counted profiles; both end with a word, two strings and a word), extension properties (≥`0x15`), two swatch lists (≥`0x16`), library view (≥`0x18`), folders (≥`0x19`), object properties (≥`0x1A`), next symbol ID (≥`0x1B`), guides (≥`0x1C`), font library (≥`0x1D`), shared-library URL (≥`0x1E`), grid snap (≥`0x1F`), template strings (≥`0x22`), preview frame (≥`0x23`), pixel grid (≥`0x24`), accessibility (≥`0x26`), next media ID (≥`0x27`), the MX–CS4 fields from `0x2E`, shared libraries (≥`0x42`) and writer identity (≥`0x43`). Below `0x43` the stream may end there or carry a compatibility tail of shared libraries and writer identity. `publish_property(0, key)` works for every revision; Flash 3–MX files carry no `Vector::ActionScriptVersion` key, and Flash 8 files have no `Vector::Invisible Layer` key (hidden layers are then published).

`BinaryContentsPrefix.stop` is `None` only after the suffix reaches exact EOF; `Some` carries an explicit failure/unsupported boundary. Suffixes retain typed publish profiles, library folders, document type (≥`0x34`) and metadata XML (≥`0x3A`) spans, with bounded swatches, object properties, accessibility, language selectors, shared-library envelopes and writer identity. Unknown classes/revisions and nonempty embedded font-library records stop explicitly. Stops before settings leave them absent and block conversion; later stops retain the completed settings and suffix records, and conversion continues with defaults (`fla_contents_partial`). No local Flash MX 2004 (`0x38`) document exists; that revision is covered by the threshold logic and a synthetic test only.

Contents has an 8 MiB stream limit, 1 MiB per encoded string, and a shared 50,000-item work budget for references, list members and counted collections. Counts and property-table products are checked before iteration/allocation; remaining bytes bound every read and opaque blob. Descriptor metadata nesting is bounded; auxiliary object nesting is limited to 32 and swatch-list nesting to 16. ANSI strings are preserved without choosing a code page; UTF-16 strings are validated. Compact stream references use their separate bounded encoding, not CString parsing.

### Typed timeline preservation

`read_binary_timeline(&Path) -> Result<BinaryTimelineDocument, ImportError>` is an explicit opt-in API returning inspection, Contents preservation and timeline streams from **one immutable CFB snapshot**. It contains private names, scripts, raw bytes and artwork. It is not printed by ordinary `inspect`; this API itself executes nothing and returns preservation IR rather than a Project. It also retains the original container and indexed raw stream bytes. Each timeline stream retains exact `original_bytes`, stream kind, root object ID, the combined MFC class/object table, pointer records in wire order and typed objects. Contents descriptor `stream_index` links into the same stream inventory.

Object IDs index the stream-local MFC table; class entries occupy IDs too. They are archive identities, not inferred display-instance identities across keyframes. Each new object records its introducing pointer, consumed byte span, body offset and `complete` flag. A newly introduced child has an `owner`; ordered `children` preserve actual child-list references. Related-layer, morph and sound references are separate typed edges and do not create ownership. A layer first introduced through a related-layer pointer can subsequently acquire its actual page ownership. Existing complete identities may be referenced again without creating replacement objects; cycles and invalid ownership remain explicit errors. Consumers must not treat an incomplete graph as an owning tree. Invalid references never become fabricated objects or edges.

Typed fields retain partial base/page/layer/frame/bitmap/instance/text records, duration, key mode, labels, raw registration/matrix/state words, text/style runs, color transforms, source-action metadata and bounded sound/easing fields. A complete shape body is associated with its actual shape or frame object through `shape_index`, including when that enclosing object later stops. Names, labels, source strings and bounded tables are spans into the same original stream; ANSI encoding is not guessed. Action presence distinguishes proven empty/source/compiled/historical content from unknown/unread data. A selected encoding mode alone does not establish nonempty code. Negative compiled-count words remain raw, unsupported and unknown; unsupported command bodies remain unread bytes.

Every stop retains completed descendants and explicit incomplete ancestors; a consumed-progress span is never presented as an inferred full record boundary. The API has an additional shared 100,000-item retention budget for non-null identity entries, objects and pointers across the document, plus the 250,000-item shape retention budget. Each stream also has its fixed table-index-zero null sentinel. A budget stop retains a consistent partial identity graph. Public inspection uses the same bounded native conversion analysis and therefore the same document retention limit. Preservation APIs expose the retained records; the ordinary report exposes counts and diagnostics.

### Preserved binary geometry

`decode_binary_shape(&[u8]) -> Result<BinaryShapeRecord, BinaryGeometryError>` decodes exactly one shape body, beginning at the `CPicShape` revision byte, after its inherited `CPicObj` fields. It rejects trailing bytes. `read_binary_geometry(&Path) -> Result<BinaryGeometryDocument, ImportError>` explicitly retains complete shape bodies encountered before the first unsupported/invalid record in each stream. Each retained body has its stream index, byte offset, parsed fields and exact `original_bytes`. These APIs contain artwork and are separate from ordinary `inspect`, which only emits `GeometryCounts`.

The preservation representation retains:

- Legacy fill words; modern packed values/flags; gradient matrices, stops and extensions; bitmap media IDs; and the known-layout but semantically unresolved `0x20` paint extension.
- Stroke color/width/style words, optional cap/join/scale/hinting fields, miter word and stroke paint. Procedural stroke appearance is not synthesized.
- Edge encoding flags, all three deltas, inherited contour style words, absolute integer start/control/end coordinates and optional line flags. Style bit 15 is retained as selection; the remaining index is checked against its shape-local table. Out-of-range references stop before coordinate data is read.
- Auxiliary point words, optional approximation entries, boundary flags and independently optional start/end boundary points. Unresolved flags remain in the IR and original bytes.

The shape edge terminator determines the boundary; the metadata hint is never trusted as a count. Signed coordinate addition is explicitly wrapping, matching the archive representation. No pixel-unit conversion, alpha normalization, contour joining, fill direction, document placement or unsupported paint approximation is inferred here. A retained shape can belong to an enclosing frame/object that later stops, so inspect the stream's completeness and stop diagnostics before using it. An exact shape body does not establish an editable scene graph.

Shape decoding is bounded to 8 MiB input and 100,000 geometry/style items, with at most 15 gradient stops. Every fixed-width read checks the remaining bytes; counted collections are checked before allocation. Opt-in document retention has a separate 250,000-item budget across streams and stops explicitly when exhausted. Unknown revisions and malformed records are errors, with no resynchronization scan.

### Opt-in solid contour adapter

`adapt_binary_solid_shape(&BinaryShapeRecord, BinaryContourContext { contents_revision: 0x14 }) -> Result<BinarySolidPath, BinaryContourError>` is a pure adapter over preservation IR. It neither invokes the byte parser nor changes `inspect`/`import_project`. The initial boundary is Flash 3 target, `CPicShape` revision 2, shape-data revision 4, exactly one plain solid fill with zero paint flags and explicit alpha 255. Stroke tables, auxiliary curves, multiple/unused paints, gradients, bitmap fills, other revisions and uncertain alpha conventions are blocked. Empty boundaries are not presented as successful converted shapes.

The adapter validates redundant encoding/delta/absolute-coordinate fields even for caller-constructed or deserialized IR. Wrapped coordinate additions, missing styles and unknown line fields stop explicitly. Fill side 0 is reversed; side 1 remains forward. Reversing a quadratic changes endpoints, keeping its control point. Edges with the same nonzero fill on both sides are interior seams, removed with their source indices retained. Selection-bit source indices also remain in the result. Unpainted edges are not silently dropped.

Directed boundaries are joined by **exact integer endpoints**, with one incoming and outgoing edge at every vertex. No tolerance-based snapping, nearest-edge search or arbitrary branch choice is used. An ordered endpoint map makes path geometry deterministic when edge records are reordered. Open/branching/duplicate boundaries, retracing segments, zero-area contours, boundary intersections and nonadjacent touching are rejected. Curve separation and containment use bounded integer/dyadic control-hull subdivision; uncertain cases are explicit errors, including some valid very close curves.

Simple disjoint boundaries are checked for nesting and signed winding. The output uses one compound `evenodd` Path only when `nonzero` would produce the same filled region: oppositely oriented holes and alternating islands pass; same-orientation nested boundaries fail with `fla_contour_winding_unsupported`. This avoids assuming that SWF fill rules alone establish every binary FLA authoring rule.

Edge coordinates are converted from 1/256 twips (raw/5120 pixels); matrix words are `a,b,c,d` signed 16.16 and `tx,ty` integer twips. The complete affine matrix is baked into endpoints and controls, including reflection and shear; the returned Path needs an identity element transform. Exact integer numerators are divided once into core `f64` coordinates. Singular matrices, core coordinate-limit violations, distinct-point collapse and loss/reversal of nonzero control/vertex orientation at `f64` precision are blocked. Ordinary floating-point rounding and renderer antialiasing remain; no claim of pixel-identical authoring round-trip is made.

Limits are 16,384 input edges, 8 MiB original bytes, 200,000 certification steps across pair/nesting/ray checks, and 12 exact quadratic subdivisions. Sorting/map work and allocations are bounded by the edge limit. Pair certification can conservatively exhaust its budget for large dense shapes; it never returns a partially converted path. `BinarySolidPath` includes core Path data, matrix words, ordered source-edge traces, removed seam indices and selection provenance. It contains artwork and remains opt-in.

The original `contour_fixture` example builds binary shape records from synthetic figures, decodes/adapts them and creates a valid NeoFlash Project for native/HTML5 preview. It is **not** a binary FLA document converter:

```sh
cargo run -p neoflash-import --example contour_fixture -- /path/to/new-fixture.neoflash.json
```

The generated original Project was exported and visually checked in the HTML5 browser runtime: its rectangular hole, quadratic lens and reflected/sheared parallelogram rendered as intended, with no console errors. This is a visual check, not a pixel-difference assertion or native editor rendering test. The expected unembedded-font warning concerns the example's Arial labels.

Save-target mapping from the independently researched Contents revision table:

| Contents byte | Save target |
| --- | --- |
| `10`, `11`, `14`, `1B`, `20` (hex) | Flash 1, 2, 3, 4, 5 respectively |
| `29`, `38`, `3F` | Flash MX, MX 2004, Flash 8 respectively |
| `43`, `47` | Flash CS3, CS4 respectively |

Unknown values stay unknown. This identifies the format saved, **not** the application/version that last edited the file. CFB's major version is a separate container property.

## SWF conversion and FLA archive export boundary

`inspect` and `import_project` accept `FWS` (uncompressed), `CWS` (zlib-compressed) and `ZWS` (LZMA1-compressed SWF 13+) movies up to `64 MiB` decompressed, populate `ImportReport.swf` (`SwfInspection`), and reconstruct a validated editable `Project` without executing AVM1 or AVM2 bytecode. A separate `SwfBytecodePlayer` executes a bounded subset for timeline/display-list state, audio commands and trace output. The editor can project that ephemeral display list onto the Stage and seek, step or restart it without mutating the authored project. This is not a complete Flash Player: unsupported bytecode and coercion/event-order differences remain diagnostic, and an unimportable SWF is inspected headlessly without replacing the current document.

- **Container validation and decompression:** rejects declared uncompressed lengths `< 8` or `> 64 MiB`, files exceeding `64 MiB`, `FWS` length mismatches, truncated/corrupt/trailing-byte `CWS` zlib streams, `CWS` streams whose decompressed length differs from the header or exceeds `64 MiB` (streamed in 32 KiB chunks), and `ZWS` headers shorter than 17 bytes or whose `17 + compressed_len` size mismatches the file. `ZWS` payloads are decompressed in memory by a bounded pure-Rust LZMA1 range-coder decoder (`swf/lzma.rs`, adapted from `lzma-rs` v0.3.0 under the MIT License, Copyright (c) 2017–2018 Guillaume Endignoux); corrupt LZMA streams block with `swf_lzma_corrupt`. Inverted or zero-sized stage `RECT` bounds block with `swf_invalid_rect`; truncated headers block with `swf_truncated`.
- **Dictionary, media and timeline reconstruction:**
  - `DefineShape` / `DefineShape2` / `DefineShape3` / `DefineShape4` (2, 22, 32, 83) convert solid, linear/radial/focal-radial gradient (`FILLSTYLE` `0x10`/`0x12`/`0x13`) and clipped/repeating bitmap-quad fills, `LINESTYLE` / `LINESTYLE2` strokes and mid-shape `stateNewStyles` lists into painter-ordered `ElementKind::PaintedPath` / `ElementKind::Bitmap` Graphic symbols (splitting oversized contours above `MAX_PATH_COMMANDS` and reporting non-pad spread, `linearRGB` or arbitrary non-quad bitmap fills with `swf_shape_approximated`).
  - `DefineMorphShape` / `DefineMorphShape2` (46, 84) build 101-frame `TweenKind::Shape` Graphic symbols addressed by `PlaceObject2` `ratio` (`0..=65535` → `InstancePlayback::SingleFrame(0..=100)`).
  - `DefineBits` / `JPEGTables` / `DefineBitsJPEG2` / `DefineBitsJPEG3` / `DefineBitsJPEG4` (6, 8, 21, 35, 90, normalizing legacy `FF D9 FF D8` table glue and un-premultiplying zlib alpha planes to PNG) and `DefineBitsLossless` / `DefineBitsLossless2` (20, 36 formats 3/4/5) become portable `image/jpeg` or `image/png` `ResourceUnit`s.
  - `DefineSound` (14), `StartSound` / `StartSound2` (15, 17) and `SoundStreamHead` / `SoundStreamHead2` / `SoundStreamBlock` (18, 45, 19) decode uncompressed PCM, Flash ADPCM (2/3/4/5-bit mono and stereo → 16-bit WAV) and MP3 streams into `audio/wav` or `audio/mpeg` resources and format-6/7 `Keyframe.sound` entries (`Event`/`Start`/`Stop`/`Stream` sync, repeat counts and custom stereo envelopes); unsupported codecs (Nellymoser/Speex) warn with `swf_sound_unsupported`.
  - `DefineFont` / `DefineFontInfo` / `DefineFontInfo2` / `DefineFont2` / `DefineFont3` / `DefineFontName` / `DefineFont4` (10, 13, 62, 48, 75, 88, 91), `DefineText` / `DefineText2` (11, 33, falling back to placed vector glyph outlines from the embedded font with `swf_glyph_outlines` when `code_table` was stripped) and `DefineEditText` (37, preserving stage instance names and stripping simple HTML tags with `swf_text_approximated`) recover editable `TextBox` or glyph-outline artwork.
  - `DefineButton` / `DefineButton2` (7, 34) with `DefineButtonCxform` (23) and `DefineButtonSound` (17) become 4-frame `SymbolKind::Button` timelines (`Up`/`Over`/`Down`/`Hit`) plus button `ObjectScript`s.
  - `DefineSprite` (39), `PlaceObject` / `PlaceObject2` / `PlaceObject3` (4, 26, 70), `RemoveObject` / `RemoveObject2` (5, 28), `FrameLabel` (43) and `DefineSceneAndFrameLabelData` (86) coalesce per-depth display tracks into held keyframe spans, 1-frame linear classic tweens, multi-scene root timelines and validated pure-vector `LayerRole::Mask` relationships (non-vector or dynamic `clip_depth` masks stay normal layers with `swf_mask_approximated`; filters, blend modes and `DefineVideoStream` placeholders warn with `swf_filters_unsupported`, `swf_blend_mode` and `swf_video_placeholder`).
- **Static AVM1 and AVM2 bytecode decompilation:**
  - AVM1 (`DoAction` 12, `DoInitAction` 59, `DefineButton2` `BUTTONCONDACTION` and `PlaceObject2`/`PlaceObject3` `CLIPACTIONS`) decodes SWF 3–19 action streams into structured AS1/AS2 source (`if`/`else`, `while`, ternaries, `function` / `DefineFunction2` preloaded registers, `with`, `try`/`catch`/`finally`, `tellTarget`, `gotoAndPlay`/`gotoAndStop` folding and button/clip event handlers); unrecognized opcodes stay as comments and warn with `swf_avm1_unrecognized`.
  - AVM2 (`DoABC` 72, `DoABC2` 82, `SymbolClass` 76) parses the ABC constant pool, traits, classes/interfaces and method bodies into `ActionScript3` `.as` `SourceUnit`s (`package`, `import`, inheritance, typed fields/constants, methods/getters/setters, `newfunction` closures, `newactivation` captured slots, loops/branches/`try`-`catch`), binds `document_class` and symbol `class_name`/`linkage_id`, and extracts auto-generated Flash IDE timeline classes (`*_fla.MainTimeline` / `addFrameScript`) back onto timeline `FrameScript`s; unrecognized opcodes warn with `swf_avm2_unrecognized`.
- **Provenance, budget guard and `.fla` export:** embeds `legacy/swf-provenance.json` (FNV-1a 64-bit digest, header metadata and tag counts) and `legacy/source.swf` when within the single-resource (16 MiB) and 128 MiB project JSON budgets (otherwise warning with `swf_source_not_embedded` / `swf_budget_shed`). `export_fla` / `export_fla_bytes` serializes any `Project` (including imported SWF and binary FLA documents) into a self-contained ZIP-compressed XFL 2.2 `.fla` archive (`DOMDocument.xml`, `PublishSettings.xml`, `LIBRARY/*.xml`, `LIBRARY/media/*` and `.as` class files; cubic Bézier segments are subdivided to quadratic twip edges and non-representable format-7 metadata is noted cleanly without dropping geometry or scripts). NeoFlash language markers make AS1/AS2/AS3 object-script event wrappers reversible on its own `.fla` round trip; unknown external wrapper grammars retain the conservative Load/raw-source fallback.

## Legacy format research and conversion routes

Historical FLA is an authored object graph inside a compound document. Reading its streams does not recover an editable project by itself. Keep these layers separate:

| Layer | What it establishes | What still needs interpretation |
| --- | --- | --- |
| CFB/OLE container | Named streams, directory entries, FAT/MiniFAT chains and exact logical bytes | No Flash scene, timeline or script semantics. |
| `Contents` | Versioned scene/library/media descriptors, stream references, settings and publish/linkage metadata | Descriptor identity, numeric stream suffix and authored library name are different identifiers; counters can include deleted items. |
| `Page N` and `Symbol N` | MFC class/object references and versioned page/layer/frame/object payloads | Instance placement, child order, frame ownership, symbol playback mode and object lifetime. A library stream is not an instance. |
| Geometry, text, actions and media | Typed payloads, styles, source spans and resource references | Paint topology, text runs, language/runtime version, action ownership and complete resource decoding. |

CFB version, Contents revision, MFC class schema and each payload's revision are independent. Preserve them explicitly instead of assigning one layout to every object in a file. Microsoft documents the [MFC reference-table mechanism](https://learn.microsoft.com/en-us/cpp/mfc/tn002-persistent-object-data-format?view=msvc-170); the Flash classes and field meanings remain reverse-engineered. A single archive identity table contains both classes and objects, and references are local to that archive context. Missing numeric stream names do not imply missing contiguous array slots.

For a reproducible external comparison, JPEXS 3.0.0 accepts `convert --format CS6 --container xfl input.fla new-output-directory`. Keep its complete conversion report and the original FLA alongside the candidate output. Its generated XFL can exceed NeoFlash's supported subset, and publication/language settings may remain incomplete. It is a research intermediate, not an automatically accepted import path.

### Interpretation and extension risks

- Keep a source span and confidence for every inferred field. Scanner-recovered strings may locate original code, but only sequential decoding establishes its frame/object owner. Require independent original-byte comparison when using another converter as evidence.
- Cross-check coordinate units and action layouts. External readers disagree on 2560 versus 5120 raw shape units per pixel in some profiles; the current NeoFlash contour profile uses the documented 5120 convention above. Some notes label action-source fields as timeline labels or character IDs. Do not transfer those names into the model without versioned fixtures.
- Preserve source-language and publish-version evidence separately from the save target. Legacy AVM1/AS1-style source must not silently become an AS2 or AS3 document. Instance-name casing matters: Ruffle's [version-dependent AVM1 lookup](https://github.com/ruffle-rs/ruffle/blob/fe6cfc545405b888ebb478ce1c211d63147ca49b/core/src/avm1/runtime.rs#L389-L391) corroborates that changing the SWF target can change case sensitivity. Retaining source text alone does not preserve execution semantics.
- Preserve unresolved media references even in library items that are not reachable from the stage. Stage appearance cannot establish lossless library recovery. Missing installed fonts are a non-blocking environment condition: retain the authored family and style without making font installation a prerequisite for parser work.
- Preserve ANSI bytes until the source code page is established; a converter's Windows-1252 default is not evidence for all historical documents. UTF-16 validation and compact stream-name decoding remain separate concerns.

Extension work must keep structural consumption, model validity, rendering and script behavior as separate acceptance claims. External decoder agreement does not authorize silent omission or establish complete Flash compatibility.

## Verification and migration work

Importer tests cover XML/ZIP/SWF inspection, CFB/MFC boundaries, Contents prefixes and suffixes for every save target, timeline identity and ownership, geometry/contour adapters, static text and bitmap decoding. Native fixtures exercise publish settings, folders/linkage, shared layer references, placement/text/action records, custom easing, partial/truncated records and explicit unsupported stops. Media checks include alpha/padding/palettes, chunked zlib and JPEG boundaries; CFB checks cover regular/mini streams against the reference writer, tolerated stale metadata, and rejected cycles, out-of-file sectors, directory loops and short chains. Conversion tests cover held tweens, partial shapes and approximated text.

Run `cargo test -p neoflash-import` for the importer family, `python3 scripts/check-fla-corpus.py` for the pinned public inputs and `cargo test --release -p neoflash-import --test legacy_samples -- --ignored` for the local Clock/banner regressions. `python3 scripts/survey-legacy-fla.py [folder]` (default: the ignored `examples/old flash files`) prints, for a folder of real documents, how many import, the first blocking cause per refused document and how many documents report each approximation code; use it before and after importer changes and drive the most common codes down. Project validation, native rendering, HTML5 export and script behavior are separate checks. Existing strict XFL boundaries remain separate from the broader binary profile; successful native import does not make an unsupported external XFL intermediate acceptable.

Private local documents are validation inputs, not redistributed fixtures or a general compatibility matrix. Raw inventories, decoded records, comparisons and command logs belong under ignored `target/`; generated exports belong under ignored `dist/`. The aggregate-only corpus/contour inspection examples remain useful for unsupported generations, and do not certify editable conversion or visual fidelity.

Remaining work is listed by the approximation table above: unsupported legacy filter/paint records, GSM/Nellymoser/Speex audio, video, XFL patterned strokes and font/video library assets, motion-object/IK animation, component behavior, Flash 1/2 targets and deeper SWF reconstruction fidelity. Project limits in the shared model (16 MiB per resource, 64 MiB of resources, 128 MiB of saved JSON) bound bitmap-heavy documents and embedding of very large originals; conversion sheds only the explicitly documented media/geometry categories with located warnings, while an unreadable container or missing required settings still refuses the document.

An import result should include:

- The detected format/version and original project provenance.
- A list of imported symbols, instances, layers, frames, assets, fonts and scripts.
- Each unsupported feature with its source location, severity and suggested action.
- Whether a visual/behavioral difference is known, and whether original data was retained.
- Explicit failure for unreadable source, instead of an apparently successful empty project.

Keep the original document unchanged. Never execute imported scripts while inspecting, opening, scrubbing or rendering onion skin. User code runs only in the preview/execution path.

For SWF, compiled content may not retain all original authoring structure. Successful playback does not imply recovered layers, source text, comments, tween intent or original instance naming. An optional Ruffle preview can help validate behavior but does not itself provide FLA/XFL editing or native HTML5 output.

Fixtures should cover multiple original Flash generations. For each fixture, record the producing application/version, available source, expected symbol/layer/frame structure, fonts, script language and whether redistribution is permitted. Use small self-authored fixtures before large third-party projects.
