# Rust-backed AS3 event families

This partial package adds **22 concrete event classes**, **47 method paths** and **69 directly declared properties**. The 47 methods comprise 44 class-specific `clone`/`toString` overrides, `GestureEvent.updateAfterEvent`, `TouchEvent.updateAfterEvent`, and `Event.formatToString`. Constructors, inherited declarations and constants are excluded from that 116-member total. Separately there are 22 constructors, three constant-holder classes, and 84 new constant names: 46 family event constants, nine enum values, and 29 previously absent base Event constants. Existing declarations are not counted as migrations.

The concrete classes are ErrorEvent, SecurityErrorEvent, AsyncErrorEvent, DataEvent, StatusEvent, ActivityEvent, FullScreenEvent, SyncEvent, ContextMenuEvent, IMEEvent, UncaughtErrorEvent, SampleDataEvent, AccelerometerEvent, GestureEvent, TransformGestureEvent, PressAndTapGestureEvent, TouchEvent, GeolocationEvent, NetDataEvent, StageOrientationEvent, ThrottleEvent and SoftKeyboardEvent. The enum holders are GesturePhase, ThrottleType and SoftKeyboardTrigger.

## Reuse and architecture

Individual constructor/default, inheritance, alias, clone and format contracts were read from [Ruffle's event classes](https://github.com/ruffle-rs/ruffle/tree/89a7049965f3090e706265670df309a5128233ac/core/src/avm2/globals/flash/events) at commit `89a7049965f3090e706265670df309a5128233ac`. Relevant source filenames match the class names, with the exceptions below. The existing Ruffle MIT notice in `THIRD_PARTY_NOTICES.txt` applies; its license is preserved with normal exports. No additional engine, dispatcher, GC implementation, ActionScript library or foreign-language runtime was embedded.

The original Rust representation in `crates/neoflash-core/src/as_events.rs` owns validated payload fields and enforces known fields, read-only properties, reference slots and bounded formatting. The deliberately authored JSON tables beside it describe API facts and defaults. `DataEvent.data` aliases the same Rust field as inherited `text`; copying creates independent scalar payloads. `formatToString` adapts Ruffle Event's observed property-order/string-quote algorithm into Rust; it is a display string rather than JSON serialization. The browser reads/coerces each supplied property once and passes its rendered scalar representation to the formatter.

`web/events.js` builds native facades from the Rust schema, connects them to the existing EventDispatcher, and holds browser object references as opaque field slots. Reference payloads retain their intended identity when cloned: SyncEvent.changeList, SampleDataEvent.data, error objects, IME clients, related objects and NetDataEvent.info. The reference graph itself never passes through JSON or Rust serialization. The adapter supplies JavaScript prototypes for the documented event hierarchy; existing network IOErrorEvent now extends the shared ErrorEvent facade, so ErrorEvent/TextEvent type checks work on the existing network event too. This hierarchy correction is not counted as a newly implemented member.

One schema/state mechanism serves all 22 classes, one Rust formatter serves their 44 clone/format API paths, and dispatch reuses the previous hub. These are API-path counts, not 116 independently implemented algorithms.

GeolocationEvent and StageOrientationEvent were implemented from their primary documented contracts because those files are absent at the selected Ruffle revision: [GeolocationEvent](https://airsdk.dev/reference/actionscript/3.0/flash/events/GeolocationEvent.html), [StageOrientationEvent](https://airsdk.dev/reference/actionscript/3.0/flash/events/StageOrientationEvent.html). Additional primary references are the [event package](https://airsdk.dev/reference/actionscript/3.0/flash/events/package-detail.html), [NetDataEvent](https://airsdk.dev/reference/actionscript/3.0/flash/events/NetDataEvent.html), [TouchEvent](https://airsdk.dev/reference/actionscript/3.0/flash/events/TouchEvent.html), and [TransformGestureEvent](https://airsdk.dev/reference/actionscript/3.0/flash/events/TransformGestureEvent.html). Downloaded source snapshots and the implementation inventory are under ignored `target/verification/as-runtime-hour-2/`.

## Supported behavior and boundaries

These are usable authored event values: construct them, read or mutate supported payloads, clone them, inspect the subclass, format them and send them through existing dispatchers. Dispatch retains existing cancellation, listener and propagation behavior. Read-only fields reject writes. SoftKeyboardEvent requires all five documented constructor arguments. Native event subclasses are diagnosed; authors can use composition and listeners.

This package **does not generate new browser/system events automatically**. It does not activate camera/microphone sensors, geolocation, soft keyboards, native IME, context menus, fullscreen, remote SharedObject sync, sample-audio capture, NetStream metadata callbacks, uncaught-error capture or gesture recognition. Those producers need their own subsequent browser integration. Named event constants do not imply that an associated subsystem exists.

Gesture and touch coordinates use the existing display hub's coordinate conversion when dispatched on a display target. Before dispatch, or through an ordinary standalone EventDispatcher, this profile reports local coordinates as stage coordinates. Stage coordinates are captured at dispatch; complete live-coordinate behavior and cross-sandbox accessibility are not claimed. Gesture/Touch `updateAfterEvent` uses the publication's real render-request hook; absent hooks produce a diagnostic. It does not create a separate animation clock.

TransformGestureEvent supports the historical constructor through `shiftKey`; the newer velocity/directional-tap additions and further constructor arguments are outside this batch. PressAndTapGestureEvent supports the same historical modifier range. The pinned Ruffle implementations note historical formatting faults for these two classes; NeoFlash emits useful structured field text instead of emulating those faults. GestureEvent commandKey/controlKey fields and constructor parameters are present. TouchEvent supports the historical constructor through shiftKey, including NaN defaults, and the corresponding 14 properties. Later timestamp, intent, cancellation and additional modifier extensions are not claimed. TouchEvent.getSamples/isToolButtonDown diagnose their missing browser adapters rather than returning fabricated values; they are excluded from all totals.

Object-reference fields enforce null/object shape, SyncEvent enforces Array, and SampleDataEvent uses the injected ByteArray brand. Complete native Error/InteractiveObject/IIMEClient type validation and historical coercion, sandbox and exception-ID fidelity remain incomplete. Numbers support finite values and explicit non-finite representations. Strings use the Rust UTF-8 payload profile; full preservation of isolated UTF-16 surrogates is outside this event layer. Payload JSON and formatted output are bounded to 1 MiB, formatter class names to 256 bytes and formatting to 64 fields. No user reference is serialized or recursively inspected for cloning.

## Verification scope

One grouped Rust test, `as_events::tests::event_payload_family`, traverses the schema and checks representative aliasing, copy independence, read-only behavior, failed-write atomicity and formatting. It is part of the coordinator's shared batch, not a separate per-class test suite.

`examples/runtime-event-families.nflash` is an ordinary authored AS3 project. Its single scenario constructs all 22 classes, dispatches clones through EventDispatcher, and checks typed hierarchy, identity-bearing payloads, the existing IOErrorEvent hierarchy, data/text aliasing, cancellation, grouped mutations, read-only properties, constants and formatting. One Run again button repeats the family scenario; ordinary publication Restart rebuilds it. Actual build/browser outcomes belong in the hour report and ignored evidence; this provenance file does not independently claim a browser pass.
