# AS2 LocalConnection and HTTP remoting

This package adds a bounded browser profile of LocalConnection and AS2 NetConnection AMF0/HTTP calls. It accounts for **12 new declarations**: five methods, three properties, two callbacks/events, one constructor and one class. Two existing declarations are extended, and the already working local NetConnection.close path has a separate stale-audit correction. The existing NetConnection class is accounted for in the coordinator's class review, not counted here again.

The shared Rust module `crates/neoflash-core/src/as2_connections.rs` owns message validation, serialization envelopes, channel naming, pending call identities, delivery acknowledgement, duplicate suppression, timeout/retry state and reset. It reuses the existing Rust AMF0 graph codec. `web/as2-connections.js` retains authored object/function identities and connects BroadcastChannel, Web Locks and the existing HTTP transport; it does not implement another AMF codec or embed an ActionScript engine. No runtime dependency, AS3 facade, native editor UI or FLA change is introduced.

## Local browser messages

A LocalConnection can connect a named receiver, send method arguments, close the receiver, read the exact publication hostname and receive delivery status. Argument values use actual AMF0 bytes, including the shared codec's record/array cycles and identity. Status success means that the named receiver accepted the message, not that its authored method existed or returned successfully. Invalid methods/arguments return false; unknown or unavailable receiver names produce a delayed error status.

The browser profile is deliberately same-origin and confined to the current browser profile. It requires BroadcastChannel and Web Locks in a secure context; localhost is supported. `isPerUser` reads true, accepts true before the first connect/send/close and locks afterward. Machine-wide false scope, other browsers/projectors, superdomain routing and cross-origin permissions remain unsupported. `allowDomain` and `allowInsecureDomain` explicitly diagnose; neither is promoted. Underscore-prefixed names remain origin-isolated here.

Web Locks claim names across browser contexts asynchronously. `connect` returns false for invalid names or an existing reservation in this publication. Otherwise true means the reservation request was accepted; an explicit `onStatus` notification with `operation="connect"` reports whether the browser actually acquired the exclusive name. This additional notification is a NeoFlash browser adaptation, not historical synchronous cross-process reservation parity. Authored code can send immediately; Rust retains and retries pending messages until the receiver claims its name. The regular send status has `operation="send"`.

Limits are 256 LocalConnection objects and pending messages per publication, 40 KiB serialized argument bodies, 1024-byte names/methods, a two-second acknowledgement window, and ten-second duplicate retention bounded to 4096 message IDs. Restart releases locks, closes the channel, cancels retries, clears state and invalidates old callbacks. There is no persistence, cross-origin discovery or exactly-once guarantee across browser crashes.

## Real AMF0 HTTP calls

An AS2 NetConnection can connect to an HTTP(S) endpoint and invoke `call(method, responder, ...arguments)`. Rust produces a headerless AMF0 remoting packet with one message, the remote target and a unique response URI. The browser posts it as `application/x-amf` through the existing request transport. Rust verifies the returned packet, URI and complete AMF body, then routes `/onResult` or `/onStatus` to the responder object. It never fabricates a server response. Transport and malformed-packet failures report NetConnection.Call.Failed through the connection's onStatus callback.

`uri` exposes the configured HTTP endpoint; `isConnected` remains false for HTTP remoting, which has no persistent Flash Media Server connection. Existing `connect(null)` local video behavior is retained by the AS2-only LegacyNetConnection adapter. `close` aborts pending requests and invalidates their replies, while preserving the existing video connection lifecycle. Switching endpoints cancels previous requests. A call is limited to a 2 MiB packet and at most 32 pending calls per connection, also subject to shared browser transport limits.

Only AMF0, one response message and headerless envelopes are accepted; unknown-length response bodies are bounded and decoded completely. AMF3 envelopes, headers, class aliases, streaming/multiplexing and server-to-client callbacks remain unsupported. Browser CORS and network policy still apply. `protocol` remains missing because its historical values describe RTMP transport; no fake RTMP or invented HTTP value is returned. XMLSocket's raw TCP contract and remote SharedObject/RTMP are not simulated with an incompatible WebSocket substitute.

## Provenance and verification

The contract references are Adobe's mirrored [LocalConnection](https://open-flash.github.io/mirrors/as2-language-reference/LocalConnection.html) and [NetConnection](https://open-flash.github.io/mirrors/as2-language-reference/NetConnection.html) documentation. Individual local-message status and AMF remoting envelope/lifecycle contracts were studied in the MIT option of [Ruffle at 07d3e430631333f80f754df01a968bdcd80d98c5](https://github.com/ruffle-rs/ruffle/tree/07d3e430631333f80f754df01a968bdcd80d98c5), `core/src/avm1/globals/local_connection.rs` and `core/src/net_connection.rs`. The implementation is adapted to our shared graph codec and browser services; no Ruffle VM, GC or transport subsystem is embedded. Existing MIT attribution remains in THIRD_PARTY_NOTICES.txt.

Downloaded reference files and their pinned SHA-256 manifest remain under ignored `target/verification/as2-runtime-two-hour/connections-reference/`. Their hashes are `406f1e16570cae571bc428fda7959b45f0b2247ba79b33e2d3f5f1217b4e0a11` and `9ef3853f6e373747395b522e666309ef26de217f236e15a78b7884f5b2210814`, respectively. Protocol framing, state tables and limits are native Rust; the existing AMF value codec retains its own provenance.

There is **one new grouped native test function**, `as2_connections::tests::as2_connections_family`, covering channel/AMF delivery, duplicate acknowledgement, retry/timeout, remoting packets and cancellation. It passed in the coordinator's shared affected native batch. The unchanged 90 execution fixtures and 24 workflows passed their single shared delivery runs; this package did not launch its own duplicate cycle. The coordinator observed **9 passed / 0 failed** initially and **13/0** after the actual AMF HTTP batch. Two same-origin browser tabs exchanged A↔B messages, then closed channel A and reclaimed it in the other instance. These observations establish the exercised browser transport profile, not cross-origin or original Flash transport parity.

`examples/as2-connections-batch.nflash` is one authored HTML5 family. It combines five initial LocalConnection groups, four grouped [primitive-box observations](AS2-BOXING-BATCH.md), paired-page receiver controls and four real HTTP remoting groups. The optional local fixture POST `/__as2_amf` echoes the request's AMF argument body through `/onResult`, or returns a genuine AMF status object for `demo.fail`. A static file server cannot provide that route. The delivery-only fixture helper remains under ignored target; it is not a deployed backend or part of the runtime.
