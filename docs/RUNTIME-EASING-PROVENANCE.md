# Scripted easing and Tween Rust family

The one-hour AS2/AS3 continuation adds scripted easing functions and a bounded Tween service. It does not change the native editor or timeline document format. All new easing equations and tween time/value/state calculations live in `crates/neoflash-core/src/as_easing.rs`. `web/easing.js` only exposes the ActionScript classes, binds target properties, and uses the existing Timer/Event host facilities.

The easing equations are individually translated and adapted from [Robert Penner's classic equations in tweenman-as3](https://github.com/danro/tweenman-as3/blob/f28c395213c021be9d64cc3c4e4c196c69b5f69e/Easing.as), pinned at `f28c395213c021be9d64cc3c4e4c196c69b5f69e`. The source carries Robert Penner's BSD-3-Clause notice. The exact notice is retained in `THIRD_PARTY_NOTICES.txt`, which is included in HTML5 exports. Original source downloads and the source hash/inventory remain under ignored `target/verification/as-runtime-hour/easing/`.

Adaptation retains the classic `(time, begin, change, duration)` signature, polynomial/trigonometric/bounce formulas, Back's optional overshoot and Elastic's amplitude/period defaults. Rust uses shared kernels for aliases and direction variants; it rejects non-finite input/output and nonpositive durations explicitly. Penner's ActionScript source is reference material only and is not compiled or shipped. No Tween.js, Tweenman or other animation engine is embedded. The unused alternative Tween.js source download is not part of the delivered implementation.

The repository's complete ActionScript catalogue confirms the public names: `mx.transitions.easing` has 19 methods, `fl.transitions.easing` has 19, and `fl.motion.easing` has 34. These **72 API paths share 11 mathematical families and 31 distinct curve kernels**. Four Linear/None method names share the same linear calculation; repeated package names are not independent algorithms.

The Tween lifecycle is original NeoFlash Rust code implementing a bounded documented public profile. A single Rust state type supports both `mx.transitions.Tween` and `fl.transitions.Tween`. Native wrappers hold only browser target references, callbacks and Timer handles. Per-publication generation invalidation stops timers and frees Rust handles on Restart/dispose. There is no separate scheduling loop or serialized browser reference.

Additional delivered catalogue names are 10 AS2 Tween methods, nine AS3 Tween methods, five AS2 Tween properties, twelve AS3 Tween properties and two TweenEvent properties. Constructors (three), TweenEvent constants (six) and event names (five AS2 callback events/six AS3 dispatch events) are counted separately. Inherited EventDispatcher methods and bridge listener helpers are not counted again. Total method/property additions are 91 methods and 19 properties; no existing implementation was migrated and no language syntax was added.

`examples/runtime-easing.nflash` is one ordinary mixed AS2/AS3 source project. It exercises all easing paths, representative interior values, tween stepping/seeking/reversing/retargeting, property changes, callback/event routes, and two actual seconds-based marker animations. Its buttons repeat the grouped scenario or restart motion; the normal export Restart is the lifetime boundary. Core verification is one grouped test, `as_easing::tests::scripted_easing_family`. Compilation and browser acceptance are recorded by the coordinating delivery report; this document does not substitute authored assertions for executed evidence.

Partial boundaries: finite numeric inputs/results, positive duration, FPS greater than zero through 240, up to 2,048 Tween instances per publication, and built-in easing/CustomEase.getValue function identities only. Arbitrary authored easing callbacks, native subclass initialization, exact historical event ordering/coercion, fractional frame catch-up, infinite/zero-duration behavior, and full broadcaster conformance remain outside this profile. `nextFrame/prevFrame` require a stopped frame-based tween. Browser timer throttling applies to seconds-based motion. `isPlaying` is read-only in this profile; changing it directly is not implemented. Target setters are ordinary host mutations and are not rolled back if authored setters throw.

The same delivery also adds the four AS2 callback timer globals and four `flash.utils` AS3 callback timer functions: `setInterval`, `setTimeout`, `clearInterval` and `clearTimeout`. These **eight new function paths** use one Rust ID/lifecycle registry in `as_timers.rs` and the existing Timer host for scheduling. IDs, limits, delay validation, cancellation and one-shot liveness live in Rust. JavaScript retains only callback/receiver/argument references and binds the existing Timer events. No second timer queue, clock, engine or browser scheduling loop is introduced. Existing Timer implementation paths are not counted as newly converted.

The callback forms and nonzero-ID/shared-cancellation design were adapted after reading Ruffle's MIT implementation at [`89a7049965f3090e706265670df309a5128233ac`, `core/src/timer.rs`](https://github.com/ruffle-rs/ruffle/blob/89a7049965f3090e706265670df309a5128233ac/core/src/timer.rs) and [`core/src/avm2/globals/flash/utils.rs`](https://github.com/ruffle-rs/ruffle/blob/89a7049965f3090e706265670df309a5128233ac/core/src/avm2/globals/flash/utils.rs). The existing Ruffle MIT notice in `THIRD_PARTY_NOTICES.txt` applies. Ruffle's VM/GC objects, priority queue, catch-up loop and complete timer engine were not copied. NeoFlash's bounded registry uses owned integers/booleans, and removes a one-shot registration before entering authored code so reentrant cancellation/Restart cannot deliver it again. The identifier counter survives Restart; old pending callbacks and browser targets are cleared.

AS2 additionally supports `(object, methodName, delay, ...arguments)` with method lookup when the callback fires. The ordinary source example adds one asynchronous grouped check per dialect for argument forwarding, self-canceling repetition, canceled timeouts, cross-clearing IDs and AS2 late method replacement. The single additional Rust test is `as_timers::tests::callback_timer_family`. Partial limits are the existing 0–2,147,483,647 ms finite delay profile, at most 1,024 active callback timers and 1,024 callback arguments by default, positive signed-range IDs, and explicit unsigned-integer clear arguments. The existing browser scheduler rounds scheduled delays up to 1 ms and does not promise Flash catch-up timing. Removed-MovieClip automatic cancellation, complete AVM coercion/error IDs, timer garbage collection and arbitrary callback `this` coercion remain outside the profile. Unsupported callbacks/delays report diagnostics.

The final coherent AS2 addition is `AsBroadcaster`: four methods (`initialize`, `addListener`, `removeListener`, `broadcastMessage`) and the `_listeners` property. The listener-ordering and duplicate/removal/broadcast contracts are adapted from [Ruffle's `core/src/avm1/globals/as_broadcaster.rs`](https://github.com/ruffle-rs/ruffle/blob/89a7049965f3090e706265670df309a5128233ac/core/src/avm1/globals/as_broadcaster.rs), at the same MIT-licensed pin. A small `as_broadcaster.rs` Rust state owns ordered opaque listener IDs, allocation, duplicate detection, removal and bounds. The host binds those IDs to browser objects/functions and resolves the named callback at delivery. Broadcasting captures the entry count and reads live indices, matching the upstream array-order rule without importing its VM, GC, Array implementation or dispatcher.

`AsBroadcaster.initialize(target)` installs the three broadcaster methods and a read-only snapshot getter for `_listeners`. Duplicate registration returns true without duplicating a listener; removal returns whether it found a listener; callbacks receive their listener as `this` plus the supplied arguments. Empty-name broadcasts can invoke function listeners. Reinitialization clears prior listeners, and publication Restart/dispose invalidates all old broadcaster records and releases their Rust state. The same ordinary source project exercises initialization, duplicates/order, argument/receiver forwarding, removal, late method replacement, ignored missing methods, reinitialization and function listeners. Its Rust checks extend `callback_timer_family`; no separate per-method tests are added.

Broadcaster partial limits: up to 1,024 initialized targets and 1,024 listeners per target, object/function listeners, string event names and at most 1,024 callback arguments. Direct `_listeners` replacement or mutation, primitive-listener AVM coercion, historical property flags, constructor behavior and complete prototype mutation are outside this profile. `_listeners` is a frozen snapshot, not a live author-editable backing array. The five catalogue additions exclude a constructor and do not recount Tween's separate broadcaster helpers. Including CustomEase below, final family totals are **96 methods, eight global/package functions and 22 properties = 126 new method/function/property paths** (AS2 43, AS3 83); four constructors, six constants and eleven event names remain separate. There are zero migrated existing methods and zero new language constructs.

The adjacent author-defined curve family is [`fl.motion.CustomEase`](https://help.adobe.com/en_US/FlashPlatform/reference/actionscript/3/fl/motion/CustomEase.html), with `getValue`, `points`, `target` and its no-XML constructor. The canonical package is `fl.motion`, not `fl.motion.easing`. Its programmatic array omits the fixed endpoints (0,0)/(1,1) and holds two controls per cubic plus intermediate anchors. The host retains the authored Point array and marshals coordinates; all segment validation, cubic evaluation and x-to-curve inversion are Rust. `getValue` observes live Point edits. Assigning that instance's stable `getValue` function to Tween captures its current coordinates in the existing Rust Tween state; reassign `func` to apply subsequent curve edits to an existing Tween.

The cubic coefficients and subdivision approach are adapted from [gre/bezier-easing v2.1.0, commit `b9f7a8b623c00ecdbf304c2d542adfa9e5c63872`](https://github.com/gre/bezier-easing/blob/b9f7a8b623c00ecdbf304c2d542adfa9e5c63872/src/index.js), copyright 2014 Gaëtan Renaudeau, MIT. Its exact notice is retained in `THIRD_PARTY_NOTICES.txt`. NeoFlash uses bounded 40-step subdivision and generalized cubic endpoints for multiple segments, without the JavaScript implementation, lookup tables, closures or Newton branch. Source/license downloads remain ignored. This adds one custom-curve solver, separate from the 31 Penner curve kernels already counted.

The bounded CustomEase profile supports zero points as a linear default, or 2/5/8/…/191 Points for at most 64 cubic segments; finite normalized coordinates, strictly advancing anchor x values, control x values inside their own segment, positive duration and time within the duration. XML construction, native subclass initialization, extrapolation and invalid/nonmonotonic segment geometry produce explicit diagnostics. The `target` name is retained for author code; no Motion XML authoring pipeline is introduced. The same grouped Rust test gains representative cubic/multiple-segment values and a malformed-curve check. The same source example gains seven checks, including mutable Points and Tween curve reassignment; its Custom curve button runs an actual Rust-controlled seconds tween. No extra test case or separate acceptance harness is added.
