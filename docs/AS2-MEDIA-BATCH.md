# AS2 progressive video controllers

This batch adds a useful progressive-video profile of `mx.video.VideoPlayer`, `mx.video.FLVPlayback` and `mx.video.VideoError`, plus four AS2 NetStream operations. It contains **151 newly implemented catalogue declarations**: 29 methods, 61 actual properties, 26 events, 32 constants and three class entries. Eight of those constants are incorrectly classified as properties by the source catalogue; they are reported separately and excluded from the **90 new method/property API paths**. There are no new catalogue constructor entries. Four stale catalogue rows cover existing `NetStream.bytesLoaded/bytesTotal` and `Video.clear/smoothing`; those are audited existing behavior, not new implementations. All 155 proposed promotions are bounded **partial** support.

The two component facades share the same Rust implementation. Counts describe named public declaration paths, not 151 independent algorithms. `VideoPlayer.attach(authoredVideo)` and `FLVPlayback.attach(authoredVideo)` are explicit NeoFlash extensions and are excluded from catalogue counts. They attach a controller to an existing authored Video viewport; they do not implement Flash library linkage, component constructors, MovieClip inheritance, a skin or editor UI. The default `getVideoPlayer(0)` returns the actual stable inner VideoPlayer controller.

## Implementation and supported behavior

`crates/neoflash-core/src/as2_media.rs` owns component state transitions, pending seek policy, cue ordering and lookup, playhead event intervals, source validation, volume policy, aspect sizing and stream measurements. `crates/neoflash-web/src/as2_media.rs` only transports JSON to the Rust core. `web/as2-media.js` retains authored object and cue-parameter identities, connects the existing AS2 EventDispatcher and applies Rust effects to the actual media transport and viewport. `web/video.js` supplies native browser metadata, buffering ranges, presented-frame facts, audio/video handles and Canvas captures. No complete engine or new dependency is introduced.

Both controllers load, play, pause, stop, close, seek and resize actual browser video. `autoRewind` requests a real seek to zero on stop/completion; `autoPlay` controls content-path loading; `autoSize` and `maintainAspectRatio` change the authored viewport using real metadata. Width, height, position, scale and visibility map to that viewport. Volume changes the actual media element gain. `playheadTime`, duration, metadata, intrinsic dimensions, preferred dimensions and state come from the real stream. `stateResponsive` identifies the supported responsive states. Seeking is asynchronous; a pre-metadata seek retains one pending destination. The profile does not emulate Flash's full command queue.

The component dispatches actual ready, metadata, playhead, playback, buffering, seek, rewind, completion, close, resize and volume events through AS2 EventDispatcher. Event objects carry the controller target and default player index. The shared inner VideoPlayer receives its documented event subset. Bundled resources expose their known encoded byte counts and terminal progress; HTTP progressive byte counts remain explicitly unsupported because the browser controls that download. `progressInterval` is therefore not promoted. `isLive` and `isRTMP` truthfully report false for the supported finite progressive sources. The version string identifies NeoFlash, never a fabricated Adobe version.

ActionScript cue points can be added, removed, found by name/time, located at or before a time and traversed by matching name. Rust rounds times to milliseconds and orders equal times by UTF-16 name, then insertion order. Parameter objects retain their original identity in the host. Returned lookup arrays are bounded snapshots; replacing content invalidates their continuation handles. Removing a cue removes the first matching cue, following the detailed `removeASCuePoint` reference rather than contradictory prose in the `addASCuePoint` entry. Forward playback dispatches crossed cues; seeking does not manufacture playback cue events. Content replacement clears authored cues. There are at most 1,024 live cues and 4,096 cue identities per controller session.

AS2 NetStream adds `receiveAudio(Boolean)` as a real per-stream audio gate and `receiveVideo(Boolean)` as a real presented-frame freeze/resume gate. Suppressing video does not promise to stop the browser downloading or decoding the source. Numeric FPS selection is unsupported. Rust computes `bufferLength` from contiguous browser TimeRanges starting at the current playhead. Rust computes `currentFps` from recent native presented-frame counts and timestamps; it returns zero while paused, disabled or without a recent measurable interval. Browsers without `requestVideoFrameCallback` receive an explicit diagnostic rather than a guessed FPS. These additions are on LegacyNetStream only; the AS3 NetStream public surface is unchanged.

## Boundaries and lifecycle

Sources must be finite, browser-decodable progressive media, including bundled MP4/WebM and permitted HTTP(S) sources. Actual codec support, CORS and user-gesture playback rules belong to the browser. There is no Flash FLV/F4V decoder, RTMP/FMS server, live stream, SMIL playlist, bitrate selection, embedded FLV metadata cue parsing, navigation cue seeking, multi-player skin, component button/bar controls or Flash security-policy emulation. Their APIs remain missing or explicitly diagnosed; returning a constant is never used to claim server support.

The component-controller `bufferTime`/`setBufferTime` surface, `idleTimeout`, custom network managers and arbitrary transforms are not silently accepted. The later bounded [AS2 runtime batch](AS2-CAPTURE-BATCH.md#related-progressive-netstream-extension) adds `bufferTime`, `setBufferTime` and `onPlayStatus` to the underlying AS2 NetStream; it does not automatically expand the controller API. Skin-only events and inspector-only `cuePoints` are not promoted. The `RESIZING` constant is available as a value, but synchronous viewport updates do not claim an asynchronous resizing state. The default player cannot be deleted through `closeVideoPlayer(0)`; that method only diagnoses the documented invalid operation and is not counted as implemented.

The existing four-stream publication limit, 1920×1080 decoder limit and 16 Mi retained video-pixel bound remain in force. Restart frees both component and stream Rust policies, releases object/cue references and native media handles, removes owned bindings and invalidates queued callbacks using generation and stream sequence checks. The same cleanup handles dispose and shared runtime failure. The ordinary example uses three actual streams and remains silent.

## References and validation

Public contracts were checked against Adobe's [AS2 Components Language Reference](https://web.archive.org/web/20130325184910id_/http://livedocs.adobe.com/flash/9.0/main/flash_as2_components_reference.pdf), notably pages 548–690 and 694–743, and the archived Adobe [AS2 NetStream reference](https://open-flash.github.io/mirrors/as2-language-reference/NetStream.html). The already downloaded component reference stays under ignored `target/actionscript-reference/components/`; its SHA-256 is `95a200ff72acb178048b92ee00a3fec7aba69c3c808b63a3df42ab32d48c7b01`. No reference prose or source example was copied into production code.

The compatible MIT option of [Ruffle](https://github.com/ruffle-rs/ruffle/tree/07d3e430631333f80f754df01a968bdcd80d98c5), pinned at `07d3e430631333f80f754df01a968bdcd80d98c5`, informed individual NetStream pause, seconds/milliseconds and callback contracts through `core/src/avm1/globals/netstream.rs` and `core/src/streams.rs`. Existing Ruffle attribution remains in `THIRD_PARTY_NOTICES.txt`. The state/cue/measurement algorithms here are project implementations; upstream unimplemented stubs were not imported or counted as support. Source downloads and their hashes remain in ignored `target/verification/as2-two-hour-2/media-sources/`.

One grouped native test, `as2_media::tests::as2_media_family`, passed. It covers state/metadata, dimensions, cue ordering/identity references, seek policy, throttling, rewind, invalid protocols, receive gates, contiguous buffering and presented FPS. The same test was extended once for the coherent stream slice and rerun after that code change; the test count remains one. JavaScript syntax passed. No independent shared-suite or WASM-build loop was run for this package.

`examples/as2-media-batch.nflash` is an ordinary AS2 source project using the existing original four-second H.264 fixture. Expected startup is `AS2_MEDIA_READY 12/12`. Physical Play adds actual FPS/freeze/resume acceptance (`AS2_MEDIA_PLAYBACK 13/13`), two cue callbacks and completion. Pause, seek, stop, close/reload and Restart remain available in the export. The coordinator observed READY 12/12, physical Play with PLAYBACK 13/13 and actual 20 fps, two cue callbacks, natural completion, auto-rewind to zero, and READY 12/12 after Restart in the real browser. The sample was silent: audible gain/quality and the unclicked control/error branches are not independently verified. The exact baseline-relative inventory is ignored `target/verification/as2-two-hour-2/media-inventory.json`.


The later [runtime delivery](AS2-RUNTIME-TWO-HOUR.md) extends this same example for the underlying AS2 NetStream buffer target and onPlayStatus completion. Its separately dated browser result is READY 12/12, physical playback 13/13 with measured 23.18 fps and freeze/resume, then 14/14 after the raw completion callback, with one raw-stream completion, one controller completion and two cues. The silent sample does not add audible-quality evidence.
