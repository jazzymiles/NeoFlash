Full Flash replacement is the product objective. The stages below are independently reviewable deliveries; completion of one does not imply feature parity.

| Stage | Scope | Acceptance |
|---|---|---|
| M0 · foundation | Versioned document, symbols, deterministic evaluation, runtime, script/compiler boundaries, tests and repository | Shared Rust behavior is exercised natively and as real WASM |
| M1 · authoring preview | Classic desktop workspace; basic shapes/text; nested symbols; keys/easing/onion; actions; save/open; HTML5 test movie | User can create/edit/save/reopen and run an interactive nested animation |
| M2 · daily editing | Complete selection/transform tools, bezier/pen/brush, snapping, groups, layer folders/masks/guides, span and multi-frame operations, autosave | Real Flash workflows are reproduced using keyboard/mouse without workarounds |
| M3 · portable text and media | Font embedding/subsetting/outlines, text layout, bitmap/SVG/audio/video imports, media synchronization | Export has predictable appearance and media playback on clean machines |
| M4 · modern web | DOM components, accessible text/forms, responsive layout and breakpoints, browser API bridges, module imports | One project can publish an accessible responsive site/application and Canvas game/animation |
| M5 · language compatibility | Complete AS2/AS3 syntax, semantics, classes, namespaces/E4X, events and supported Flash APIs with conformance corpus | Each claimed feature has native/web tests and a documented result against references |
| M6 · legacy projects | XFL breadth; binary FLA reading; SWF AVM1/AVM2 playback and structured import strategy | Provided legacy corpus has repeatable per-file results with no silent loss |
| M7 · release quality | Performance, accessibility, macOS integration, packaging/notarization, crash recovery, migration and extension APIs | Signed tested releases and documented compatibility/performance budgets |

The initial commit addresses M0 and part of M1, with an initial importer and compatibility harness. Subsequent increments add Light/Dark themes, persistent panel visibility and detachable native Tools/Timeline/Actions, pen/pencil/point editing, compound vector paths, cross-layer multi-selection and Free Transform, object clipboard transfer with nested symbols, authored Button/Image metadata, ActionScript functions and structured exceptions, and bounded binary FLA shape, Contents and typed timeline preservation. A separate strict solid-contour adapter produces core paths; complete binary documents remain blocked. A pinned public FLA corpus now checks 14 honest refusals, six original fixture imports and one unchanged real CS6 FLA whose published HTML5 matches the original 17-line trace. M2–M7 are not complete. Order can overlap: language and legacy work continue while the editor matures. No arbitrary completion date is promised.

The current user priority is breadth first: bring the main subsystems to working partial support through large coherent deliveries, then deepen conformance. Develop project scripting, events/display behavior, assets/imports and authoring workflows in parallel where file ownership permits. Validate each batch with representative ordinary HTML5 scenarios and one shared regression pass; individual API edge cases do not each trigger a lengthy browser cycle. Shared breakage, crashes and content/data loss block a delivery; other failures remain explicit follow-up work. There is no fixed numerical batch size.

The first P0 increment covers Boolean MovieClip visibility, fresh replacement state, bounded hidden-layer policy/placement guards, distinct parseInt profiles and AS3 toFixed precision limits. Chrome and in-app browser observations accompany those tests. The next integrated family adds project source files and linked AS3 classes, Stage/EventDispatcher and broader MovieClip/DisplayObject behavior, including bounds, traversal, coordinates, rotation and void timeline results. New native/browser observations are recorded separately from compiler/host execution. Neither increment completes M5 or M6.

Background language work proceeds in coherent families. The a05a08d collection/string/plain-text batch has independent bounded HTML5 evidence; the a3fedc3 AS2 project/classic-input batch now has independent bounded HTML5 evidence, including the shared mouse-click correction. Geometry and timers now share one verified export/WASM/browser workflow. Dynamic display/Graphics and resource documents follow, with one shared scene graph and explicit lifecycle/resource ownership. Verification cost is controlled: reuse representative scenarios, run one shared regression pass for a delivery, and retain explicit follow-up boundaries instead of multiplying per-method tests.

Progress is tracked in the [reviewed capability ledger](progress/README.md), with a [compact public coverage page](https://jazzymiles.github.io/NeoFlash/progress.html) and [daily history](https://jazzymiles.github.io/NeoFlash/history.html). AS2/AS3 use the [complete declaration catalogue and audit](progress/ACTIONSCRIPT.md), including separate component/framework scopes and review gaps. Other product areas retain bounded capability percentages. Neither metric measures overall Flash parity or milestones completed.

Date, JSON and regular expressions connect resource loading to real scripted web interfaces. The delivered partial profile combines AS2/AS3 UTC calendar calculations, AS3 JSON callbacks/class getter serialization and constructor-based RegExp/String operations, with one shared regression and combined browser workflow. Historical locale/regex conformance and slash literals remain separate follow-ups; this does not shrink the goal to display animation alone.

The delivered runtime family connects Transform/ColorTransform to exact affine matrices, shared-pixel display views and consistent color/alpha behavior through nested instances. The pure authoring evaluator stays separate from script execution; native script preview, 3D and authoring skew controls still need their own work.

Typed Vector models, identity-keyed Dictionary and enumeration now have a coordinated partial implementation. Their shared indexed-reference lowering preserves evaluation order and object identity, connecting existing linked display classes with JSON data workflows. XML/XMLList and E4X remain on the full language roadmap.

The delivered partial XML family connects the Rust parser to publication-owned AS2 DOM and AS3 XML/XMLList facades, portable loading, traversal, mutation and serialization. E4X literals/operators, full namespaces and historical parser behavior remain part of the broader language roadmap.
