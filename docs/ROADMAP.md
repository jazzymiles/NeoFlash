# Roadmap

NeoFlash aims to provide a complete Flash-inspired environment for websites, applications, games and animation, with HTML5 as the primary publishing target. It is currently a development preview. The priority is useful support across the main subsystems, followed by deeper conformance.

## Authoring

Timeline authoring includes compact controls, inline layer rename, drag reordering, resizable layer columns, frame zoom, colored outlines, folders, guides and vector masks. The workspace has four-sided docks with resizable tab groups; the library has preview, folders, search and linkage. SVG/PNG/JPEG graphics can be imported from files or dropped onto the stage. Frame-range selection/clipboard, independent layer ends and explicit global script movement are available with integer-frame baking at edited tween boundaries. Shape tweens morph different contours, motion tweens key independent property tracks with ◆ property keyframes (Motion editor, motion path on the stage, Copy/Paste motion), classic tweens follow motion guides, the Ease panel edits curves, documents can hold several scenes (Scene panel) and keyframes can carry Event/Start/Stop/Stream sounds. Stage rulers, ruler guides, the grid and grid/guide snapping work. Bounce/Elastic and per-property eases, Bézier motion paths, Orient/Snap, shape-hint markers, custom envelopes, decoded timeline waveforms and Test scene are available. Next timeline work includes reversing non-linear easing correctly, preserving scene-local synchronized playback in HTML5, editable curve preservation across range cuts, Edit envelope waveform/trim controls, richer button state-object APIs and the approved alpha-mask mode selector. Geometry and explicit format9 gradient/PNG/mixed masks now share native/HTML5 coverage, including nested and moving sources; the Mask command uses displayed neighboring-layer order. Solo-hidden selection/edits and folder Hide/Lock others behavior still need correction.

The editor uses the locked NF2 interface. The Brushes panel provides built-in and document-local custom presets; Brush properties offer eight tip shapes, document-unit size, smoothing, pressure/tilt input, Lock fill and all five Paint modes. Pencil has Straighten, Smooth and Ink modes, and Customize tools stores the global tool layout. Lasso can split intersected Merge fills, and the Bitmap Fill and Bitmap Properties panels provide bounded authoring paths. Trace bitmap converts a selected image into editable vectors with background preview, colour/curve controls, fill/stroke output, cancellation and one Undo. History can replay, copy and save supported authoring steps as project Commands; arbitrary `.nfsl` scripts and a stable public extension contract remain future work. Asset Warp, advanced Appearance/vector effects, camera/depth/parenting/IK, Deco/Spray, 3D and motion-expression/Wiggler data have tested Rust engines and bounded internal command APIs. The Bone panel persists target, length, degree-based rotation limits and stiffness and runs a bounded solve; its other fields and the Deco/Spray panels remain settings drafts. Most direct Stage gestures remain future work. Remaining controls and planned panels are specified in [NF2-FUNCTIONAL-SPEC.md](NF2-FUNCTIONAL-SPEC.md) and ordered in [NF2-WIRING-PLAN.md](NF2-WIRING-PLAN.md).

Next tool work includes physical tablet-driver acceptance, artistic/pattern brush presets, advanced Pencil stroke styling, broader partial-stroke support and partial-fill erasing. Paint Bucket gap controls, Cut strokes and contour-based Lasso slicing are connected. The compact Brush/Pencil header needs a shared NF2 variant (R-047). Trace bitmap remains bounded approximate vectorization; effects that cannot be preserved are refused.

Multiple document tabs, safe Close/Quit decisions and named-workspace management are available. Each document retains its own edits and Undo; workspace presets store layout rather than the list of open documents. The shared notification host handles partial-stroke refusals and Save/reload errors; visible external-file-change notifications/reload decisions, general import/export notifications and multiple main-window views remain future work. External changes currently set an internal flag only; File → Revert is available. Follow the locked NF2 design and resolve missing controls through its design requests. See [workspace behavior](WORKSPACE.md) for current controls and limits on tracing, merging layers with sounds and grouping across keyframes.

Runtime rich text, auto-size, bitmap fills, cached alpha masks and browser Video already have useful paths; embedded imported timeline spans now publish through the shared scheduler and play automatically in HTML5. |
| Interactive web | Editor/CLI workflows for document publication profiles and network simulation, plus additional publish targets/options. HTML5 size settings and cancellable estimates, DOM layout/forms, breakpoints and JS/TS project modules are available within their documented boundaries. |
| Code authoring | Deeper semantic/type-flow analysis, connected-session expression watches and richer debugger inspection. Advisory AST flow, structured warnings with range/peek navigation, safe fix selection, code folding, Script Assist and connected Chromium Test Movie breakpoints, pause/step, call stacks and read-only locals are available within their documented mapping limits. |
| AS2 and AS3 | Deeper language/coercion/prototype conformance, class initialization and reflection, remaining XML/E4X operations, display/event lifetime semantics and unsupported platform APIs. Partial support remains distinct from full compatibility. |
| Legacy projects | Deepen reported binary FLA approximations, including 3D projection and remaining effects, rich/dynamic text and media; extend the bounded XFL and AS1 profiles. SWF import, source reconstruction and a bounded AVM1/AVM2 interpreter exist; unhandled bytecode and comparison semantics need conformance work, and its runtime display list is not yet projected onto the editor Stage. Complete per-file visual/behavioral comparison with Flash remains open. |
| Platform and release quality | Complete timeline virtualization beyond paint culling, visible external-file-change handling, performance/memory budgets (including a deliberate decision and stress proof before lifting the 100,000 expanded-node document boundary), authoring/published integration for the extended accessibility resolver, Intel macOS verification, broader recovery/migration acceptance, notarized distribution and extension interfaces. |

Individual compatible algorithms may be adapted into the shared Rust core with their licenses and provenance preserved. Complete third-party ActionScript engines are not embedded. Unsupported content must produce actionable diagnostics rather than being silently dropped.

## AS3: Flash Player foundations first

Adapt remaining built-in Flash Player behavior in the order below. The first six stages support ordinary websites, games and timeline animation; local media follows, then cameras, networking and platform services. Each stage should deliver a useful coherent subset before pursuing rare conformance cases. Existing bounded implementations are dependencies, not new implementation tasks.

| Order | Remaining adaptation | Purpose |
| --- | --- | --- |
| 1. Mathematics and numeric values | Remaining ordinary coercion/arity behavior and broader numeric prototype/type fidelity. Numeric Class aliases, int/uint limits and bound numeric method values now have a bounded implementation. | Reliable calculations, coordinates and game state. The Math functions/constants, number formatting and 2D geometry already have implementations. |
| 2. Objects, language and collections | Broader native/prototype mutation behavior, class initialization and typed assignment results; deeper native/interface/namespace reflection and remaining native method-value semantics. Ordinary source-class identity/property/reflection APIs, dense Array insertAt/removeAt, shared Array Class aliases and bound Array trait method values have bounded implementations. Array prototype string functions remain outside that binding profile. | Reusable classes, models and scripts. Existing classes/interfaces/accessors, primitive constructors, Array/String algorithms, Date/RegExp, XML and ByteArray are retained; extend their specific gaps. |
| 3. MovieClip and timeline | Streaming progress, automatic frameLabel events, `FRAME_CONSTRUCTED`/`EXIT_FRAME` delivery and ordinary construction/frame-script ordering. | Multi-screen animations, menus and game scenes. Construction/linkage, play/stop/goto, label navigation, counters and nested clocks already exist. Local label/playback/loaded-frame readback, FrameLabel values, authored multiple scenes with scene navigation and pointer-driven button label states have bounded implementations. Automatic keyboard button activation and tab ordering remain later work. |
| 4. Display list, events and input | Survival of moved authored children beyond source replacement, authored layer-mask migration and native per-child removal callback timing; remaining `SimpleButton` state-object properties; Stage display-list behavior, `scaleMode`/`align`, logical resize and `invalidate`/`RENDER`. | Interactive UI and scene composition. Mixed authored/runtime hierarchy changes and range removal during active source lifetimes, subtree timeline stopping, ordinary event propagation, added/removed events, ENTER_FRAME, keyboard/mouse/focus and timers are existing foundations. |
| 5. Graphics, bitmaps and effects | Deepen stroke/gradient, raster, blend/cache and alpha-mask conformance and complete remaining BitmapData contracts. Runtime bitmap fills and cached alpha masks exist; their missing native authoring controls are tracked above. | Drawing, image effects and 2D games. Existing paths, gradients, pixel IO, draw/filter/PNG and 2D transforms are retained. Stage3D/shaders and advanced 3D remain in stage 8. |
| 6. Text and fonts | Fuller shaping/Flash metrics, IME and remaining layout contracts. Runtime mixed format ranges, `htmlText`/`StyleSheet`, auto-size and font embedding have useful implementations; native mixed-run and auto-size authoring remain open. | Text-heavy sites, forms and dialogue. Plain text, wrapping, formatting and bounded text input already work. Native Flash Text Engine is distinct from the external Text Layout Framework. |
| 7. Local sound and video | Remaining SoundMixer, local playback/mixing/sample APIs and video timeline synchronization. | Soundtracks, effects and file video. Existing Sound/SoundChannel and bounded Video playback are retained. Capture and remote protocols wait for stage 8. |
| 8. External services and advanced Player subsystems | Camera/Microphone, remote networking/streaming, sockets, file dialogs, browser integration/storage gaps, printing/clipboard/system profiles, workers and advanced 3D. | Hardware access, servers, OS interaction and specialized rendering. Existing URLLoader, local SharedObject and ExternalInterface paths are not reimplemented. Browser policy and protocol restrictions require explicit adaptation boundaries. |

AIR-only APIs (filesystem, native windows/processes, SQLite and similar desktop/mobile services) form a far-future backlog with no scheduled adaptation. `fl.*` components, Flex `mx.*`/`spark.*`, TLF `flashx.textLayout.*` and other packaged libraries share that far-future priority: running on Player does not make a library built into Player. Flash Builder is an IDE, and JSFL automates the authoring application; neither is a native AS3 runtime family. Reconsider these tracks only after an explicit priority change. Useful existing library helpers such as easing remain available without moving the entire library into the foundation queue.

The [generated AS3 priority breakdown](progress/ACTIONSCRIPT.md#as3-adaptation-priorities) counts the full catalogue by these stages and deferred tracks without changing implementation evidence. A dated `missing` or `needs_review` entry can already have a newer code path: review that evidence before scheduling implementation. In particular, do not re-add primitive constructors, numeric formatting, MovieClip construction or Graphics line/curve/ellipse methods just because their historical declaration decisions lag the code. A partial class contributes only its remaining contracts to the adaptation queue.

## Coverage and validation

The [compatibility matrix](COMPATIBILITY.md) describes current behavior. The existing [capability registry](progress/DETAILS.md) and [complete ActionScript declaration audit](progress/ACTIONSCRIPT.md) track scope and evidence; no overall Flash-completion percentage is implied.

Representative editor and HTML5 workflows establish user-visible behavior; compiler tests and successful exports alone do not establish visual acceptance. [Verification scope](VERIFICATION.md) records observed boundaries, and the [backlog](BACKLOG.md) tracks concrete unresolved issues. These work areas can progress together; no completion date is promised.
