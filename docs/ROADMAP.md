# Roadmap

NeoFlash aims to provide a complete Flash-inspired environment for websites, applications, games and animation, with HTML5 as the primary publishing target. **Current release: `0.1.0-beta.1` for macOS 15+ (Apple Silicon), with Windows x64 and Linux x64 Technical Previews.** `Preferences ▸ Updates` checks GitHub Releases (`Stable` / `Beta` channels, with opt-in daily checks) and downloads SHA-256 verified platform packages against `SHA256SUMS`; installing or updating `NeoFlash.app` in `/Applications` (or replacing portable archives) remains a manual copy from the revealed verified download with no silent self-replacement, preserving `~/Library/Application Support/NeoFlash` preferences, custom workspaces, recent files and crash recovery. Every platform package includes its media helpers and exact licence evidence; a checksummed corresponding-source archive is supplied beside it, and incomplete evidence stops packaging. The priority is useful support across the main subsystems, followed by deeper conformance.

## Authoring

Main-window dock groups can split in both directions at any depth.

Timeline authoring includes compact controls, inline layer rename, drag reordering, resizable layer columns, frame zoom, colored outlines, folders, guides and vector masks. The workspace has four-sided docks with resizable tab groups; the library has preview, folders, search and linkage. SVG/PNG/JPEG graphics can be imported from files or dropped onto the stage. Frame-range selection/clipboard, independent layer ends and explicit global script movement are available with integer-frame baking at edited tween boundaries. Shape tweens morph different contours, motion tweens give several same-layer objects independent stable-ID property keys, easing, paths and options (selected-object Motion editor, Stage paths and Copy/Paste motion), classic tweens follow motion guides, the Ease panel edits curves, documents can hold several scenes (Scene panel) and keyframes can carry Event/Start/Stop/Stream sounds. Stage rulers, ruler guides, the grid and grid/guide snapping work. Bounce/Elastic and per-property eases, Bézier motion paths (preserved as editable De Casteljau curves across range cuts, splits and reversals), exact non-linear easing reversal on Reverse frames, Orient/Snap, shape-hint markers, custom envelopes, decoded timeline waveforms, decoded stereo Edit envelope waveforms with draggable in/out trim handles, scene-local synchronized Graphic playback in HTML5, Classic/Motion tween dummy-filter interpolation across all eight filter families, Solo-hidden Stage selection/edit protection, folder-aware Hide/Lock others and Test scene are available. Next timeline work includes richer button state-object authoring APIs and large-layer-count header virtualization. Geometry, Alpha and Luminance layer masks share native/HTML5 coverage, including gradients, PNG transparency and nested/moving sources; the Mask command uses displayed neighboring-layer order.

The editor uses the locked NF2 interface. The Brushes panel provides built-in and document-local custom presets; Brush properties offer eight tip shapes, document-unit size, smoothing, pressure/tilt input, Lock fill and all five Paint modes. Pencil has Straighten, Smooth and Ink modes, and Customize tools stores the global tool layout. Lasso can split intersected Merge fills, and the Bitmap Fill and Bitmap Properties panels provide bounded authoring paths. Trace bitmap converts a selected image into editable vectors with background preview, colour/curve controls, fill/stroke output, cancellation and one Undo. History can replay, copy and save supported authoring steps as project Commands. The versioned `.nfext` contract provides bounded, capability-gated proposed transactions against the `0.1.0` host compatibility core; arbitrary `.nfsl` execution and a third-party package registry remain future work. Asset Warp, advanced Appearance/vector effects, camera/depth/parenting/IK, Deco/Spray, 3D and motion-expression/Wiggler data have tested Rust engines and bounded internal command APIs. The Bone panel persists target, length, degree-based rotation limits and stiffness and runs a bounded solve; its other fields and the Deco/Spray panels remain settings drafts. Most direct Stage gestures remain future work. Remaining controls and planned panels are specified in [NF2-FUNCTIONAL-SPEC.md](NF2-FUNCTIONAL-SPEC.md) and ordered in [NF2-WIRING-PLAN.md](NF2-WIRING-PLAN.md).

Next tool work includes physical Wacom and Apple Sidecar tablet hardware certification (`T-235`: deterministic event-level pressure `0.05..=1.0`, tilt-to-nib-angle mapping, consecutive strokes, pen-tip/eraser switching, single-step Undo and `.nflash` round-trip are verified and advertised as **experimental** in `0.1.0-beta.1`), artistic/pattern brush presets, advanced Pencil stroke styling, broader partial-stroke support and partial-fill erasing. Paint Bucket gap controls, Cut strokes and contour-based Lasso slicing are connected. Trace bitmap remains bounded approximate vectorization; effects that cannot be preserved are refused.

Multiple document tabs (including dedicated full-window pure Script Editor tabs for standalone `.as` files alongside `.nflash` documents), safe Close/Quit decisions, external disk-modification banners/reload decisions and named-workspace management are available. Each document retains its own edits and Undo; workspace presets store layout rather than the list of open documents. Multiple main-window views remain future work. Follow the locked NF2 design and resolve missing controls through its design requests. See [workspace behavior](WORKSPACE.md) for current controls and limits on tracing, merging layers with sounds and grouping across keyframes.

Individual compatible algorithms may be adapted into the shared Rust core with their licenses and provenance preserved. Complete third-party ActionScript engines are not embedded. Unsupported content must produce actionable diagnostics rather than being silently dropped.

For HTML5 ad delivery, the next interoperability check is submitting a Criteo-preset creative through the receiving placement’s validator with its actual click convention and byte budget.

## AS3: Flash Player foundations first

Adapt remaining built-in Flash Player behavior in the order below. The first six stages support ordinary websites, games and timeline animation; local media follows, then cameras, networking and platform services. Each stage should deliver a useful coherent subset before pursuing rare conformance cases. Existing bounded implementations are dependencies, not new implementation tasks.

| Order | Remaining adaptation | Purpose |
| --- | --- | --- |
| 1. Mathematics and numeric values | Remaining ordinary coercion/arity behavior and broader numeric prototype/type fidelity. Numeric Class aliases, int/uint limits and bound numeric method values now have a bounded implementation. | Reliable calculations, coordinates and game state. The Math functions/constants, number formatting and 2D geometry already have implementations. |
| 2. Objects, language and collections | Broader native/prototype mutation behavior, class initialization and typed assignment results; deeper native/interface/namespace reflection and remaining native method-value semantics. Ordinary source-class identity/property/reflection APIs, dense Array insertAt/removeAt, shared Array Class aliases and bound Array trait method values have bounded implementations. Array prototype string functions remain outside that binding profile. | Reusable classes, models and scripts. Existing classes/interfaces/accessors, primitive constructors, Array/String algorithms, Date/RegExp, XML and ByteArray are retained; extend their specific gaps. |
| 3. MovieClip and timeline | Streaming progress and historical lifecycle edge cases beyond the tested construction, frame-phase and reentrant-navigation profiles. | Multi-screen animations, menus and game scenes. Phased construction, automatic FrameLabel events, one-frame visits, nested clocks, late EXIT_FRAME work and reentrant retirement are implemented. Scene navigation, metadata and pointer-driven button labels retain their bounded implementations. Automatic keyboard button activation and tab ordering remain later work. |
| 4. Display list, events and input | Survival of moved authored children beyond source replacement, authored layer-mask migration and native per-child removal callback timing; remaining `SimpleButton` state-object properties; Stage display-list behavior, `scaleMode`/`align`, logical resize and `invalidate`/`RENDER`. | Interactive UI and scene composition. Mixed authored/runtime hierarchy changes and range removal during active source lifetimes, subtree timeline stopping, ordinary event propagation, added/removed events, ENTER_FRAME, keyboard/mouse/focus and timers are existing foundations. |
| 5. Graphics, bitmaps and effects | Deepen stroke/gradient, raster, blend/cache and alpha-mask conformance, complete Flash 8–CS6 / Animate Display & Layer Filters (full per-filter parameters, Gradient Glow/Bevel stops, Enable/Disable, Presets, Layer/Keyframe Filters, tween dummy-filter interpolation, and live native Stage preview), and complete remaining BitmapData contracts. Runtime bitmap fills and cached alpha masks exist; their missing native authoring controls are tracked above. | Drawing, image effects and 2D games. Existing paths, gradients, pixel IO, draw/filter/PNG and 2D transforms are retained. Stage3D/shaders and advanced 3D remain in stage 8. |
| 6. Text and fonts | Fuller shaping/Flash metrics, IME and remaining layout contracts. Runtime mixed format ranges, `htmlText`/`StyleSheet`, auto-size and font embedding have useful implementations; native mixed-run and auto-size authoring remain open. | Text-heavy sites, forms and dialogue. Plain text, wrapping, formatting and bounded text input already work. Native Flash Text Engine is distinct from the external Text Layout Framework. |
| 7. Local sound and video | Remaining SoundMixer, local playback/mixing/sample APIs and video timeline synchronization. | Soundtracks, effects and file video. Existing Sound/SoundChannel and bounded Video playback are retained. Capture and remote protocols wait for stage 8. |
| 8. External services and advanced Player subsystems | Camera/Microphone, remote networking/streaming, sockets, file dialogs, browser integration/storage gaps, printing/clipboard/system profiles, workers and advanced 3D. | Hardware access, servers, OS interaction and specialized rendering. Existing URLLoader, local SharedObject and ExternalInterface paths are not reimplemented. Browser policy and protocol restrictions require explicit adaptation boundaries. |

Native AMF0/AMF3 `.sol` and `ByteArray` object exchange is available through the SharedObject byte APIs and browser file facilities, including `Vector.<int|uint|Number|*|T>`, `Dictionary` (`weakKeys` and object/primitive keys) and `IExternalizable` (`registerClassAlias`). Remaining serialization work includes full historical alias/coercion edge cases and RTMP server synchronization.

Raw SWF loading through runtime `Loader.load` / `loadBytes` decodes bounded `FWS` / `CWS` / `ZWS` shapes, sprites, bitmaps, text, timelines and AVM1/AVM2 bytecode into live `MovieClip` content alongside published NeoFlash child bundles; full Flash Player SWF tag and VM edge-case conformance remains open.

AIR-only APIs (filesystem, native windows/processes, SQLite and similar desktop/mobile services) form a far-future backlog with no scheduled adaptation. `fl.*` components, Flex `mx.*`/`spark.*`, TLF `flashx.textLayout.*` and other packaged libraries share that far-future priority: running on Player does not make a library built into Player. Flash Builder is an IDE, and JSFL automates the authoring application; neither is a native AS3 runtime family. Reconsider these tracks only after an explicit priority change. Useful existing library helpers such as easing remain available without moving the entire library into the foundation queue.

The [generated AS3 priority breakdown](progress/ACTIONSCRIPT.md#as3-adaptation-priorities) counts the full catalogue by these stages and deferred tracks without changing implementation evidence. A dated `missing` or `needs_review` entry can already have a newer code path: review that evidence before scheduling implementation. In particular, do not re-add primitive constructors, numeric formatting, MovieClip construction or Graphics line/curve/ellipse methods just because their historical declaration decisions lag the code. A partial class contributes only its remaining contracts to the adaptation queue.

## Coverage and validation

The [compatibility matrix](COMPATIBILITY.md) describes current behavior. The existing [capability registry](progress/DETAILS.md) and [complete ActionScript declaration audit](progress/ACTIONSCRIPT.md) track scope and evidence; no overall Flash-completion percentage is implied.

Representative editor and HTML5 workflows establish user-visible behavior; compiler tests and successful exports alone do not establish visual acceptance. [Verification scope](VERIFICATION.md) records observed boundaries, and the [backlog](BACKLOG.md) tracks concrete unresolved issues. These work areas can progress together; no completion date is promised.
