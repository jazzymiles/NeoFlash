# 0007 — Reviewed capability coverage and Git-backed daily history

Status: accepted, 2026-10-27.

The project needs a concise public statement of AS2, AS3 and product progress, plus detailed local evidence. Counting parser tokens, function names, test count or JavaScript counterparts would overstate Flash compatibility.

Use versioned JSON inventories of bounded capability families. Distinguish implemented, partial and planned. Only implemented contributes to the percentage; never aggregate categories into a claimed global completion score. Keep scopes, limitations and source/test evidence for each stable ID. Generate a compact README table and a detailed Markdown ledger from the same inputs.

Build the static GitHub Pages site from the committed revision. Derive daily records from the last first-parent commit per UTC day with a registry. Do not fabricate observations before measurement began. Show total scope alongside implemented and partial counts. Freeze historical registry values rather than retroactively guessing statuses from today's rules.

GitHub Actions checks schema/evidence paths, report consistency and history rules, then publishes on main. Status promotion remains a source/conformance review performed with implementation work. This is implementation coverage of a declared inventory, not code coverage and not full AS2/AS3 compatibility. Any future API-level reference catalogue must be a separately defined metric with its own denominator and evidence.
