# Typed collections and enumeration

Status: accepted for the bounded implementation, 2026-10-27.

## Types and identity

AS3 Vector types are parameterized by an actual element-type token, coercion operation and default value. A qualified-name string alone cannot distinguish classes in different publications. Generic type parsing belongs to the Rust frontend, including nested closing brackets without changing numeric shift expressions. Construction, explicit conversion and assignment to a nullable typed slot are different operations. Dense storage, bounds and fixed length belong to the captured runtime adapter.

Dictionary object keys retain their identity. The pinned AVM2 reference implementation routes primitive keys through property-name conversion; using JavaScript Map for every key would give a different result for values such as 1 and "1". Compiled indexed access therefore retains the original receiver and key until the runtime reference adapter selects the correct container behavior. Compound writes, postfix updates, deletion and membership must not stringify an object key or evaluate its receiver/key twice.

Weak dictionaries require actual weak ownership. A WeakMap can own values while a separate enumeration index holds WeakRef keys; it must never retain a strong fallback key/value pair. Garbage collection timing is nondeterministic and cannot be certified by an ordinary browser scenario. Unsupported platforms must diagnose the weak mode.

## Iteration and serialization

For-in and AS3 for-each use a bounded enumeration adapter, with explicit ordering/mutation boundaries. Project metadata distinguishes dynamic enumerable properties from fixed AS3 traits. Native display proxies are valid Dictionary keys; enumerating their hidden custom storage needs a separate host contract rather than an empty successful loop.

Vector JSON encoding is array encoding, with the existing callback traversal and ordinary serialization of each element. Dictionary's default toJSON result is a label, not an entry dump; authors can override it or explicitly project entries for a useful report. Neither family changes ambient JavaScript prototypes.

Ordinary AS3 property queries and enumerability changes use descriptor facts from the same project trait registry. Rust decides fixed/dynamic ownership and whether a descriptor may change. Public source reflection receives compiler-emitted metadata, never getter results: names, hierarchy, lookup and describeType XML are produced in Rust, while the host retains object/class identities. Unknown native traits and unsupported description signatures diagnose. Dense Array insertAt/removeAt similarly asks Rust for an index/growth plan before the host moves stored values.

AS3 Array Class facades and captured trait method values belong to the publication session. Class aliases agree between project methods, frame/object handlers and public class lookup. The method-value cache keys by array identity and trait name; `call`/`apply` cannot replace the captured array receiver. Lookup obtains the property once and preserves a custom function or getter result. Replacing an array method property does not alter a previously captured native closure. Existing adapters still perform the operations, so this adds no second sorting, callback or index algorithm. The public Array prototype functions `toString`/`toLocaleString` are not bound traits; AS2 extraction and broader prototype/borrowing semantics retain their separate limits.

Ordinary Object-root AS3 source instances use their own class prototype, and source subclass prototypes delegate to the source base prototype. Prototype constructor properties are nonenumerable and refer to their class. This follows [Adobe avmplus newclass at 858d034](https://github.com/adobe/avmplus/blob/858d034a3bd3a54d9b70909386435cf4aec81d21/core/MethodEnv.cpp). Fixed traits remain per-instance slots. Native-derived allocation and the AS2 shared-prototype model retain their separate paths. Explicit default object string methods share the short class-label operation in Rust, following [ScriptObject](https://github.com/adobe/avmplus/blob/858d034a3bd3a54d9b70909386435cf4aec81d21/core/ScriptObject.cpp) and [Object.as](https://github.com/adobe/avmplus/blob/858d034a3bd3a54d9b70909386435cf4aec81d21/core/Object.as); custom methods are selected before adapting the captured default identities. No ambient browser prototype is changed. Prototype replacement and full implicit coercion remain separate work.

## Combined delivery

One inventory publication parses source records, creates Vector.<Item> models, indexes their linked display cards in a Dictionary, updates stock through enumeration, deletes/reinserts a key while reusing its card, and serializes the typed model Vector including public getters. It also displays numeric Class conversion/bound formatting, property visibility, public model reflection without getter execution, and an Array-backed recent-batch history. Its Array pipeline retains a Class alias and captured mutation/sort/slice/map methods across handlers, uses call/apply with a different supplied receiver, and retains captured native/custom values after replacement. An AS2 plain-record for-in readout remains independent. Restart recreates the program and container identities. Existing compiler scenarios carry type/control-flow boundaries; the inventory remains in the existing project runner rather than a per-member suite.
